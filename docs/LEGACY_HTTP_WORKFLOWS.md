# 自动采集与证据中心：实际操作及验收边界

> 本手册保留高级 HTTP 路线的字段、数据源、游标和预算细节。早期“页面 step 驱动”的实施说明只描述当时版本；当前已确认批次由后台推进，生命周期见[现用操作手册](WORKFLOWS.md)。浏览器登录属于另一条向导路线，不共享本手册 HTTP 请求的会话。

本指南描述合并后的 main 能力；采集执行与证据界面来自 PR #6。首次使用先读 [零基础操作指南](FIRST_RUN.md)，当前能力与后续路线见 [采集能力说明](ACQUISITION_CAPABILITIES.md)。启动方式不变：Windows 双击 `start_windows.bat`；macOS/Linux 在源码目录运行 `python3 scripts/start_workbench.py`。从基础工作台进入新增入口，不需手写 JSON。

## 一、自动取数不是单个万能爬虫

本项目默认配置 BOSS直聘、猎聘、前程无忧、智联、拉勾、脉脉、牛客、实习僧。三条可执行路径分别解决不同访问条件：

| 路径 | 输入 | 自动执行的工作 | 明确边界 |
|---|---|---|---|
| 搜索路线 | 平台、岗位、Brave Key、预算、存储权限确认 | 交错检索、分页、线索入库、获准公开正文获取、报告 | 搜索摘要不是完整 JD；Key 不代表招聘平台授权 |
| URL 路线 | 一组 HTTPS 职位链接及正文访问许可 | 逐条安全获取、正文解析、去重、报告 | 无搜索 Key 也可用；链接必须属于所选平台，遇访问限制停止 |
| 授权数据源路线 | 实际获准的 JSON API 地址、接口契约链接、可选 Bearer Token | 按游标分页、验证职位、入库、报告 | 通用 publisher contract，不是伪装的 BOSS/猎聘私有接口适配器 |

可在界面新增平台标识、名称和域名，配置保存在本机 `platforms.override.json`，重启后保留；不允许覆盖或与已有平台域名重叠。新增域名仍须单独确认实际授权，并不新增自动登录能力。

全部平台指已配置的平台集合，不意味着全站、全中国或所有招聘软件的数据完整覆盖。平台没有开放给当前用户的接口、未获自动访问许可、存在登录验证、robots 拒绝或页面结构变化时，该来源必须保持受限或未验证状态，不能凭一个示例测试声称已打通。

### 先选路线，再填字段

首次核验建议一个平台、一个岗位，勿一开始全选。以下是建议的小预算，不是程序默认值：

| 路线 | 必填 | 凭据 | 首次建议 |
|---|---|---|---|
| search | 目标岗位/平台、实际使用范围、同意、搜索存储权限确认 | Brave Key；高级界面也可读启动前的 BRAVE_SEARCH_API_KEY | 搜索预算 3、每任务 1 页、正文尝试 3；未获正文许可则不勾选对应平台 |
| urls | 每行一个最终 HTTPS 职位链接、目标平台/岗位、实际使用范围、同意 | 服务 Key 留空，不读取网页登录态 | 1～3 个 URL，正文尝试 3，勾选实际获准的正文平台 |
| feed | 实际 endpoint、contract_ref、目标平台/岗位、使用范围、同意 | 页面填该 API 的 Bearer Token；不是招聘账号密码 | 数据源最大页数 1；其他路线输入留空、无关数值保持合法默认值 |

URL 路线不需要搜索存储权限勾选；feed 的平台选择用于校验返回职位的 URL 归属，正文许可复选框不改变 API 自身授权。默认值为搜索预算 24、每任务 1 页、正文尝试 20、数据源 5 页、新鲜度 24 小时。高级页搜索预算上限 300，基础页“发现摘要线索”上限 20，两者不是同一个入口。

不要把浏览器地址栏中的工作台令牌、平台登录密码或 Cookie 放进“本次服务 Key”。feed 的 RADAR_FEED_TOKEN 环境变量仅由采集 CLI 读取，当前浏览器高级页需填服务 Token；search 的 BRAVE_SEARCH_API_KEY 同时支持 UI 和 CLI。修改环境变量后需重新启动工作台。项目不自动加载 .env。

### 操作步骤

选择岗位和平台；选择采集路径并填写对应输入。仅勾选明确获准自动获取正文的平台，填写实际许可依据。使用搜索路线时还须确认自己的搜索 API 套餐允许保存结果；普通搜索 Key 配置成功不等于具备存储许可。

点击“创建并自动执行”。页面会依次发出有限步请求，显示搜索请求数、正文获取尝试数、数据源页数、各平台结果以及完整任务审计。任务完成后可以下载要求清单及 `collection_manifest.json`，并在证据区选择自动生成的真实输入报告。

搜索任务轮转执行；少量预算不意味着每个平台都已经执行过。每个任务最多 10 页，每页最多 20 条。实际少于 20 条并不是全市场没有更多职位的证明。默认 8 平台×3 岗位时，24 次预算只覆盖首轮任务，并不覆盖所有别名和关键词。

正文预算按尝试次数计数，每次可能还包含一次 robots 请求；不是整个程序全部 HTTP 请求总数。没有正文许可时仅保留摘要。相同 URL 的完整正文可在指定新鲜度窗口内复用，但“新鲜采集”不等于确认仍在招聘。

### 暂停、继续、重启

暂停在当前请求结束后生效；页面关闭后不再连续发出下一步请求，已经开始的当前步骤仍可能完成。重新打开页面，选择已有任务，补填本次需要的 Key，再点击“继续所选任务”。completed / needs_attention / empty 是终态，不会因为继续按钮而重新抓取失败项；要在修正条件后重新采集，创建新的有限预算任务。Key 不写入任务文件或浏览器持久存储；环境变量方式仍在进程环境中，按本机凭据管理要求保管。

程序在外部请求前保留请求预算及处理中状态。若进程异常结束，该步骤标为 `interrupted_uncertain`，不退还预算、不无限自动重试；授权数据源的中断页会停止后续读取，避免重复/遗漏被当作成功。需要重试时创建新的、明确预算的任务。工作区使用操作系统文件锁，防止 CLI 和浏览器进程同时写同一采集状态。

需要离开浏览器连续执行已有任务，可在安装包后使用：

```bash
vibe-radar-collect --workspace /你的工作区 --run-id 界面显示的任务ID
```

源码模式也可先把 `src` 加入 Python 模块路径再执行 `python -m vibe_job_radar.collection`。Brave Key 从 `BRAVE_SEARCH_API_KEY` 读取；授权数据源 Token 可从 `RADAR_FEED_TOKEN` 读取。不要写入版本库。CLI 不是后台常驻服务，进程退出即停止；需要定时执行时应由你本机的任务调度器管理进程。避免同时运行多个采集驱动。

### 失败如何解释

`permission_required` 表示没有勾选实际允许的正文访问范围；`robots_denied/robots_unavailable` 表示门控拒绝；`login_or_challenge` 表示需要在正常客户端处理登录或验证；`http_401/http_403/http_429` 会停止相应服务/主机，不通过换号重试规避限制；`parse_error` 不会把首页或挑战页面冒充 JD；`budget_skipped` 代表未执行，不能计作无结果。

`completed` 仅表示配置任务执行完成；`needs_attention` 表示存在受限、错误、预算跳过或中断；`empty` 表示本次未取得可用条目。报告使用当前工作区中符合所选平台、岗位和新鲜度的样本，不是声称只包含本次新抓到的职位。逐条本次来源结果请查采集清单。

### 授权 JSON 数据源契约

仅适用于你自己提供/签约/获准访问，且确实符合下列协议的数据服务。API 地址和契约链接都要填写实际 HTTPS 地址，不是普通招聘网页 URL。访问同一初始 API 主机，拒绝重定向、内网地址、非 HTTPS 或 URL 内凭据；Token 只通过请求头发送。允许的接口调用以实际授权为准。

GET `endpoint` 或 `endpoint?cursor=<opaque cursor>` 返回：

```json
{
  "jobs": [
    {
      "title": "实际职位名称",
      "text": "实际职位正文或摘要",
      "url": "https://www.zhipin.com/job_detail/实际ID.html",
      "evidence_level": "full_text",
      "company": "实际公司"
    }
  ],
  "next_cursor": null
}
```

以上只是字段契约，不是可以直接用于真实运行的招聘数据。每页最多 100 条、最多 20 页。`evidence_level` 未提供时保留为 `snippet`，不能自动升级正文。需要下一页时返回非空字符串游标，结束返回 null/空串；重复游标会停止。职位 URL 必须归属所选平台。合成记录和结构错误不进入真实库；一页先校验全部行，但磁盘故障下不承诺跨条目的事务回滚。

记录标记 `source_mode=authorized_feed`，保留 API 来源及用户声明的使用范围；这个字段不等于本项目替用户证明授权真实有效。没有有效官方契约的平台，不会被宣称为已认证连接器。

## 二、从原文到自己的证据，不再编辑 JSON

选择一个真实输入报告，点击加载原文要求。每页 50 条，可搜索和翻页；勾选的要求跨页保留。每一行可展开完整 JD 与引用位置，然后批准、拒绝或恢复待复核，填写复核人和理由。复核不会改变原始文本；批准摘要也不会将其变成完整正文。

填写姓名、项目、本人的实际负责范围、离线/影子/生产阶段。上传附件并自动计算 SHA-256，或者填写不含登录凭据的外部 HTTPS 引用；外部引用不自动访问，也不宣称已经验真。单附件 1 MB、总计 50 MB/100 个，超过时请使用新的独立工作区或提供适当外部引用。

选择该证据实际支持的能力，并从要求列表勾选精确映射。界面不会仅凭属于同一能力类别就判断完全满足。离线证据不能用来满足明确的生产经验要求；学历、年限、禁止项等仍须单独核对。

添加指标时选择指标目录项，填当前值、当前样本量、窗口和比较口径。提供基线时还需填写基线样本量和基线窗口。先预览，再添加到证据。支持 13 类既有观测契约；百分率的变化按百分点表达，基线为零时不计算相对下降，负值/NaN/错误样本量拒绝。示例 `10→6` 可计算为下降40%，但只是测试算例，不能作为个人真实经历。

保存草稿不会成为“已确认个人成果”。保存为已确认时须明确确认本人经历、指标和逐条映射，并填写确认人。哈希校验只证明文件一致，不证明经历真实性，也不证明收益由 AI 单独导致。

### 编辑、撤回、版本与冲突

已保存证据可以编辑，编辑后再次确认真实性；也可以降为草稿或撤回。当前资料的修改有 SQLite 版本历史。旧浏览器标签页提交过时版本时返回冲突，不覆盖最新资料；刷新、核对后重试。

撤回从当前资料删除，不销毁旧版本、旧报告或原始附件。这是审计保留，不是隐私彻底删除。需要清理历史时先停止服务、备份后处理整个本机工作区。

### 生成与下载

点击生成个人报告，使用所选来源报告的冻结招聘快照、原分析时间、配置和当前个人证据。它不会重新抓取职位，不会加入复核后新进入数据库的职位，也不修改旧报告。

新增报告包括本人负责范围、观测指标、精确映射矩阵、覆盖率和缺口，另保存 `candidate.effective.json`、`reviews.effective.json`、`evidence_revision.json` 及文件哈希。样本证据映射覆盖率不是胜任度或录用概率。

下载可迁移证据 ZIP，包含当前候选人数据、复核结果和被引用的附件字节；本地相对路径转换为包内引用。只有一个来源报告时根目录仍提供 candidate.json / reviews.json；多个来源报告时分别使用 reports/<来源报告ID>/candidate.json 和 reviews.json，根目录 reviews.by_report.json 保存按报告分组的复核，不合并可能冲突的决定。请同时匹配原来源报告的招聘数据与配置。该 ZIP 不含全部工作区/任务/原始 JD，当前 UI 也没有 ZIP 一键导入恢复按钮。

同一 requirement_id 可以出现在多份分析报告中；复核按“来源报告ID + 要求ID”隔离，A 报告批准不影响 B 报告拒绝。旧版本保存的带 source_run_id 记录仍可读取，编辑时迁移当前条目，不改写历史版本；旧版本已经覆盖丢失的当前决定不做自动推测恢复，应重新核对原文。

个人证据也关联来源报告。生成后继续修改原资料时，保持选择原来的来源报告，不要误选刚生成的个人报告；切换来源需要明确重新映射。每项证据支持一份附件或一个外部引用，可将多项资料整理为一个不超限制的文件或分成多条证据。

上传附件→选择引用；“校验并预览”→“添加到当前证据”→“保存个人证据”是三个不同动作。填写完成但未保存的数据刷新后可能丢失。先检查“已保存的个人证据”中出现项目，再点“生成个人报告”。

## 三、验收分层与外部资料

自动测试使用人工样本和模拟远端响应，但实际执行 HTTP 服务、状态机、SQLite、指标函数、报告生成和真实浏览器操作。它不证明真实招聘平台的采集许可或线上成功率。BOSS、猎聘等实际账号/Token 没有提供，本轮不会虚报逐平台已认证。真实授权与生产覆盖仍由总路线 Issue #3 跟踪。

官方资料核对日期：2026-09-14。

- Brave 官方分页契约：https://api-dashboard.search.brave.com/app/documentation/web-search 。`count<=20`、分页 `offset=0..9`，检查 `more_results_available`。
- Brave 官方存储说明：https://brave.com/search/api/ 。保存结果需相应存储权限；Key 存在不等于具备保存权限。
- 猎聘官方技术介绍：https://ir.liepin.com/system/ 。官方介绍了 MCP 能力，但产品介绍不等于本项目已取得接口契约和授权。本轮不猜测 endpoint/tools 名称，也不把通用 JSON 连接器标为猎聘 MCP 实现。

这些服务与权限可能变化；以实际服务条款和用户授权为准。
