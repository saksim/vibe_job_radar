# 向导操作与状态轮询交接

Refs #232 / #69 / #210。向导上一项操作仍在提交或读取本机结果时，按钮保持不可用并显示正在处理；无论先前已发出的状态轮询何时返回，都不能把仍受请求保护的按钮提前启用。本机请求结束后立即按当前后台状态恢复控件。后台运行且没有本机请求待结束时，暂停和停止仍可用；不自动排队、重放点击或发送登录。

原实现仅按后台 busy 渲染按钮，而 act 另有请求保护。实际 Edge 人工测试证明：在途轮询先返回最新空闲状态、收集命令回应仍在途时，登录按钮启用且 requesting=true，点击一次却产生0次登录请求。测试保留真实服务、工作线程、第一条已保存JD和部分报告，仅控制本机HTTP回应的顺序；无真实账户或站点请求。

浏览器回归 `run_login_detail_return_browser.py --pending-action` 固定上述交错：等待时控件不可点，释放回应后首次登录准确执行一次，登录返回原选定详情并形成原报告，先前正文/报告和请求计数保持。普通人工选择和创建时自动选择的原流程继续运行。脚本只增加固定阶段、人工请求方法/路径和有限状态代码，失败不输出任意异常文本、令牌、密码或Cookie；原等待时间和内容断言保持。

PR69/bdbd3585的首次CI在受控详情登录回接处失败；旧日志缺少阶段记录，无法确认是否由该竞态触发。上述确定性反例与修复单独验收，不能据此关闭原原因未知的失败，也不混同#126的Windows等待问题。真实登录滑块/短信和目标平台验收仍按原记录跟进；本项不修改网络准入、配额或用户工作台。
