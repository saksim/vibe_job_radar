# 已确认公开查询的独立本机进程

Refs #115 / #131 / #9 R3 / #30 H4。此入口复用原公开查询计划、任务、配额、缓存、来源审计和报告，在没有网页服务器时也可执行已经明确同意的每日计划和[一次性查询待办](PUBLIC_QUERY_QUEUE.md)。默认计划关闭、待办为空，不启动浏览器，不监听HTTP，不自动登记系统服务或启动项。

## 使用

先在同一工作区首页选择来源/查询，明确同意保存每日计划，或另行确认加入一次性待办。两种许可独立，独立进程启动不等于联网同意；只认原记录里的来源契约、网络路线和修订。然后可关闭工作台服务，从源码目录运行：

```powershell
python scripts/run_public_worker.py --workspace "D:\Radar\workspace"
```

已安装命令行包时可用 `vibe-radar public-worker --workspace "D:\Radar\workspace"`。Windows便携候选可用：

```powershell
.\VibeJobRadar.exe --public-worker --workspace "D:\Radar\workspace"
```

使用原来的工作区目录；新目录没有旧计划。此进程需保持运行，Ctrl+C请求停止。关闭进程后计划仍保存；后续启动最多执行一次已到期查询，不补跑每个错过的日期。需要撤销未来执行时，在同工作区首页点“停止计划”，再关闭独立进程。已有报告保留。

可以重新打开网页工作台查看历史和报告、停用或重新确认计划。两个worker或worker与工作台共用原OS锁：一方执行，其他等待。网页仍显示真实计划状态；“另一进程持有锁”不会把“已停用/失败/暂停”隐藏。当前只支持同设备同工作区，不是跨设备账户配额服务。

#124补充[原任务完成回执](PUBLIC_TASK_OUTCOMES.md)：计划任务已完成后，即使另一个手动查询先更新当前任务记录，也能找回原报告并继续计划。同ID人工续接按不同尝试处理；缺少可信结果仍暂停，不推断成功或重放请求。

## 运行和故障

进程输出逐行JSON，仅在状态改变时输出固定字段：启动、计划/待办状态、是否本进程持有各自调度、计划历史条数、待办数量和停止。`retained_runs`最多20，是当前保留的计划历史条数，不是终身执行次数；`queued_queries`包含待办当前尝试与未开始条目，最多5。查询词、正文、Cookie、密码、URL令牌和工作区路径不写入这些状态行。

按[Python信号说明](https://docs.python.org/3/library/signal.html#signals-and-threads)，信号回调只设置停止标记，主循环完成涉及锁的清理，避免Ctrl+C/终止信号重入事件锁。独立子进程测试真实触发SIGINT/SIGTERM及Windows SIGBREAK并核对原处理器恢复；不向个人进程发送信号。

计划保持原24小时间隔、共享频次库和一次首屏查询，不自动翻页。成功/过期/条件改变/时间回拨/配额拒绝仍按原计划处理。退出码0表示进程正常停止，不证明已经有成功查询；需查看计划历史。坏记录、调度线程意外退出或关闭未完成返回2，不删除记录来恢复。

正常停止先停止后续调度，再取消后续任务步骤并等待当前只读请求/本地保存。强制结束进程时OS释放自有锁，已开始但结果不确定的任务在下次启动暂停，不重复请求；仍需用户核对后重新确认。原配额和缓存不重置。若计划暂停，worker可保持等待，不会自行重新同意来源或改网络路线。

## 验证与边界

独立进程测试使用明确标注的人工目录，覆盖默认不联网、没有监听端口、同工作区竞争、处理中止后不自动重放、原配额保持和原完整JD/报告。实际浏览器验证“网页确认计划→关闭整个网页服务→独立进程执行→新工作台读原报告并停用”，390px、页面错误和意外外部请求单独检查。

Windows CI以实际冻结exe、无Python PATH启动空计划worker，确认独立入口和默认关闭；只终止该次自有空闲进程，不把它算作正常Ctrl+C或真实长跑证明。当前head结果以Issue/PR记录为准。

首轮#116的独立exe worker/PAC检查通过，但其后的包内Chromium空白页超时，单独由#117跟踪。原离线探针与便携工件现在记录`set_content`、`read_title`、`verify_title`/`verified`，每步耗时以及主动清理前的加载/崩溃/关闭事件计数。只记录固定事实，不记录页面正文、标题内容、URL或事件参数。按[Playwright接口](https://playwright.dev/python/docs/api/class-page#page-set-content)保留原`set_content`完成条件和6000ms默认超时，没有重试或替换成更宽松的检查。新增证据不等于最初超时根因已解决。

本分支#131新增有限持久待办：每条只尝试一次、24小时许可、至少30秒间隔、失败/过期缓存/未知结果暂停；原共享额度与任务锁不变。Windows CI新增实际冻结worker读取人工缓存、零请求生成原完整JD报告的验收，同head结果见PR。这仍不是Windows Service或无人登录全天保证。#120的[Windows登录启动](WINDOWS_LOGIN_STARTUP.md)可明确选择此进程；默认关闭，已有登记不自动改变，登记不创建或重新同意计划/待办。生产服务、签名发行、跨设备权限/配额、实际24小时/重登录长跑和中国三站正常登录→完整JD仍独立验收。

回退前先停用计划并暂停待办，等待当前步骤结束、关闭全部同工作区worker和工作台并备份。#131新增独立版本的`public_queue/queue.sqlite`，旧版本忽略该文件；原计划/任务/频次/报告继续使用既有格式。旧源码不得与新worker同时写入工作区。恢复新版时，未撤销的旧许可仍可能使已到期计划执行一次，或使未过期待办继续运行。
