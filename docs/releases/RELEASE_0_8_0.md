# 0.8.0：HTTP Digest 代理认证

## 解决了什么

[#385](https://github.com/saksim/vibe_job_radar/issues/385) 补齐原来只能选择 HTTP Basic 或 SOCKS5 用户名密码、无法连接 Digest 本机代理的缺口。三个工作台新增明确的 Digest 选项；Windows 加密保存、修改、清除及独立进程恢复共用原工作区流程。CLI/环境变量入口同步支持。

## 提高了什么

认证方式绑定运行中与重启后的网络身份。支持标准 Digest 算法及会话变体、随机客户端 nonce、可选服务器证明；407 挑战和一次响应共用期限。保留数字公网 CONNECT、原站 TLS、一次业务请求和拒绝后的停止规则。既有 Basic/SOCKS5、匿名/PAC/宿主机、升级断点续传及自动交接、Python 分发、采集和原报告功能保留。

## 验证结果

本机 51 项定向检查通过，包括标准向量、真实本机代理/TLS、并发拒绝、Windows DPAPI 独立进程与既有后台队列。首轮一处测试误将单字母 nonce 与类型名称匹配，修正断言后通过；原失败日志保留。真实浏览器、冻结程序、完整准确主干和正式 Tag 结果以对应 PR/Release 的实际证据为准，不预填通过。

## 剩余问题

本次只覆盖[明确的 Digest 协议范围](../HTTP_DIGEST_PROXY.md)。代理端 DNS、NTLM/Negotiate、其他系统加密保存、企业/VPN 实际环境和程序签名继续单列；人工 JD/本人材料、生产主机域名尚需提供。受控网络不代替真实站点或正常账号认证。
