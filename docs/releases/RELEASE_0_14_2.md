# 0.14.2 发行说明

## 解决了什么

- #420：SOCKS/宿主代理暂时断连或超时被当作硬失败，错误阻断已有公共岗位缓存；远端公共查询遗漏加密DNS临时错误，团队传输又丢失HTTP 503等临时故障类别。
- #421：配置PAC后，团队公开搜索被传入仅本机来源支持的参数，在请求前失败，无法生成原报告。

- #423：首次读取没有额外间隔或请求窗口的 robots 规则时，仍创建零约束记录、等待写锁并落盘。

## 提高了什么

本机和远端公共查询共用明确的临时错误白名单。在已有缓存仍处于原有效期、没有此前未解决的硬失败时，可返回明确标记为stale的原岗位，并保留原观察时间和此次失败类别。未知错误、认证、TLS、协议及数据错误仍拒绝；一次成功且有效的刷新才清除旧硬失败。旧版本已经写入的错误记录不会被静默删除。

团队公共搜索保留安全的临时故障分类，团队配额、续租和权限接口仍失败即停止。团队任务由原认证连接选择网络策略；本机任务继续绑定自己确认的策略和取消信号。取消后即使在途响应返回，也不再导入岗位或生成新报告。

无约束规则在读取确认没有原规则后不再写入零约束行；robots访问判断、坏/丢失数据库拒绝仍保留。更严规则和窗口继续原子合并，每次请求仍读取当前约束。数据库模式、同步强度和fsync不变。

没有自动重试或自动改用直连，保留采集、完整JD、原报告、调度、升级及三平台分发功能。

## 验证结果

准确0.14.1基线已复现两项缺陷并保留失败输出。定向回归检查旧时间戳、无缓存/过期缓存、认证/TLS与未知失败、原硬失败保留、团队真实本机HTTP到原报告及取消边界。具体数量、准确提交和完整CI结果以配对PR和正式Release为准；不重复本机全量测试。

首轮候选的Windows Edge headless在原45秒等待处失败，原始日志、阶段计时和线程栈保留于#269；新现场有数据库长等待，但底层慢因尚未确定。随后对#423先用3项回归复现2次无效提交与写锁阻塞，再做95项相关回归一次通过（7.381秒）。此前缓存/PAC修复的164项回归一次通过（35.001秒）。新增共10项，完整矩阵预期3354项/组。原45秒/整套期限及全部业务断言保持。
