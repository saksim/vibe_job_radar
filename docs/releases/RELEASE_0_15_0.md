# 0.15.0：服务备份恢复与非登录工程收口

关联 #23 / #30 / #47 / #51 / #52 / #55 / #56 / #57 / #426 / #427。

## 解决了什么

- #427：团队服务增加完整备份manifest、`verify-backup`和`restore`，无需手工拼接数据库。校验所有文件的字节摘要、数据库完整性与支持的结构；保留成员/设备、共享用量/冷却、目录和刷新账本/缓存。
- #426：现有BOSS/51job DOM路径拒绝正文内明确的“展开全部”等未完成提示，以及已选岗位与最终页面/canonical身份不一致。保留完整正文、原报告、猎聘和其他采集路径；不扩大站点访问权限。
- 明确原24项的本期范围，5个已交付工程项按证据收口、2个重复总控统一到 #57。待环境/材料及真实未完成的站点功能继续明确跟踪，实际状态以 #57 最终记录为准。

## 提高了什么

恢复前可离线检查备份是否缺失、混入文件或损坏。恢复只接受不存在的新目录，要求确认源服务/刷新/管理员写入在备份前已停止且之后没有继续；不覆盖现有数据，不清空账本。中断目标保留标记并拒绝启动/管理/刷新，原备份保持不变。旧格式备份不删除或补造清单，继续按原人工审查方式处理。

工程交付、真实环境验收、尚缺功能和历史复发分别统计；不再让未知代理产品和未准备的生产主机无限扩大 #23/#30 的本期研发范围。

## 验证结果

0.14.2基线上的三个DOM负对照共有6个分站失败。修改后首轮142项相关回归中140项通过，两项因新增manifest改变精确文件清单而失败；只更新相应四处文件列表预期，保留失败回收/替换保护断言。补充中断与隐藏控件场景后，受影响的20项一次通过（2.845秒）。没有重复本机全套测试。后续审查用单项负对照复现系统祖先路径别名误拒绝，修复只规范化备份之外的祖先路径，备份本身/内容链接与重解析点仍拒绝；新增定向验证结果记录在PR中。

第二候选的完整CI实际发现新增测试两处未声明读取编码，已修复，没有重跑旧提交寻找绿灯。审查另外确认并修复全表/约束校验遗漏、最终目录落盘失败后的恢复标记丢失、完整展开按钮后缀漏判。相关85项实际用例通过；一次命令还误列不存在的测试模块，该导入错误单独记录，不算通过。最终恢复落盘和旧版数据库迁移再做定向验证，具体结果见PR。macOS随后发现两处故障注入使用规范化前临时路径而未命中，夹具统一resolve后保留原故障断言；未改产品实现或跳过平台。

79c5f06的11项必需CI虽全部通过，合并前追加审查又确认CSS隐藏按钮误拒绝与新恢复目录的父目录同步缺失，负对照复现后一起修复。前者使用已有浏览器可见文本排除隐藏模板，后者在标记仍存在时同步父目录，失败保持阻断；最终定向结果见PR。

feature与准确main保留仓库必需资格；相同代码树的中间晋升按已有流程去重重型任务，取消单列，不能记为通过。正式发行复用准确main验证过的资产；最终CI、PR、Tag与公开附件核对结果由 #57 和发行页补充，不提前宣称通过或已发布。

## 剩余问题

BOSS/51job专用动态搜索、分页和真实完整链路仍未全部实现或认证。生产主机/域名、真实网络、多设备、净机、真人标注和本人项目材料仍待条件。旧历史失败原因不由新CI回填。Windows仍unsigned，macOS签名/公证仍缺凭据。

恢复入口适用于停止写入后取得且之后没有继续使用源服务的完整备份。较旧灾备若遗漏了后续权限变更/请求用量，不能靠确认参数恢复这些未知活动；须先由运营者核对当前权限/平台额度及停用旧节点，不能直接按本命令恢复后继续采集。详见 [团队恢复](../TEAM_SERVICE.md#完整备份校验与恢复0150)。
