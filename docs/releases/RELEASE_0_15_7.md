# 0.15.7：原生资源清理与公开查询批次持久化

## 解决了什么

- #472：原生代理监听端口建立后，线程创建/启动失败导致构造退出而端口遗留。现在失败路径释放已持有listener，不等待未启动的服务循环，保留原始异常。
- #473：原生浏览器某项清理抛错会跳过剩余资源，构造时还可能覆盖原启动错误。现在逐项清理、保留首个故障；关闭回调失败也清空监听器。仍只操作自有PID和私有目录，进程存活或状态未知时保留profile。
- #474：公开来源批次逐条提交，后续记录失败留下半批观察。现在记录、观察和审计共同提交或回滚，避免重试累积半次操作。

- #476：GitHub Ubuntu依赖下载连续两次触及原8分钟限制，尚未进入功能测试。现在CI仅移除runner已配置的HTTP Azure首选镜像，验证并保留两个官方HTTPS后备源；不改变用户网络、软件包、签名校验、时限或验收要求。

## 提高了什么

启动失败能释放本机监听资源，清理失败保留可操作的原始错误；公开查询两条记录的持久事务由2次降为1次。保留全部fsync、原有期限与业务断言、完整JD/原报告、已成功批次和观察历史、取消/调度、网络认证、数据与升级/回滚功能。事务次数改善不代表已测得总体耗时改善。
