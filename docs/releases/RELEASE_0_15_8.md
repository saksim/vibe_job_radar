# 0.15.8：代理时限与资源、计划恢复修复

本版基于正式 0.15.7 / `877d5047ecdda85769d9b9e703f2cf6312b41683`，沿用 dev → release → main 晋升。正式交付以三个 Tag 和公开附件为准。

## 解决了什么

- #479：HTTP 代理持续分片发送 CONNECT 状态行或响应头时，原逐次读取时限可能续期。现在发送和每次底层读取都扣除同一个原总预算；保留标准库 CONNECT、认证、验证过的目标 IP 和成功后的原 socket/TLS 路径。
- #480：原生 CDP 管道线程分配或启动失败后，构造函数现在向自有 bridge 关闭 stdin，并有限等待已经成功启动的线程；保持原始启动异常，避免丢失尚未交给连接管理器的资源。
- #481：原生隧道关闭某一步抛错时，仍分别尝试停止循环、释放自有监听器和有限等待线程，最后报告首个异常。
- #482：公开计划重启恢复时保留匹配的活任务，使暂停或停止仍能关联原任务；恢复前识别时钟回拨，保持原暂停要求并保留已完成报告。

## 提高了什么

代理握手更准确地遵守原时限，失败路径更完整地释放自有资源，公开计划恢复后仍能追踪原任务。没有延长业务等待、删除 fsync、切换代理路线或取消原功能；清理仍是有限尽力操作，不承诺任意操作系统失败都能强制停止线程。本轮未测得可泛化的速度提升。

## 验证结果

- 准确 0.15.7 的代理定向对照：4 项中 3 失败、1 正常控制通过；修后 4 项通过（0.166 秒），一次相关 53 项通过（6.706 秒）。临时本机滴流实验保留在证据中，永久仅新增 3 项确定性测试。
- 原生清理两种机制共 5 项负对照全部失败；修后计入一次 93 项相关检查，全部通过（2.387 秒），不重复计算共用检查。
- 计划恢复新增 3 项负对照全部失败；修后 3 项通过（0.599 秒），一次相关 30 项通过（9.322 秒）。初次临时导入额外执行的 27 项旧控制均通过，已改模块导入避免永久重复收集。
- 仅测试发现确认总数由 3532 增至 3543，新增 11 项；发现操作不等同完整测试执行。没有重复本地全矩阵或运行公开程序包。

候选与准确main仍须各自必要CI和实际程序产物证明；按dev→release→main晋升后发布三个正式Tag并核验公开摘要和旧版升级解析器。实际完成状态记录在总控#57。
