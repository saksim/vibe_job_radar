## 用户流程

沿用首页“获取并在本机筛选”。第一次成功取得完整目录只建立基线，不将全部岗位称为新增。下一次用户确认的查询满足原缓存/配额条件并成功刷新完整目录后，显示新增、修改、本次未出现和未变数量，以及两个观测时间。无需新配置、命令、服务器或订阅。

比较范围是所选公司 **Greenhouse完整本机公开目录**，不是当前关键词、地区或本页结果，更不是整个招聘市场。原Anthropic目录保持，本分支#95新增Cloudflare时为其单独建立缓存和变化基线，两家公司从不互相比较。首次使用、七天内无可用基线或适配器版本变化时明确重新建立基线，不猜测变化。

“本次未出现”只陈述该 ID 在第二份完整回答中缺席，不代表岗位关闭、招聘冻结或已被录用。不会删除历史岗位、个人证据或报告。空查询结果也展示目录级摘要，但仍不虚构岗位或创建空岗位报告。

## 比较与数据

身份由已有来源 key 和来源内 ID 确定。比较标题、公司、地区、远程字段、正文、原始/最终 URL 和正文完整性；观测时间本身不算岗位内容变化。适配器版本不一致重新建立基线，避免解析器变化被当作市场变化。

先完成原来源、总数、ID、正文、时间及缓存校验，再比较；部分/异常回答、403、证书失败或暂时失败不会推进基线。暂时故障可以按既有规则显示带时间和失败原因的旧缓存，其变化摘要也仍对应旧的观测时间。旧硬失败保护不被变化功能清除。

新目录与变化记录在同一份 v2 缓存中原子写入，沿用原工作区写锁，不新增第二份需要单独提交的水位文件。没有任何附加外部请求、后台定时任务或对外上传。分页、换关键词、刷新网页和读取状态不会被当作新的来源观测。

缓存文件分别为`local_public/anthropic-board-v2.json`与`local_public/cloudflare-board-v2.json`。旧 `anthropic-board-v1.json` 保留不修改，v2 尚不存在时可懒读取旧缓存，下一次真实刷新后写 v2。坏 v2 不偷偷退回 v1；回滚旧版可继续其旧格式，旧版不提供新来源能力。仍共享原限频数据库、保留各来源错误记录，不能通过切换版本清除配额。

缓存、游标使用的原 revision 继续绑定完整快照；变化对比单独忽略观测时间，避免每次刷新都误报正文变化。只保留相邻近期完整观测的变化，不是长期事件日志；两次观察之间发生又撤回的变化无法推断。

## 网页与报告

任务状态只带有界摘要，不塞入完整目录 ID 列表。网页以 textContent 展示，不把来源数据当 HTML。完整差异中仅含 ID、变化字段名、计数、来源和观测/版本信息，不重复保存正文或用户查询词。

有匹配岗位且生成报告时增加 `catalog_changes.json`，其摘要同时进入 `public_source.json`，文件 SHA256 进入原 `run_manifest.json`；原本机鉴权下载接口可直接下载。每页报告保存同一完整目录的变化，不把分页未见岗位误报缺失。没有匹配岗位时仍保留本地缓存与状态摘要，不把目录级变化伪装成查询命中。

这些哈希用于一致性检查，不证明上游信息真实性，也不是抗本地恶意篡改的签名。旧缓存首次读取没有变化记录时不补造历史事件。
