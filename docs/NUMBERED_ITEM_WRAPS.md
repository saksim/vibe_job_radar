# 编号中文职责的续行与原文证据

Issue #164，基于PR163的42项统一候选。采集保存了完整正文，但原提取器将每个换行都当成句子边界：同一编号职责中，前半句提到AI编程，后半句的能力可能失去语境。`rules-0.2.1`修复这类有明确结构的续行，不修改采集器或原始记录。

人工示例（不是市场岗位）：

```text
1、推动AI编程在研发小组中
的应用，提升交付效率。
2、禁止使用 Codex。
```

新分析保留第一条的完整引用，包括原换行；第二条仍是独立禁止项，不能成为正向能力。能力匹配使用单独文本，将续行两侧的中文字接合，保留英文词间空格，解决“编／程”“审／查”等断字。存储的正文、引用、start/end始终来自同一原始JobRecord；模型既有的导入CRLF→LF规范化不变，直接调用切句器处理CRLF也保持对应输入位置。

识别范围限定为阿拉伯数字编号的中文条目（如`1、`、`2.`、`（3）`），最多8行、2000字符。续行必须以中文开头。空行、新编号或项目符号、句末标点、标题、独立义务/否定词开头和英文新行均保留边界；非编号段落、纯英文段落及超限条目仍逐行处理。“不／要求”“无／需”等已知否定词内的换行保持否定语义，不能把后半词当成独立正向要求。带【】的标题仅按已知标题词表识别；补入实测出现的“任职资格”“工作职能”，避免没有标点的标题被串接。公司和福利章节继续排除。

这是有界的规则判断，不覆盖所有排版。无法明确判断的断行仍可能需要原文复核。含糊工具提及、相关技能和摘要不会因此自动得到人工批准。

重新分析产生独立报告，旧报告不重写。扩展引用可能产生新的requirement_id，旧原文复核/个人证据映射不能自动套用到新ID；按新引用重新核对。提取版本写入manifest，采集日期、记录身份和原来源证明保持。

验证使用独立撰写材料：连续引用与未换行含义对照、LF/CRLF位置、断词、不同编号、正负条款、标题/福利/公司、英文与长度边界、硬约束及旧报告不变。原网页表单→分析→CSV→历史流程和实际Windows程序也验证新规则及重启恢复；具体通过状态以本提交的CI和产物证据为准，不借用基线绿灯。已有74条真实正文仅在本机离线生成新报告，原采集失败和实际日期保持，不为分析修复重访猎聘。
