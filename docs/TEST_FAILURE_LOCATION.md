# 自动续采等回归失败的代码位置

Refs #192 / #126 / #174 / #179。PR191的Windows源码资格首轮完成2104项，自动续采用例失败时后台线程位于报告写入。原工件只留下控制台末尾3000字符；长任务状态断言覆盖了失败断言的位置。原失败记录、工件和唯一原配置复核分别保留，本项不补造旧堆栈或宣称耗时原因已解决。

`scripts/run_tests.py --progress --report ...` 现在在现有进度文件增加`FAILURE_LOCATION`。它使用失败的原异常三元组，记录内置异常类型及项目`src`、`scripts`、`tests`下的相对Python文件和行号。最多保留24个最近源码帧、遍历256帧，其他来源和省略帧计数、遍历截断状态明确标注。它不输出异常消息、代码行、局部变量、subtest参数、外部完整路径或自定义异常名。

这份位置记录与失败瞬间的后台线程栈回答不同问题：前者定位断言或异常代码，后者显示当时其他线程在做什么，均不能独立解释此前全部耗时。Python3.10仍在原清理前观察延后结果，Python3.11/3.12沿原结果回调；每个测试只记录首次意外失败，预期失败不额外记录。位置记录失败时仍尝试原线程栈，原失败数量、清理和退出码不变。

原Windows资格流程已经保存进度文件，不复制完整断言正文或新增日志上传范围。600秒资格时限、各测试等待、fsync、产品运行时、站点请求与真实报告不变。六项人工回归的旧运行器基线均失败，修复后另验长断言、subtest、延后结果、外部路径/自定义类型、诊断错误和深堆栈边界；当前提交完整及跨平台资格见对应Issue/PR。
