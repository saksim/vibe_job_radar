# 0.5.0 非登录网络兼容与自动升级

## 解决了什么

- #23/N6：独立许可的完整网址PAC增加dnsResolve、isResolvable、IPv4 isInNet、myIpAddress，解决可信脚本缺少DNS和本机地址助手的问题；原无DNS模式保留。
- #30/H6：Windows便携版增加确认后自动升级，覆盖验证下载、重新解压、离线探测、退出、工作区备份、新版就绪确认和入口提交；原手动准备入口保留。
- 升级后原0.5.0及之后的启动入口会跟随已提交版本，既有Windows登录启动命令和回执保留；不会改写陌生登记或覆盖旧程序。

## 提高了什么

- PAC按次缓存并限制16名称，DNS故障、超限和死循环受隔离期限约束，私网DNS回答不会放开HTTPS目标限制。
- 自动升级保留SQLite已提交WAL数据、个人文件和历史报告，失败不自动回写用户数据；首页可读取上次升级记录与备份位置。
- 正式发行资格新增真实编译程序交接和DNS助手证据要求；保留已有测试矩阵、网络模式、公开采集、完整JD、团队与原报告功能。

## 验证结果

- 本地关联63项全部通过；此前关联52项中51通过、1项因Windows符号链接权限跳过。仅按新增范围验证，没有重复本机全套。
- 实际Edge升级页面6项通过；三个页面的PAC模式、独立授权、真实隔离localhost解析及390px布局通过，0页面错误、0浏览器外部请求。
- 首轮DNS测试发现无效IPv4被当成名称；首轮备份测试发现持有的Windows锁标记不能复制，另有夹具字段错误。均已修复并复验，原失败日志保留。
- 编译程序交接、精确提交CI与正式发行结果以本轮PR和Release记录为准；源码/人工包测试不能冒称真实新旧版本现场升级。

## 剩余问题

- #23：其他代理认证、socks5h/代理端DNS、企业分区DNS、VPN/TUN产品与物理环境矩阵仍未全部覆盖。
- #30：Windows包未签名；其他系统包、跨历史版本与干净Windows现场验收继续开放。0.4.1及以前首次使用自动升级器需手动启动0.5.0。
- #315/#316/#317/#319与总控#57：真实岗位、人工JD金标准、本人项目材料、干净设备及新手验收待条件；生产Linux主机与域名尚未准备，不宣称上线。登录专项继续独立跟踪。
