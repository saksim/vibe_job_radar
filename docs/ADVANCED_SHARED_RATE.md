# 高级站点HTTP的共享限额

Refs #168 / #52 / #166。公开分类、URL正文和搜索API之后的站点正文，现在与同一工作区的浏览器向导共用原 `guided/rates.sqlite`，使用相同的平台标识和原限额。Brave API及授权JSON接口仍按自己的任务预算执行，本改动不把第三方API请求当成招聘站点访问。

一次分类页或详情获取预留一次页面额度；robots、详情和每次受限跳转分别预留HTTP请求。有效robots给出的更严格间隔、请求窗口存入原账本，后续较宽松的响应不会降低已保存约束。HTTP自身的间隔、HTTPS、DNS、公网地址和逐跳robots检查继续生效。

原向导限额保持：页面最小间隔15秒、每小时60次、每天200次；请求最小间隔0.5秒、每小时600次、每天3000次。发布方限制可以更严格。这里计量的是连接前预留的尝试，不保证请求送达；失败和中断不退款。缓存命中、本机预览和创建暂停任务不预留网站访问；各批正文尝试数字也不等于全部HTTP请求数。

最多在当前步骤内等待原来的30秒短间隔。较长发布方等待、小时/日限额、已有冷却或账本/时钟异常会产生明确结果，保留已成功正文、失败和未访问项。401/403/429的冷却写入同一账本，换入口、新任务或重启仍生效。本批结束后不自动重放失败；先核对原因，等共享额度允许，再为已确认的剩余范围新建小批任务。所示等待秒数是当次受阻记录，不是实时倒计时。

2026-09-24受控基线复现了旧缺口：原默认高级工厂在向导已有3600秒冷却时仍完成2次模拟请求，账本请求预留为0。此前真实采集验证脚本额外绑定了原真实账本；它证明了当次计量，不能替代产品默认工厂的接线。本次回归直接使用原Collector默认工厂，仅替换单跳网络响应；另检验原UI和实际冻结程序，结果以当前PR提交为准。

不重建或清空已有账本，不迁移原正文/报告，不扩展跨设备账户配额，也不因此认证登录、搜索、三站或三日期。回退到未接线旧版本会失去高级HTTP这一约束，不能在旧版本中继续本轮自动采集并声称仍有同样的持久限额。
