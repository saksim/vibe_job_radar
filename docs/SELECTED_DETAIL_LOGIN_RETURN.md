# 登录后直接接回所选完整 JD

关联 #49 / #50 / #46。原补丁开发基线为已合并 PR61 的 main `ec4587992113848be879da2fbc4cebdac62d10e2`。

## 解决的具体问题

原自动登录返回观察器只识别原搜索列表。采集中某条详情要求登录，平台正常登录后直接返回该详情时，即使完整正文已经显示，也不能自动继续。原 `resume` 会再次访问该岗位，而不是使用刚刚返回的完整页面。

本增量仍使用原 GuidedService、Store、JobRecord、批次报告和 Cookie 检查点。没有平行导入器、猜测的平台 API、手工 Cookie/JSON 输入或新的浏览器后端。

## 用户流程

1. 在原任务中选择岗位并开始采集。已有成功正文和部分报告保留。
2. 某个所选岗位需要人工登录/验证时，明确勾选“本次登录返回原列表或所选岗位详情后自动继续”，再点击原登录/人工接管按钮。
3. 采集阶段且下一待处理选择可恢复时，打开该岗位自己的正常页面进入登录，而不是丢弃目标跳回首页。没有选择、已结束或未勾选时保留旧登录入口行为。
4. 用户在平台原生页面完成必要步骤。平台返回所选完整详情后，程序核对身份和完整正文，连续两次可读后接回原采集。不必回列表或再点读取/继续，也不再请求这条已经取得完整正文的详情。
5. 返回原列表仍走原列表恢复；不同查询、其他岗位、推荐内容、登录提示或未展开摘要不作为成功。

这不是自动输入账号密码或自动处理验证码。读取到 JD 不证明特定账号已认证，完成后仍使用 `user_resumed`，不新增虚假的 authenticated 声明。

## 一次性接续与原访问约束

观察器只保留下一待处理所选岗位的本地 ID、预期 URL 和完整解析内容指纹。它不把 HTML、密码或 Cookie 放进动作队列，也不发观察请求。最长十分钟、每秒最多一次的既有上限不变。

进入工作线程执行时，再读取一次当前页面并重新核对同一浏览器、同一待处理选择、身份、完整内容及原访问规则。期间页面跳转、正文变化、停止或浏览器替换时终止，不回退为自动重抓；原报告保留。原生网络策略变化、robots 拒绝、HTTP 拒绝等仍按原规则停止。随后恢复只读采集模式；其他待处理岗位仍沿原导航与配额执行。

已保存条目的 `acquisition_path` 为 `login_returned_detail` 或原来的 `navigation`；旧条目没有该字段仍兼容。原报告中的采集审计包括这个路径，不记录认证资料。新内部动作不接受来自工作台 HTTP API 的直接提交。

## 验证范围

`tests/test_login_detail_return.py` 使用明确的人工数据覆盖匹配、完整性、两次稳定观察、第三次重验、取消/替换/页面变化、规则拒绝，以及原服务的部分结果到最终报告。`scripts/run_login_detail_return_browser.py` 是独立真实浏览器验收入口，以人工站点模拟正常登录返回详情，并断言没有多余详情请求、没有推荐岗位请求。

浏览器验收脚本必须实际通过才能将这一层标记完成；单元测试不代替浏览器结果。完整工作流保留全部旧脚本，并增加此脚本。

真实猎聘搜索入口在本轮研究环境进入 `safe.liepin.com/intercept/ip/captcha/dispatch`；该路径已停止，未换出口/账号/工具重试挑战。没有得到 Radar 在用户本机正常会话中的首条真实完整 JD，所以 #49/G1 和 #50 其余目标仍开放。本功能只修复正常页面已返回后的接续缺口，不能掩盖仍未适配的真实登录、搜索和必要资源依赖。

## 回滚

默认仍不启用自动接续。不勾选时继续旧人工登录/恢复流程；回滚本增量不删除岗位、原文、报告、证据、Cookie 快照或配额。没有数据库迁移、生产依赖或站点允许范围变更。

## 接入 PR62 的本轮复核

本轮将此前未发布的本地补丁接入现有 PR62，不覆盖其原生搜索响应、CORS 和猎聘实际记录形态解析。详情型 HTTP 转交任务的 search_url 本来就是详情，不能先因 not_job_list 跳过详情识别；现已覆盖。接续执行只使用仍存活的原浏览器，关闭后不会调用浏览器工厂悄悄恢复另一个会话。原始 API-only 列表接续另有联动回归。

所有登录继续依赖平台允许的正常页面；未新增平台登录主机/接口或自动填密。公开可读内容不要求预先登录。零岗位与缺少可用 Cookie 不再在卡片区提示必须登录。当前真实平台仍待本机一次同关键词、1页1岗位验证，不能用人工上游代替。
