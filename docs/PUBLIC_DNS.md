# 公共域名加密解析（#23 / N5）

当本机无法解析目标域名，但所选代理或系统路线能够连接解析服务时，可在本工作区单独选择“公共域名使用 Cloudflare”。应用查询固定 Cloudflare DoH，再连接经过校验的公网 IP；目标域名不先交给系统 DNS。普通设置和原有 Fake-IP 授权保持原含义，不会根据网络错误自动启用新模式。

## 操作与许可

首页、引导页、高级页的“网络自动适配”共用设置。选择解析范围，阅读说明，勾选同意并保存。切换范围会清除勾选；没有重新同意时保存只会关闭额外解析。保存、刷新和查看状态均不查询域名或测试代理。

新请求和新浏览器会话读取新策略；已有会话不改变路线。模式改变或关闭后，旧策略不能继续借用另一模式的许可发送加密查询或使用其 DNS 缓存。先停止、再打开采集会话以采用新设置；已经发出的请求和已建立的连接不能撤回。

Cloudflare 可看到被查询的域名、A/AAAA 类型和出口。查询不含职位路径、关键词、URL 参数、Cookie、代理密码或个人材料。该模式不适用于企业内部名称、分区 DNS 或要求指定解析商的环境，不保证这些网络的兼容性。明确许可的 PAC 脚本仍可能通过其原生 DNS 函数解析名称；本功能不控制那些脚本。

## 路线与校验

只复用现有固定端点、二进制 DNS 协议和连接实现。解析流量沿目标原选 HTTP、SOCKS、PAC 或系统路线，解析商的 NO_PROXY 不会改变选定代理；失败不改用系统 DNS、其他解析商或直连。源站拒绝、TLS 错误、robots 和来源配额仍独立生效，不重放业务请求。

只接受原问题及其 CNAME 链的有效公网 A/AAAA 回答。私网、混合私网、映射地址、坏响应、拒绝和不存在的名称均停止；不将目标域名直接交给 SOCKS CONNECT。解析端和目标端各自校验证书，目标沿验证后的数字 IP 连接并保留原 SNI。已识别的本地/特殊域名和私网字面地址不发送给解析商。

仍使用最多两次 POST、合计十秒的 DNS 预算、TTL/HTTP 年龄约束、冷却和每工作区对象限额。更换模式清理答案缓存，不重建解析器、不重置预算；策略指纹区分两种模式。此限额仍不宣称跨进程或跨设备统一。HTTP/1.1、固定供应商和现有 DNS 记录类型边界保持。

## 兼容、回退与验收边界

旧偏好原样读取；新模式使用独立的 `cloudflare-public-doh-v1` 许可。不能只把旧 `fake_ip_doh` 的模式名改成 `public_doh`。未增加数据库迁移、运行依赖、系统代理/DNS修改、账号登录或用户原工作区的自动设置变更。

回退到不认识新模式的版本前，先在当前页面取消勾选并保存，或选择原映射修复范围后重新同意保存；确认任务停止，再备份并使用已验证旧源码。旧版本遇到仍启用的新模式会明确拒绝，不会静默降低校验。原报告、配额和其他网络偏好保留。

受控验证覆盖系统目标 DNS 不可用、HTTP/SOCKS 与请求桥的真实本机 TCP/TLS、公网目标绑定、私网回答/证书错误/代理拒绝、模式撤销与原生连接守卫；三页真实浏览器覆盖保存、重载、撤销和窄屏。它们没有查询真实招聘站点，不能替代用户 VPN、虚拟机、企业 PAC 或账号现场验收。SOCKS5h/代理端 DNS、其他认证、WPAD及其他系统 PAC 仍由 #23 保留；此功能不关闭整个 N5/N6/N8。

## 官方依据

2026-10-10 核对：[RFC 8484](https://www.rfc-editor.org/rfc/rfc8484.html) 定义 HTTPS 二进制 DNS；[Cloudflare wireformat](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-wireformat/) 给出 `cloudflare-dns.com/dns-query` 的 POST 与媒体类型；[官方地址](https://developers.cloudflare.com/1.1.1.1/ip-addresses/) 与现有固定 bootstrap 的两组 IPv4/IPv6 相符。没有增加自动端点发现或任意解析商 URL。
