# 0.15.9：响应完整性、升级选择与浏览器清理

基于正式0.15.8，按dev→release→main晋升；正式交付以Tag和附件为准。

## 解决了什么

- #486：公共HTTP请求和浏览器网络桥现在拒绝Content-Length尚有剩余却提前EOF的正文，避免有效JSON/HTML前缀被当作完整成功响应继续处理。
- #487：下载或安装请求等待启动、执行安装预检期间，如果另一次版本检查更换或撤销选择，启动worker时会在同一把锁内再次核对目标与状态，旧确认不能继续执行。
- #488：浏览器上层清理分别尝试策略、浏览器、驱动、请求调度器和隧道，保留首个异常并通知既有关闭不确定保护；清空停止会话的请求状态，启动失败分类不再被清理错误覆盖。

## 提高了什么

减少不完整响应进入JD与报告链的风险，保持升级确认与执行目标一致，使异常路径仍尽力释放其余自有资源。保留原采集、完整JD、原报告、认证、DNS/TLS、调度、下载续传、备份/回滚和升级功能；没有延长期限、删除fsync或放宽断言。清理仍是有限尽力操作，不承诺任意操作系统故障都能强制退出，也未测得可泛化的速度提升。

## 验证结果

- 准确0.15.8负对照：HTTP正文4个方法中2个失败（3个失败子断言）、2个控制通过；修后4项通过（0.079秒），一次相关57项通过（2.100秒）。使用真实HTTP解析器和内存字节，保留chunked、无长度、HEAD/204/304与大小限制。
- 升级选择3项负对照失败，修后3项通过（0.074秒）。一次39项相关检查中38项通过、1项因首次PYTHONPATH遗漏scripts而导入错误；补正确路径后只执行该1项，通过（0.054秒）。原错误日志保留，没有重复已通过组或执行下载程序/安装器。
- 上层清理5项负对照为4失败、1错误（0.250秒）；修后一次92项直接相关检查全部通过（32.999秒），含新增5项、启动健康、节流、下层清理及进程所有权正反例。夹具只使用自有loopback监听器及模拟资源，无真实招聘登录。
- 仅测试发现确认总数3543→3555，新增12项；发现操作不等同完整测试执行。没有重复本地全矩阵。主助手和子助手代码审查不冒称独立真人验收。

候选与准确main仍须各自必要CI和实际程序产物证明；按dev→release→main晋升后发布三个正式Tag并核验公开摘要和旧版升级解析器。实际完成状态记录在总控#57。
