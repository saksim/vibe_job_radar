# Windows 本机 HTTP 拒绝响应（#65）

在多个独立回归中，未授权或跨站的 JSON POST 偶发在读取 403 前出现
`WinError 10053`。原处理器先验证权限并发送拒绝，然后在请求正文未消费时
直接关闭连接；Windows 对这种关闭可能发出重置，客户端因此看不到响应。

处理器仍先鉴权、立即发送拒绝、关闭连接，绝不分发或解析未授权正文。
响应刷新后，仅当 Content-Length 唯一、为 ASCII 数字、为正长度且没有
Transfer-Encoding 时，丢弃这一帧剩余正文的有限前缀，累计不超过原 2 MB 上限。读取以 8 KiB 分块，采用
总共 200 ms 的绝对截止时间，慢速分块不能延长等待。已消费正文不读第二次。
重复/非法或非正长度、传输编码不尝试读取；不消费后续请求或复用连接。
声明长度超过 2 MB 仍立即拒绝为 413；短正文已经到达时，按同一个字节和
时间上限丢弃，避免旧代码直接跳过清理导致客户端收不到拒绝。持续发送
超量正文的连接仍会关闭，不承诺读完整个超量帧。

`test_http_rejection_delivery.py` 检查总时限、大小/帧边界、超时恢复、40 次
真实回环缺令牌/跨站请求均得到 403、无业务调用，以及授权请求仍执行一次。
此修复与平台实站取数及登录无关，也不放宽工作台访问权限。

超长声明/实际两字节正文的 Windows 10053；完整1614项首轮的1错误保留。
本修复从既有PR138提交 `27ddf028` 精确提取生产及测试两文件变更，独立基于
已验收main `4a817d36` 验证，不引入该旧集成PR的其他功能。新增回归检查
超长声明的有限前缀/绝对截止，以及40次实际本机413、零业务分发；原403、
2 MB请求门槛、200 ms清理截止、鉴权及不重放保护保持。准确新头结果见关联PR。
