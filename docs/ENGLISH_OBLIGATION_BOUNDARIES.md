# 英文正文的岗位要求与提及边界

Refs #107 / #3 / #30。自行编写的例句复现了旧规则两类错误：About us/Benefits内的工具产品介绍被自动计入要求；同一行`You must use Cursor. You must not upload customer secrets.`被视为一个禁止条款，丢失前面的正向要求。

规则升级为`rules-0.2.0`：识别有限中英文公司/福利/资格/职责/优先条件标题，包括同行冒号标题；保留原始标题与正文偏移。公司和福利文本不作为候选人要求。常见英文独立义务按句号/问号/感叹号与新条款开头分开，明确的逗号转折正负条款也拆开；小数、版本、URL及常见缩写保持原文，不改写或翻译引用。

明确的使用指令、资格/经验要求可进入原规则结果。仅提及工具、没有明确要求强度的内容进入待复核，不建立AI上下文锚点，也不计入已接受正向统计。英文直接描述建设/销售某个工具产品时也需复核，不能因此自动断言候选人用该工具编程。新增有界的客户数据、敏感代码、API密钥英文匹配，使相邻禁止条款保留在审计中；负向条款不成为正向要求。

这仍是有界规则，不宣称解决所有英文断句、产品名歧义或自然语言义务。未知标题、复杂嵌套否定和上下文应人工复核，不能用扩大词表制造更多Vibe要求。输入摘要仍不能因复核变成完整JD；普通支持技能不会自动成为AI编程要求。

旧报告保持原文件、原规则版本与原统计，继续可查看/导出。重新分析创建新报告，统计可能减少或重新分配，原规则下的人工映射不会静默迁移；既有版本保护要求对新报告显式复核和映射。回退后同样不能用旧规则直接生成新版本报告的个人映射。

验证区分人工句子、真实浏览器产品流程与实站数据：新回归覆盖标题切换/内联标题、正负条款、含糊提及、原生中文行为、缩写/版本/编号、精确偏移、原CSV与历史文件。浏览器测试用自写英文正文，经原表单→报告→CSV→重载，零招聘站点请求；不把这些人工Cursor/Codex句子算作市场证据。当前提交完整测试、CI与初次失败见PR；三站真实登录/取数卡点仍单列。
