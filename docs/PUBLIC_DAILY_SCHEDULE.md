# 本机公开查询24小时计划

对应 #87、#9 R3/R5、#30 H4。此分支基于待审 #86/#84/#82/#72，不能当作已合并 main 的默认能力。

## 用户操作与实际范围

首页“按岗位查询公开来源”中填查询词、地区、来源，再展开“每24小时自动更新这组公开查询”，勾选独立同意并保存。保存只写本机，首次到期为24小时后；修改表单不修改已保存计划，也会取消尚未提交的同意。当前来源仍只有已批准的 Anthropic 公开目录，网页每批最多20条首屏结果，不自动翻页，不调用招聘平台登录。

计划保存在此工作区。工作台服务运行时，关网页不影响；关服务则停止执行。重启后已到期但尚未开始的计划最多补一次，下一次从实际完成时间起算24小时，不密集补跑历史日期。底层仍使用原公开任务、缓存、全目录变化审计和本批报告；目录抓取后在本机筛选，首屏结果不是完整市场覆盖。

点击“停止计划”立即持久停用，并对属于此计划的当前公开任务请求协作取消。已开始的只读请求或本地保存完成后停止，缓存、报告和历史保留。过去20次结果在计划下方展示，点击结果可打开对应原报告；新定时结果不会替换用户已经明确打开的报告。

## 运行与异常语义

- 默认无计划文件、无外部访问；只有带本机会话令牌的同源操作能配置。只接受现有查询字段、已批准本机来源及无游标的首屏查询。
- SQLite 单行记录包含版本、修订号、固定查询、来源契约/路线指纹、到期时间、执行标记和20次结果。跨页面旧修订拒绝，不覆盖新计划。凭据与网络策略对象不写入计划。
- 工作区的 OS 文件锁决定单个调度所有者；其他服务实例等待，不恢复或重复其执行。这里不宣称解决其他旧任务的跨进程所有权或跨设备配额。
- 先持久记录本次执行标记，再交给原 PublicTasks。进程退出留下不确定标记时暂停；只有原任务ID匹配且已明确完成时才对账保留结果。已有手动公开任务忙时等待，不抢占。
- 到期时重新检查来源、许可与网络指纹。提交前再次核对，并在内存固定本次已确认的网络策略，避免用户修改偏好时后台线程悄悄换路线。
- 来源/路线改变、时间回拨、失败、被停止或使用过期缓存都会暂停。保存错误后当前调度实例停止，不循环重试不确定提交。原任务的缓存、冷却与配额均保留；重新启用必须重新确认查询条件。
- 定时任务与手动任务共用现有单任务槽；极短的任务完成→结果对账间隙若被新的手动任务替代，计划按“不确定”暂停，报告仍在原历史中，不猜测成功。

## 验证

新增21项测试使用真实 PublicTasks、缓存、SQLite 和报告实现，外部目录为人工夹具。覆盖首次24小时、漏过多日只补一次、首屏边界、停止前后提交、失败/过期缓存、路线/来源改变、排队期间路线固定、时间回拨、不确定提交、已完成报告对账、存储失败、跨页面修订及真实第二 Python 进程的 OS 调度锁。

`python scripts/run_public_schedule_browser.py` 使用实际浏览器和本机 HTTP API：保存不联网、修改表单撤销同意、旧页面冲突、关闭所有页面后执行、报告固定与历史链接、390px、关闭服务后重启补一次、停止后零新增请求和三份报告保留。时间使用注入时钟，网络使用明确标注人工内容的夹具。此脚本进入原浏览器 CI，不替代三站现场或24小时长跑认证。

## 升级与回退

这是独立可选目录 `public_schedule/schedule.sqlite`，不改原任务、缓存、配额、岗位和报告的数据格式。回退前先在新版本停止计划，等待当前请求完成，关闭服务并备份整个工作区。旧源码忽略计划目录，仍可读原报告；以后恢复新版时，已停用的计划保持关闭。若未停用就切换版本，旧版不会调度，但重新打开新版可能执行此前已授权且到期的一次查询，不能把“旧版忽略”当作撤销计划。
