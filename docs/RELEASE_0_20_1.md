# 0.20.1：分类任务接纳与历史观察分离

对应 [#521](https://github.com/saksim/vibe_job_radar/issues/521)，基于正式 0.20.0 继续收口高级页边界。实际完成状态以配对 PR、准确 main 的 CI、正式 Tag 和镜像回执为准。

## 解决了什么

分类“下一批”和“下一页”已成功创建子任务后，历史列表读取失败曾阻止其进入原继续流程。本版将创建回执与准确子任务身份先独立保留，再进入原后台执行接纳；历史读取使用独立错误提示，迟到结果不会覆盖不同任务的选择或后台状态未知提示。

## 提高了什么

两个衍生入口共用小范围前端流程边界，业务接纳继续交给原后台服务，页面上的辅助观察不再决定任务能否执行。原授权、所有权、网络预检、共享额度、暂停与报告保存保留。已存在的子批次不自动执行，分类恢复和同页重试仍只保存，不自动联网。没有新增后台 API 或改变服务器部署模式。

## 验证结果

两处在 0.20.0 上各作一次定向首红：创建成功、历史读取失败，原 5 秒内未发出后台启动请求，子任务保持暂停且没有新增上游请求。首个探针另有折叠诊断文本读取错误，原退出码及完整记录保留，并经独立审查区分夹具错误与产品首红。修后仅新增四组定向浏览器验证一次运行、4/4通过：下一批和下一页准确接纳对应子任务；已存在子任务不自动执行、真实后台关闭拒绝与迟到历史错误保持各自语义；临时共享额度恢复仍只保存，不发起采集。旧父任务、原报告和预算语义保持，页面异常及外部请求为空。原八组验收可逐字还原，未在本机重复运行；默认CI仍执行全部原八组及新增四组。准确候选/main 的完整CI和正式发行结果另以本期实际回执为准，未执行的检查不计通过。

## 剩余问题

原 18 项的真实站点、完整 JD、人工标注、本人项目、普通净机和生产环境验收继续单列；#183、#263、#269、#436 的历史因果缺口不以新版通过替代。#210/#320保持只读，#23/#30维持既定本期范围。没有可信签名凭据，桌面发行仍 unsigned / unnotarized。服务器仍为单人、单工作区模式，未宣称真实生产部署或多用户私有数据隔离完成。
