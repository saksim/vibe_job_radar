# 猎聘原生可见搜索与登录返回

新建、仅含关键词的原生任务先打开无查询参数的搜索入口，再通过唯一可见的“搜索职位、公司”输入框填写关键词、提交一次 Enter。显式筛选入口保持原地址。无查询参数入口以所属文档中的唯一可见、启用且非只读的搜索框作为就绪条件；默认推荐未返回时也可提交原关键词，默认推荐已返回却没有可用搜索框时仍继续等待。就绪观察前后重新核对页面身份、访问权限、暂停及挑战状态，不增加等待期限或重放输入。默认推荐响应不能作为关键词候选或“没有匹配岗位”；必须收到当前网址和完整条件对应的响应后，才能进入原来的选取、完整 JD、Store 与报告流程。

浏览器后台用所属页面的主框架导航事件建立身份，覆盖 Edge/Chromium SDK 与 Chrome 直接 CDP。完整导航替换已提交文档；history 变化只更新当前地址。只有真正提交的无查询参数入口可以沿用该文档的访问判断，实际文档/API 请求仍各自检查 robots 与请求规则。同地址的页面替换、所属会话变化及读取期间导航都会使旧观察失效。

本人选择登录后自动继续时，新任务须满足原查询、未有候选/选择或冻结筛选、仍等待人工登录等条件。账号区域和唯一搜索框出现、登录/密码控件消失，经两次稳定观察才能产生一次内部交接；原工作线程提交前还须第三次重新核对。账号区域可用不证明特定账号已经认证。原条款勾选状态、密码提交结果、登录额度、滑块和短信人工处理要求保持。

等待中的页面变化只在原 15 秒就绪期限内重新观察；不会重新导航或再次提交关键词。明确下架职位立即保留 `job_unavailable`。其他访问拒绝、暂停和截止时收到的原错误保持。只有输入前的明确入口 GET 可采用既有有限读取重试，表单输入不能重放。

本范围新增 74 项行为测试，包含 13 项页面身份、56 项原表单/返回/就绪测试及 5 项导航竞态防护。隔离原型 401 项相关回归通过；首轮测试对象适配错误及原负对照日志均保留。两个真实浏览器的本地事件验证仅证明共同导航身份接口可用。六类新增原生浏览器场景仍须在 CI 的隔离机器验收：完整流程、确认为空、缺失响应、人工验证、实际查询文档拒绝及合成登录返回。先前 23 个精确地址场景保留所有断言，其中默认入口输入明确为带 currentPage=0 的种子地址以独立覆盖原路径。

上述合成场景不代表猎聘实站账号登录验收；父 Issue #63/#196 的其余问题继续跟踪。
提交前最后一次正文读取也会重新核对所属页面身份。该读取期间替换同地址文档或页面的1项测试，在修复前有2个失败子例；修复后401项回归全0，负对照与修复记录分别保存。


## 入口等待回归（现有 #45）

旧代码在可用搜索框已经出现、默认推荐响应缺失时仍于提交关键词前报 page_not_ready；未修改生产代码的负对照为 1 个测试、1 个错误。修复只改变匿名的无查询参数入口；登录入口、显式筛选文档，以及提交后对本次查询响应的要求保持。单元回归涵盖未出现/重复/禁用/只读控件、迟到控件、同地址文档及页面替换、权限拒绝/暂停/挑战与提交后缺少响应。原生浏览器夹具新增“不发默认推荐请求”的完整搜索、正文及原报告场景。

这证明上述等待依赖可以消除，不证明 2026-10-10 实站超时瞬间搜索框已经可用；该时刻未记录表单状态。实站恢复及真实账号登录仍需各自验收，不能用合成结果替代。

入口默认推荐晚到时不会结束提交后的结果等待；有结果及确认为空两种延迟响应均覆盖。补修前的单项负对照含两个 page_not_ready 错误子例。
