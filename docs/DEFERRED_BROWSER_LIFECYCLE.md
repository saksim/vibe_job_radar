# 等待期间关闭采集窗口（#73）

任务因发布方节奏或共享配额等待时，只能在原采集会话仍然有效的情况下自动继续。原实现只检查后端对象是否还在字典中：即使窗口已经关闭，到期仍会排入动作，后续按普通操作重建浏览器。

现在在拥有浏览器的线程中检查其生命期、认证模式和错误状态。窗口关闭、状态未知、检查异常、仍在认证或已有致命页面/HTTP 错误时，取消自动接续并提示明确继续；任务条件、选择、已有报告和原截止时间保留。正常等待到期的原会话仍走已有配额与采集逻辑。发布方等待必须有对应的 `RateLimit`；后台请求因等待而留下的普通 `paused` 标记不妨碍原会话到期继续。

定时动作携带仅在内存中的原后端引用；动作真正开始时再次校验，窗口在排队之后关闭或被替换也不能自动创建浏览器、读取保存会话或借用别的窗口。用户明确点击继续后，才允许按既有正常流程重新打开。登录与分页点击不加入自动计时重放。

状态读取接口不跨线程调用浏览器。自定义后端如需自动定时继续，必须在工作线程提供 `alive()` 并返回严格的 `True`；缺失该方法时仍可手工继续。测试中的旧假后端补充此方法以准确模拟存活状态，未放宽生产判断。

此变更不调整发布方间隔、HTTP/页面/登录配额、网络策略或默认后端，不删除原报告或配额。回退只涉及源码；没有新工作区数据格式迁移。窗口生命期修复不能解决 #63 的猎聘真实页面空白，也不构成真实登录或完整 JD 验收。

`scripts/run_deferred_browser.py` 用实际 Chromium/Edge 窗口和人工岗位验证：首个完整 JD 与报告保存后，第二项进入发布方等待；关闭窗口使计时器失效，到期没有新窗口、请求或配额变化；明确继续才创建一个新采集窗口，跳过已保存 JD 并完成剩余项，旧报告仍可读取。所有站点响应由本地测试传输提供，真实来源请求为零。
