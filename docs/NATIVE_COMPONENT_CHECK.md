# 实际进程中的原生组件检查

`VibeJobRadar.exe --native-browser-check` 在该 exe 自身进程中构造生产 `NativeBackend`，使用包内 Node/浏览器和生产 CDP 管道。源码启动器也支持同一选项，但输出明确标为 `source`，不能作为 exe 已验证的证据。

检查使用临时目录和全新浏览器，只读空白页上的固定计算结果，然后发起一个固定虚构 `.invalid` 请求，验证生产控制器本地拒绝。该主机不在人工契约或 CONNECT 主机白名单中，在解析/外连前即拒绝；契约没有任何允许网站操作。检查不读取用户网络设置、工作区、账号、Cookie或已有浏览器，不调用招聘入口、登录、搜索、robots或正文。通过条件还包括零外连、原生控制器已安装到该页面，以及自己的进程和临时 profile 均清理完成。

命令输出固定字段 JSON，失败退出码为2；原始异常、进程日志、路径和账号值不输出。它不启动网页服务器，不能和doctor/worker或监听端口组合。现有普通doctor仍检查离线工作区能力，不新增浏览器副作用。

Windows候选验收在去掉Python/虚拟环境路径的环境里，直接运行所构建的exe执行此命令。任一检查缺失、源码runtime、环境浏览器替代包内浏览器、清理不确定或出现外连都不能通过；失败阶段和固定错误码仍保留于原验收结果，未通过不会留下合格产物。此前仅包含CDP脚本的文件指纹或其他Playwright空白页通过，不能追认为已执行此检查。

这覆盖实际包内原生组件的启动、页面读取和请求拒绝，不是原生HTTP/TLS正文链路、真实招聘账号、搜索/JD或报告验收。上述链路继续沿用各自人工HTTPS及实站证据，不从本检查推导成功。实际测试成绩以PR/Issue记录为准。
