# 实际进程中的原生组件检查

`VibeJobRadar.exe --native-browser-check` 在该 exe 自身进程中构造生产 `NativeBackend`，使用包内 Node/浏览器和生产 CDP 管道。源码启动器也支持同一选项，但输出明确标为 `source`，不能作为 exe 已验证的证据。

检查使用临时目录和全新浏览器，只读空白页上的固定计算结果，然后发起一个固定虚构 `.invalid` 请求，验证生产控制器本地拒绝。该主机不在人工契约或 CONNECT 主机白名单中，在解析/外连前即拒绝；契约没有任何允许网站操作。检查不读取用户网络设置、工作区、账号、Cookie或已有浏览器，不调用招聘入口、登录、搜索、robots或正文。通过条件还包括零外连、原生控制器已安装到该页面，以及自己的进程和临时 profile 均清理完成。

命令输出固定字段 JSON，失败退出码为2；原始异常、进程日志、路径和账号值不输出。它不启动网页服务器，不能和doctor/worker或监听端口组合。现有普通doctor仍检查离线工作区能力，不新增浏览器副作用。

清理分项保存在 `cleanup`：是否尝试关闭、关闭是否返回、临时 profile 是否删除、是否记录删除失败、桥接进程是否退出、代理是否关闭及代理线程是否停止。布尔值不可观察时为 `null`，不能当作成功；关闭异常只保留固定类型名称。实际 exe 的便携验证保留相同的字段白名单。原有清理动作、时限、总体成功条件和退出码保持，不增加重试或放宽资格。

2026-09-25，PR201 的 `a22d775` 首次 CI 为21/22。其 [Windows 作业](https://github.com/saksim/vibe_job_radar/actions/runs/36190628425/job/108254609167)在实际 exe 的组件检查中完成空白页、请求拒绝和零外连，随后 `cleanup_verified:false`；临时构建目录的 `chrome.dll` 删除也被占用阻止。旧结果只有总体布尔值，不能据此确定是进程、目录还是代理线程未结束，也不是此前 Playwright `set_content` 超时。故保留原失败并增加分项事实，尚不声称根因已修复。

独立 Windows 进程实验曾直接运行原管道桥，用自有子进程的文件锁和无关同类进程作对照。本机 EOF 后锁释放、对照进程仍运行，没有复现“EOF 必然遗留子进程”的猜测。该实验加入首版 `2097d3a` 后，Windows 3.12 在原10秒等待内未收到人工子进程就绪标记，尚未执行 EOF 断言；启动原因未知。首版 CI 的20/22、该实验源码和完整失败工件保留于[PR203](https://github.com/saksim/vibe_job_radar/pull/203)及[Issue202](https://github.com/saksim/vibe_job_radar/issues/202)，没有把它当作浏览器清理故障复现。

本次交付限于清理分项诊断，将这个未复现原问题的额外实验从必需单测移出。原先所有测试、实际 exe 中自有浏览器/profile/代理清理验收及时间限制均保留；新增诊断测试覆盖各分项失败、观察未知、关闭异常和便携字段过滤。首版实际程序作业另在打包前单测触及600秒上限，未生成exe；该结果和原 `a22d775` 的真实exe清理失败分别保留，不将本次范围调整称为修复上述未知原因。

Windows候选验收在去掉Python/虚拟环境路径的环境里，直接运行所构建的exe执行此命令。任一检查缺失、源码runtime、环境浏览器替代包内浏览器、清理不确定或出现外连都不能通过；失败阶段和固定错误码仍保留于原验收结果，未通过不会留下合格产物。此前仅包含CDP脚本的文件指纹或其他Playwright空白页通过，不能追认为已执行此检查。

这覆盖实际包内原生组件的启动、页面读取和请求拒绝，不是原生HTTP/TLS正文链路、真实招聘账号、搜索/JD或报告验收。上述链路继续沿用各自人工HTTPS及实站证据，不从本检查推导成功。实际测试成绩以PR/Issue记录为准。
