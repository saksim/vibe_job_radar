# Windows 登录后打开工作台

Refs #105 / #9 R3 / #30 H4,H6 / #87 / #91。此候选默认关闭，只支持 Windows 便携包。源码版和其他系统继续手动启动。它补充既有本机每日计划，不是独立常驻服务。

首页“本地数据与辅助工具”下方展开“登录 Windows 后打开工作台”，核对当前 exe 和工作区，勾选后启用。只为当前 Windows 用户登记；下次该用户登录时打开该程序、网页和可关闭的终端。关闭终端结束本次服务；关闭网页不结束服务。启动过程只读取设置，不自动安装或修复启动项。

每日计划独立保存、默认关闭。用户已启用的计划在工作台启动后仍遵守原24小时间隔、条件绑定、最多补一次与失败暂停。开启登录启动不创建查询、不自动登录招聘平台，也不替用户选择计划。

“关闭登录启动”只移除下次登录的登记，当前任务和计划保持。移动或升级便携包之前，从旧包关闭登记，再关闭工作台并备份原工作区；打开新包后核对路径、重新勾选。若直接换包而保留原工作区，新包显示旧路径登记，允许关闭旧登记，然后重新选择；不会静默改指向。若移动工作区，也应先关闭旧登记，否则它仍指向原工作区。回退版本不会理解本功能，应在回退前关闭，或从 Windows 启动应用设置核对登记名称。

## 状态与实现边界

- 只使用当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `VibeJobRadar.<工作区摘要>` 单值；不使用系统用户、RunOnce、计划服务、密码或任意脚本。
- 命令固定为当前 `VibeJobRadar.exe --workspace <当前目录>`，两个路径正确引用，不使用shell；拒绝控制符、引号、环境变量占位符、UNC与超过260 UTF-16单位的命令。过长时先选较短目录。
- 本机回执先原子保存，再写登记；崩溃/写入失败后根据真正注册表值判断状态。旧页需带当前修订，两个本应用实例经原OS锁串行更改；不匹配的外部值、损坏或异工作区回执均拒绝覆盖/删除。
- 注册表没有提供本流程使用的跨外部工具原子比较交换；操作前和回读均核对自身项，不宣称能阻止同用户外部工具在检查与写入之间并发修改。回执不是启动成功证明。
- 界面显示“已登记”。Windows可能延迟执行或由启动应用设置禁用；本应用不修改系统的独立开关，不保证精确登录时刻启动。实际重新登录、睡眠/重启后的长期计划验收单列，不能用登记回读替代。
- 本机离线/浏览器测试使用隔离注册表。只有显式 `--verify-login-startup` 且位于临时 GitHub Actions runner 时，便携验收才执行实际exe登记、第二进程回读、移除及失败清理。普通本机构建/验收不写真实登录启动项。失败保留阶段和脱敏错误类型，不上传完整命令、工作区路径或原始系统异常。

依据：[微软 Run/RunOnce 契约](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)规定登录触发、260字符上限及可能延迟；[Windows 启动应用管理](https://support.microsoft.com/en-us/windows/experience/startup-boot/configure-startup-applications-in-windows)说明用户可在系统设置管理启动。三站实站认证、无人登录的服务执行、跨设备队列仍未完成。
