## 实际发现与修复

### 1. 最后一次查询与等待锁期间的撤销／取消

原实现只在发起每个地址族查询前检查取消与许可。若用户在第二个回答到达时撤销，或者等待另一个查询的锁时撤销，仍可能收到结果／命中缓存。
现在在获得锁后、连接建立后发送 DNS 正文前、读响应期间、每个地址族返回后及交付结果前重查。系统 DNS 返回后也检查取消。已经发送的字节不能撤回，不承诺撤销历史网络访问。
取消及撤销不被改写成网络故障，不缓存其半成品，不给下一次任务制造额外故障冷却。

### 2. 区分零 TTL 与已过期

原实现把 `TTL - Age` 的负值夹成 0，并将它当成本次事务仍可用的零 TTL。真正的 TTL=0 可以供当前事务使用，但原来为正、已被 HTTP Age／传输耗时消耗完的地址不应该借这个例外重新变有效。
现在计算 Age 与本次请求至完整响应的耗时，拒绝耗尽的正 TTL。CNAME 最短 TTL、无地址族的负回答有效期也参与两次回答之间的到期判断。高位为 1 的 TTL 按 RFC2181 视为 0。
`Answer.valid_for` 与缓存 TTL 分离：`no-store`／`no-cache` 禁止复用，但不会关闭正有效期的检查。
重复 Age／内容类型等歧义头拒绝；多条 Cache-Control 合并，不能丢失先到的 no-store；重复、非法 max-age 不作为正常缓存规则使用。未启用过期 DNS 地址降级。

### 3. 硬失败不能在第二次点击变成“临时等待成功”

原解析器将任何失败后的冷却统一返回 `encrypted_dns_cooldown`，而公开岗位客户端允许临时故障时使用带过期标记的缓存。这样，证书错误／非公网回答可能第一次失败、第二次却通过缓存生成报告。
现在解析冷却保留原硬失败类别；只有确实的暂时不可用／超时被归为临时等待。

还修复客户端自己的请求频率限制带来的同类问题：本机目录与可选远端客户端用 `CacheFailureGuard` 保留来源级硬失败。重试间隔、切换关键词、分页、重启或后来的暂时错误，不会把尚未解决的拒绝／坏数据当成成功。一次全新、校验通过的获取才清除状态。
仅保存固定错误码、版本、时间，不保存域名、查询、响应头、异常消息、Cookie、密钥或正文。来源按哈希隔离；损坏、符号链接或未来时间不静默当作无错误。
历史报告不删除。显式 `cached()` 历史读取仍可用，但保留原采集时间和未解决的错误；它不等于重新获取成功。

### 4. 特殊本地域名不发送到公共 DNS

在调用系统 DNS／DoH 前拒绝 `.onion`、本地域名及既有特殊域后缀，包括 `home.arpa` 本身。该公开来源解析器不实现 Tor 或企业内网解析；不能将这些名称误当作公网 Fake-IP 修复目标。

## 验证

新增 `test_dns_resolution_review.py` 和 `test_public_cache_guard.py` 共 41 项测试。与基线 627 项在同一源码中执行：668 项，不删除原测试。旧“TLS 失败后只有通用冷却码”的断言改为必须保留 TLS 原因；旧过期 TTL 测试改为区分真零 TTL 与已过期，不是删掉安全断言。

## 使用和回滚

普通用户仍只需在“网络自动适配”阅读 Cloudflare 域名解析的隐私说明并同意一次；无需自建服务器、填写端口或改 OS DNS。仅系统结果全为 `198.18.0.0/15` 时进入该可选路径。

新增 `failure-<scope-hash>.json` 是本地最小来源状态，不改变原数据库。回滚先停止活动任务，保留工作区／限频／原报告及这些状态；旧版不会消费新失败状态，不能宣称保留同等防掩盖保证。不删文件制造成功，不重新启用已撤销的许可。
