# 主线：首份可用的岗位研究，而不是基础设施清单

## 为什么创建

本项目原始说明（README_CLI.md）的结果是：把目标岗位文本变为逐条可追溯要求，再形成通用能力底座、分岗位补充、本人可量化表达及缺口。默认方向是垂直领域算法、时间序列算法、架构师。网络和缓存只为此服务。

用户已要求快速回归这条主线。生产服务、多来源监测平台、额外缓存层和非当前用户流程必需的发布工作暂缓；原任务保留，不删除承诺。当前开发基线是合并 PR35 后的 main@a9d8173fb4050ae0f8da80ce2bd8a42f184f4504。

## 本次用户流程

1. 首页先确定岗位/平台/检索词。将目标带到原浏览器采集向导，只传本地 URL fragment，校验字段；不自动勾选访问许可，不发起平台请求、不代填密码。
2. 原向导正常登录、读取列表、选择正文后，直接返回本批研究结论。手中已有真实完整 JD 可按原入口录入/导入，不因此视作自动采集验收成功。
3. 新报告包含 research_brief.json/md 及首页首读摘要：输入与纳入数量、排除原因、原文引用、样本内能力、分岗位补充、本人证据下一步。严格使用现有分析的 accepted/positive 和去重分母，不重新抽取或补写要求。
4. “用我的证据继续”携带同一个报告 ID 到原文复核中心；已有较新报告也不替换目标。由用户复核、填入本人项目/负责范围/真实指标，再由原证据引擎生成个人报告。返回和刷新保持该报告，不由旧公开任务抢占。

原始清单、源码句子偏移、下载接口、旧报告和个人数据保护保持。不新增后台采集、公开任务取消接口或高级批次网络接线，不包装重试历史被阻止的变更。

## 结论边界

- 没有目标岗位正文、只有摘要、普通岗位技能、否定/待复核语句，均不能冒充正向 AI 编程要求。
- 共同项只限足够的当前样本，单岗位要求不成为通用底座；频次不等于市场占比。
- 待补证表示该报告没有本人已确认的精确映射，不表示本人不具备能力。
- 个人数字只来自用户观测，不能把招聘方要求或示例变成履历；生成模板不是可直接投递的事实。
- 旧报告不被重新分析或迁移。没有新摘要时仍可阅读原清单；不存在、损坏或合成报告不能被自动替换成另一份真实报告。

## 下一阶段唯一P0：目标平台现场闭环

必须用一个目标岗位、一家指定平台的一次完整实际流程证明“搜索→正常登录→取得相关列表→选取完整正文→本批分析→本人证据”。先完成少量实际样本再跨日期扩展，报告应保存样本分母与失败条目。网络矩阵只优先验证该流程实际遇到的阻断；不能让平台取数一直被外围模块替代。

当前Anthropic公开来源可验证真实来源路径，但不能代表中国招聘市场、时间序列/电力算法需求或三站认证。主线截图、人工JDs和测试指标只能证明程序行为，不能充当真实用户验收。

## 本次验证方法

`python scripts/run_tests.py` 保留全量回归；新增研究摘要测试区分零正文/零AI证据、单样本/共同项、不同岗位、排除原因、模板事实、报告快照和文件清单。`scripts/run_research_workflow_browser.py` 使用人工材料，实际操作首页→目标带入（不请求站点）→JD分析→指定报告复核→本人填入指标→个人报告→返回原报告，并检查错误ID不静默回退、窄屏、无额外外部请求。

该脚本加入已有浏览器CI，所有旧脚本保持。最新提交CI结果另行核验；工具本地浏览器失败不得算成通过。测试数不是本阶段的产品验收指标。
