# 自动采集能力说明与下一阶段路线

核对日期：2026-09-14。实现依据：`collection.py`、`network.py`、`html_parser.py`、`advanced.js`。外部官方资料列于文末；本文件将已实现功能、未实测能力和后续设计分开。

## 一、可以怎样介绍当前项目

> Vibe Job Radar 是招聘要求与个人证据分析工具，支持通过搜索 API 自动发现多平台职位线索，对明确允许访问、且结构可识别的公开 HTML 职位页进行批量正文获取，也支持按约定契约接入用户提供的授权 JSON 数据源。采集结果自动去重、入库、分析并生成来源级审计。当前未完成各大招聘网站专用爬虫的逐站实测认证。

不能写“已打通 BOSS、猎聘、前程无忧等 8 平台完整自动采集”“自动登录全网抓取”“全平台成功率 99%”。没有数据分母、实际接口契约和实站验收，不存在这些保证。

不是完全没有爬虫：当前 `SiteFetcher` 的确发送 HTTPS 请求获取页面，是有限的 HTTP 正文采集器。缺的是特定网站完整采集路径及运行认证，不是所有功能都只是假接口。

## 二、三条路线的具体含义

| 路线 | 实际请求发给谁 | 如何得到正文 | 主要限制 |
|---|---|---|---|
| search | Brave 搜索服务，随后可能访问许可域名 | 搜索先返回摘要，再由 SiteFetcher 尝试详情 | 搜索索引不等于平台全部数据库；保存结果需套餐权限 |
| urls | 用户给出的获准 HTTPS URL | HTTP 返回的 HTML 中提取独立 JD | 不渲染 JS，不继承浏览器登录态，不自动跟随跳转 |
| feed | 用户提供的实际 JSON API | 解析 jobs 数组；显式 full_text 才是正文 | 固定 GET/cursor 契约，不是任意网站 API 自动适配 |

feed 路线需要数据提供方确实提供接口。没有这类数据源时，不能通过填一个 BOSS 网页地址就获得它。原始字段映射、认证协议、非本项目分页契约不同的服务仍需专用适配。

8 家平台是默认域名注册项。新增域名只改变检索、归属识别和允许域名集合，不会自动产生站内搜索、页面选择器、会话、分页或者官方 API 权限。

## 三、已实现与仍缺少的能力

| 能力 | 当前状态 |
|---|---|
| 多平台关键词交错检索、搜索分页、预算 | 已实现；上游按 Brave 契约 |
| 已知 URL 批量正文获取、HTML/JSON-LD 解析 | 已实现；只适用实际可访问且可识别页面 |
| 统一职位记录、去重、快照、新鲜正文复用 | 已实现；不等于确认职位仍在招 |
| JSON 数据源游标分页 | 已实现；需要真实提供方契约匹配 |
| 来源级失败原因、暂停/继续、中断记录 | 已实现 |
| 正常用户登录及本机浏览器会话复用 | 未实现于生产采集器 |
| JavaScript 动态渲染、列表滚动/站内翻页 | 未实现于生产采集器 |
| 各大网站专用搜索/详情适配与真实样本认证 | 尚未完成 |
| Retry-After、自适应退避、统一全请求预算 | 尚未完整实现；当前主要是固定间隔和拒绝后停止 |
| 常驻 worker、定时新建任务、无页面长期运行 | 未实现；已有 CLI 仅驱动已创建任务，前台进程结束即停 |
| 验证码自动破解、访问拒绝后换身份继续 | 不作为本项目交付目标 |

仓库里的 Playwright 用于测试本地工作台，不等于采集器已经能驱动第三方网站浏览器。当前 `SafeHTTP` 不执行网页脚本，401/403/429 会停止服务/主机，robots 不可确认时保守停止；后两者不是“已经自动修复反爬”。

页面保持打开时，高级页循环请求后端 `step`。关页不再发新步骤；CLI 可在没有页面的情况下继续一个已有任务，但不是 Windows 服务、守护进程或定时调度器。任务中断后保存为不确定结果，不退预算、不自动重复该请求；这是审计可恢复，不是每次都能无损自动续传。

`detail_attempts` 是正文获取尝试数，可能连正文请求都没发出就因 robots 停止，也可能额外发 robots 请求。不是总 HTTP 请求数。报告还可能包含同工作区此前满足条件的记录；本次新增/受限来源应看 `collection_manifest.json`，不要用整个数据库总数当本次抓取量。

## 四、如何实现真正的逐站自动采集（后续设计，未交付）

建议目标是“有权限边界、可持续运行、可解释失败的站点采集器”，而不是“永不被封的万能爬虫”。逐站优先级按实际允许的接入路径和可验收性决定；不假定任何网站没有官方接口，也不猜测其私有端点。

**阶段 A：首站最小闭环。** 固化站点 source specification：来源域名、适用账号/授权范围、搜索入口、分页、详情结构、字段、终止条件和采集预算。优先官方授权接口；页面自动化适用于实际允许访问的页面。交付列表→详情→规范化 JD→去重→报告，至少完成一站真实样本验证，不用八个空适配器代替。

**阶段 B：浏览器采集后端。** 可选 Playwright 依赖，保持本地分析无需安装浏览器工具。使用独立本机浏览器配置，允许用户正常登录和人工处理验证；授权会话有失效检测、撤销和本地保护。等待真实 DOM/响应就绪、解析动态正文、处理明确允许的分页。登录成功不自动扩大内容使用权限。浏览器全部导航、子资源及重定向仍需域名/网络安全边界，不能绕开现有内网访问防护。

**阶段 C：采集韧性。** 按站点/账号限额调度，低并发起步；对可重试网络故障做有上限的指数退避与抖动；遵循服务明确的重试时间；失败率上升降速和熔断。缓存、增量水位、稳定身份、去重和检查点减少无谓请求。DOM 结构变化进入解析告警，不把验证码页或空容器当正常 JD。401/403、登录或验证码转人工/授权恢复，不靠账号池或身份轮换继续被拒绝的访问。

**阶段 D：常驻任务与认证矩阵。** 独立 worker + 队列 + 调度 + 取消/暂停状态 + 进程恢复；UI 不再负责持续驱动。每个平台显示 configured / fixture_tested / live_verified / degraded，以及验证时间、页面/接口版本、范围和证据。失效后降级，不永久保留一次成功的认证标识。

以上是后续建设范围，不是当前分支已经新增了 Playwright 爬虫或 worker。

## 五、“反反爬”应该落实成哪些指标

可以建设的是授权范围内的抗限流、抗会话过期、抗网络抖动、抗页面变化能力。适当浏览器渲染解决动态页面，正常会话复用避免反复登录，自适应节流减少对站点负担。这些技术不会让禁止访问变成允许访问。

不以验证码破解、窃取 Cookie、未授权接口探测、伪装身份逃避访问拒绝作为验收。遇到挑战时停止并要求用户正常处理；保护内容边界和用户账号，不给“全站永远可抓”的承诺。

建议每站验收表至少记录：

| 指标 | 口径 |
|---|---|
| 正文获取成功率 | 实际拿到可解析独立 JD 的数量 / 实际执行的许可内详情尝试数 |
| 字段一致率 | 人工抽查中符合原页标题、公司、正文和日期的字段数 / 已检查字段数 |
| 已知集合覆盖率 | 从事先记录的许可内列表中取得的唯一职位数 / 该列表已知唯一职位数；分母未知则不报告全站覆盖率 |
| 挑战/拒绝率 | 登录、验证码、401/403/429 分别计数，不能合并为网络故障 |
| 数据新鲜度与成本 | 距最近成功观察的时长、每条有效正文的请求数/耗时；复用缓存与新获取分开 |
| 可恢复性 | 暂停/进程中断后重复与遗漏；未经确认的中断不标为成功 |

建议首站至少人工抽查 30 条、跨 3 个日期观察，并测试失效/撤销、分页结束、限流、布局变化和进程退出。这是拟定发布门槛，不是已经达到的结果或普遍行业标准。不能只拿一个页面成功截图就写“支持整个招聘平台”。

## 六、官方参考

- [Brave Search API](https://brave.com/search/api/)：自有搜索索引；保存结果需明确 storage rights；不授予第三方内容权利。
- [Playwright Python 认证](https://playwright.dev/python/docs/auth)：可以复用正常登录状态；状态文件含敏感信息，不提交仓库。
- [Playwright 自动等待](https://playwright.dev/python/docs/actionability)：元素可操作性及等待机制，用于减少动态页面时序错误。
- [Scrapy AutoThrottle](https://docs.scrapy.org/en/latest/topics/autothrottle.html)：按延迟调节抓取间隔，出错时不因响应更快而加速。
- [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html)：robots 协议不是访问授权机制；robots 允许不等于其他授权，当前更保守的 404 停止是项目策略。
