# 0.4.0：跨设备任务所有权与稳定版升级入口

关联 [#355](https://github.com/saksim/vibe_job_radar/issues/355)、[#356](https://github.com/saksim/vibe_job_radar/issues/356)和[总控 #57](https://github.com/saksim/vibe_job_radar/issues/57)。代码按功能分支 → dev → release → main 晋升，正式下载以[公开发行页](https://github.com/saksim/vibe_job_radar/releases)及实际 Tag 为准；文档存在不代表发行已完成。

## 解决了什么

- 配置团队服务的本机公开任务原先只有共享额度，现在增加服务端持久任务租约，避免两个登记设备同时启动同一资源的采集。到期接管后旧拥有者不能续租、释放或继续预留额度。
- 首页新增明确检查稳定版、核对变更和下载准备入口；核对官方8资产、来源提交和摘要，将新版解压到独立目录，保留旧程序和工作区。
- 发行流程支持标准版本 Tag、公开稳定 Release 和 Latest；必须先完成准确 main 的既有8工作流，再校验实际上传8资产。原预发行/草稿入口保留。

## 提高了什么

- 工作台、原公开计划/队列及独立 worker 共用租约生命周期；崩溃后可到期接管，失效后阻断后续请求，报告提交前再确认。额度不因释放/接管退款。
- 租约只在真正访问来源时获取，新鲜缓存和离线报告继续可用。团队状态展示当前占用。
- 升级无需手工寻找候选工件和逐个校验，明确显示新版目录与回退步骤；没有启动时后台检查或自动执行下载文件。
- 保留0.3.0的 JD 人工复核、来源观测历史、团队权限/同步及所有原采集、材料、报告和 CLI。

## 验证结果

本地必要定向验证覆盖：两个独立客户端的真实 HTTP 争用、到期接管、旧代次拒绝、权限撤销、v1→v2原子迁移与额度保留、服务不可用时的新鲜缓存报告；升级摘要/来源错误、外部地址、危险 ZIP、失败清理、旧文件保留；稳定发行必须完整上传再公开。首次租约夹具两项断言修正及实际结果保留在 PR，不抹去失败。

实际 Edge 界面检查覆盖默认离线、显式检查、确认下载、390px页面、失败后重试与原数据保留；使用人工构造发行字节，不执行夹具程序，不冒称公网下载或干净机器验收。最终 CI、准确提交、真实公开 Tag/Release 与匿名资产验证在对应 PR/Issue 和 Release 正文记录，避免用开发阶段通过代替最终发布证据。

## 剩余问题

Windows 包仍未签名；自动替换/重启和其他系统包未完成。升级服务控制库后，旧0.3.0服务不能读取v2，须保留新版中央服务及完整备份，详见[团队迁移](TEAM_SERVICE.md)。租约不能撤回已经在途的请求；高级/登录采集本轮仍只保留既有共享配额，不冒称全部接入跨设备任务所有权。

未提供生产主机/域名，尚无公网部署；人工JD金标准、真实本人材料、干净Windows、新手、正常账号三站完整JD以及持续运行仍需各自现场条件。这些 Issue 继续开放，不能因工程或稳定渠道发布而算作已认证。另见[升级步骤](UPDATES.md)及[发行流程](PORTABLE_RELEASE.md)。
