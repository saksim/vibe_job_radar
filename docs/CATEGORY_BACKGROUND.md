# 关闭网页后完成当前分类批次

开始或继续猎聘公开分类采集后，本机工作台负责完成已经确认的当前批次。网页显示进度，可以关闭或刷新；重新打开原工作台即可查看正在执行的任务。工作台应用需要保持运行。

打开页面时，采集表单等待本地配置、入口预设和后台状态读取完成后才允许填写。这样较慢的加载不会覆盖已经填写的预算或执行确认，也不会在后台状态尚未知时开始另一任务。加载失败会保留提示，可刷新重新读取。

本批最多一个已确认的分类页和1～5个已选正文，完成后生成原报告并停止。原名单下一批、相邻页和等待恢复任务使用同一执行方式，但仍需按各自入口明确选择，不在后台自动扩充范围或等待到期重试。URL、Brave搜索和授权数据源暂保留原页面连续执行方式。

点击“暂停连续执行”后，正在进行的请求先结束并保存，随后不再执行下一步。暂停期间刷新网页仍能看到结果；点击“继续所选任务”只处理剩余步骤。退出应用也会停止后续步骤，重启不自动继续。请求结果未知时保留原尝试及预算，原恢复逻辑将其标为未知中断，不重放该请求。

同一工作区通过操作系统所有权隔离执行。另一工作台可以查看进度，不能接管、覆盖检查点或通过原单步/CLI同时执行。应用退出等待结束时若原请求仍存活，所有权会继续保留到它真正退出；进程终止由操作系统释放，不靠PID或锁文件存在推断。状态读写共用原有短记录锁，网络请求不占用该锁。

开始时绑定原批次检查点和网络策略，每步校验条件。许可、任务字段或网络策略变化后停止后续访问；现有分类/分页祖先和恢复原文校验继续有效。使用默认Collector与同一工作区持久账本，成功缓存、拒绝、冷却和预算口径不变。

Issue #172 跟踪。实际浏览器验收使用人工上游、默认工厂和临时真实账本，覆盖关闭页、重新打开、暂停与刷新后的续接；原版对照在关页后停留于一条成功/一条待执行。Windows助手另验证实际程序后台分发遵守原冷却、零招聘请求及新进程保留结果。各提交的回归、浏览器和冻结程序资格以对应PR为准。这不认证真实账号、长期无人值守、跨日期或正常关键词入口。
