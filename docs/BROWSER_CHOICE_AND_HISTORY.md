# 已安装但仍崩溃：不再循环重装

## 当前 Chrome 与检查模式

工作台现可明确选择配套 Chromium、本机 Edge 或本机 Chrome。第1步分别提供默认浏览器桥和原生实验检查；后者验证实际可见空白页、拒绝未许可请求、零外连和退出清理。只有该项当前检查通过才保存选择，历史记录标明检查模式；第2步仍需选择本任务的后端。

仅明确选择Chrome的原生实验使用继承管道控制和独立临时资料目录；Edge与配套Chromium保留原SDK路径。Chrome定位固定应用安装位置，不读取日常浏览器的标签页、表单、Cookie或配置。未安装或启动失败不会安装系统浏览器、自动改用其他通道或改变网络设置。

本机Chrome156的SDK首次启动失败、Chrome原生组件和表单通过的范围见[本机Chrome的两种采集检查](INSTALLED_CHROME_NATIVE.md)。该文档记录当前迁移与测试边界；旧分支的通过项不是当前源码的资格。实站账号登录、滑块、短信、完整JD和报告仍单独验收，堆损坏底层原因尚未确认。

## 历史输入与边界
用户从 Playwright 1.57 更新到 1.63 后仍收到 `0xC0000374`。包安装成功、浏览器文件存在不代表进程能正常工作；该 Windows 状态说明堆损坏异常，但不能单凭异常码定位哪个模块负责。需要本机 Application Error 事件的故障模块/版本进一步定位，不建议重复卸载、关闭系统防护或修改 DNS。

开始时“尚未运行安装”是进程内 `_last_install` 的初始值，并非检测出未安装。以前这个提示以“安装状态”展示，容易造成重复重装。本次将它明确改为本次组件操作记录，独立展示当前检查结果。

## 使用本机 Edge（必须用户主动选择）
在向导第 1 步展开“重下载或更新后仍崩溃？选择本机已安装的浏览器”，选择本机 Microsoft Edge，点“检查并使用所选浏览器”。只有当前实际有界面空白页检查成功并保存后，原采集任务才使用这个选择。缺少 Edge 或启动被系统/组织拒绝时停止，不安装、不覆盖、不静默退回其他浏览器。政策限制必须由管理员审核，不能通过修改策略绕过。

这是 Playwright 官方 `msedge` 稳定通道，沿用原 Python 采集后端、域名/HTTPS/robots/TLS/方法与限频保护；不接管日常浏览器标签页，不使用个人 profile 或复制 Cookie。登录仍在独立采集会话完成；默认退出后不保留，用户明确启用本机 Cookie 会话保存时遵循独立的保存与到期规则。

现有采集会话必须先停止才能更换，不会擅自结束它。原安装/重下载/更新按钮仅管理配套 Chromium，不负责安装系统 Edge。默认仍用配套 Chromium；没有自动失败后换浏览器的逻辑。当前 API 只接受 bundled/msedge/chrome、明确布尔同意及可选的 bridge/native 检查模式，不接受任意路径、命令或其他通道。

## 重启后的显示
工作区 `browser-choice.json` 只保存选择和一次最小检查历史：时间、通道、检查模式、SDK 版本、状态码、退出码和解释器路径的不可逆摘要。不存路径原文、日志、账号、正文或 Cookie。

历史启动成功不能作为新进程的 ready；重启仍需检查，但不再丢掉上次失败记录让用户误认为“从未安装”。文件损坏、未知格式或符号链接不被当作缺省选择；不会悄悄切换。新选择未能保存时不宣称成功。个人数据、限频和旧报告不迁移、不删除。

## 用户当前原生故障仍未被证明修复
Edge 在受控环境成功不能证明用户电脑也成功；它是一个明确授权的可选运行路径，不是堆损坏的根因结论。若两种浏览器都失败，请在事件查看器“Windows 日志→应用程序”找刚才的 Application Error（通常 ID 1000），只记录异常码、故障应用/模块名称与版本、Windows 版本。不要发送完整转储、账号或 Cookie；模块显示 ntdll.dll 也不足以断言系统 DLL 损坏，不从第三方网站替换 DLL。

## 验证与继承问题
新回归验证选择的明确同意、启动成功才保存、旧会话保护、拒绝不自动回退、原网络后端接线、重启历史和无安装副作用。独立 Windows Edge 工作流实际检查有界面采集后端与原工作台 UI，不下载系统浏览器、不访问招聘页面。

从 main@db6beee 开始。PR39 合并时遗留的桌面修复验收脚本使用字符串求值等待，被应用的内容安全策略（CSP）拒绝；已观察到 Windows 1.57 和 Linux 当前版本失败，不能归因为只影响旧 SDK。本 PR 的 CI 修订改为 Playwright 定位器文本断言并保留原等待条件和超时；同时明确验证应用仍返回只允许同源脚本、未开启 unsafe-eval 的策略。窄屏尺寸检查使用函数形式，不改变被测页面。保留原所有工作流、系统/SDK 矩阵和断言，不调整生产 CSP 或浏览器安全选项。各工作流是否通过以本次新提交的实际运行结果为准，不能沿用旧提交的绿灯；CI 修复也不代表用户本机堆损坏已经解决。
