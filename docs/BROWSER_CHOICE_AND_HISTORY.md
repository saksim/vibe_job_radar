# 已安装但仍崩溃：不再循环重装

## 2026-09-26：Chrome 与原生实验检查

可明确选择本机 Google Chrome（`chrome`），继续使用独立临时资料目录。Windows/macOS/Linux 原生启动只定位固定应用安装位置；未安装时报所选通道缺失，不安装、不改用另一个浏览器。安装和更新按钮仍只管理配套 Chromium。

第1步提供两个明确检查按钮：普通按钮检查默认浏览器桥；“原生实验：检查并使用所选浏览器”使用真实 NativeBackend 验证可见空白页、拒绝未许可请求、零外连和完整清理，成功才保存选择。后者对应第2步的原生实验，不认证默认浏览器桥；历史记录保留检查模式，旧历史按默认桥显示。正在使用的采集窗口仍须先正常停止，原任务和共享配额保持。

本机实际 Chrome156 对照：日常 Chrome 可以登录（用户反馈）；SDK 控制的 headless 和 headed 启动均出现0xC0000374，原生CDP的10项本地密码表单和实际NativeBackend可见启动/请求拦截/清理检查通过。没有关闭防护或改变系统策略，不能据此确定堆损坏根因，也不代表招聘站真实登录通过。具体测试终态以当前PR记录为准。

公开支持的浏览器通道依据：[Playwright 浏览器文档](https://playwright.dev/python/docs/browsers#google-chrome--microsoft-edge)。原生模式沿用项目独立控制器和原网络契约；本改动不开放新的站点接口、不读取日常 Chrome 的 Cookie 或帐号资料。

## 历史输入与边界
用户从 Playwright 1.57 更新到 1.63 后仍收到 `0xC0000374`。包安装成功、浏览器文件存在不代表进程能正常工作；该 Windows 状态说明堆损坏异常，但不能单凭异常码定位哪个模块负责。需要本机 Application Error 事件的故障模块/版本进一步定位，不建议重复卸载、关闭系统防护或修改 DNS。

开始时“尚未运行安装”是进程内 `_last_install` 的初始值，并非检测出未安装。以前这个提示以“安装状态”展示，容易造成重复重装。本次将它明确改为本次组件操作记录，独立展示当前检查结果。

## 使用本机 Edge（必须用户主动选择）
在向导第 1 步展开“重下载或更新后仍崩溃？选择本机已安装的浏览器”，选择本机 Microsoft Edge，点“检查并使用所选浏览器”。只有当前实际有界面空白页检查成功并保存后，原采集任务才使用这个选择。缺少 Edge 或启动被系统/组织拒绝时停止，不安装、不覆盖、不静默退回其他浏览器。政策限制必须由管理员审核，不能通过修改策略绕过。

这是 Playwright 官方 `msedge` 稳定通道，沿用原 Python 采集后端、域名/HTTPS/robots/TLS/方法与限频保护；不接管日常浏览器标签页，不使用个人 profile 或复制 Cookie。登录仍在独立采集会话完成，退出后不保留。

现有采集会话必须先停止才能更换，不会擅自结束它。原安装/重下载/更新按钮仅管理配套 Chromium，不负责安装系统 Edge。默认仍用配套 Chromium；没有自动失败后换浏览器的逻辑。原版 API 只接受 bundled/msedge 和明确布尔同意（当前另支持 chrome 及明确的原生实验检查），不接受任意路径、命令或其他通道。

## 重启后的显示
工作区 `browser-choice.json` 只保存选择和一次最小检查历史：时间、通道、SDK 版本、状态码、退出码和解释器路径的不可逆摘要。不存路径原文、日志、账号、正文或 Cookie。

历史启动成功不能作为新进程的 ready；重启仍需检查，但不再丢掉上次失败记录让用户误认为“从未安装”。文件损坏、未知格式或符号链接不被当作缺省选择；不会悄悄切换。新选择未能保存时不宣称成功。个人数据、限频和旧报告不迁移、不删除。

## 用户当前原生故障仍未被证明修复
Edge 在受控环境成功不能证明用户电脑也成功；它是一个明确授权的可选运行路径，不是堆损坏的根因结论。若两种浏览器都失败，请在事件查看器“Windows 日志→应用程序”找刚才的 Application Error（通常 ID 1000），只记录异常码、故障应用/模块名称与版本、Windows 版本。不要发送完整转储、账号或 Cookie；模块显示 ntdll.dll 也不足以断言系统 DLL 损坏，不从第三方网站替换 DLL。
