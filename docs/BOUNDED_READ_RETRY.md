# 有限主文档重试

Refs #79 / #9 R2。本改动依赖 #74 的原采集会话所有权保护，单独提交后续PR供审查；未合并不等于main已交付。

仅 `backend.open` 主动打开的非认证主文档GET，且返回地址与本次目标完全一致、状态为502/503/504，才产生可重试错误。`open`结束即清除资格；分页点击、浏览器自发刷新、iframe、robots、XHR/POST、登录和其他错误不会获得这一资格。每次重开仍经过原适配器、robots、DNS/TLS、请求头、发布方节奏及页/请求配额。

每任务最多安排两次自动重试，退避分别5–7.5秒与10–15秒，使用有界随机抖动。有效Retry-After和已存在的更长冷却只会延长时间；歧义、无效或超过366天的Retry-After停止自动请求。共享SQLite冷却使其他任务、重启和明确继续也不能提前发送；429的原至少5分钟冷却不变。

任务保存 `read_retry` 版本、已安排次数和最后状态。先扣预算再排队，崩溃可能消耗一个未发送的名额，不会赠送额外重试；成功、暂停、关闭、重启或明确继续均不补回。旧任务无字段时从0开始，未知/损坏字段在启动浏览器前拒绝。此计数只约束自动重试，用户核实后仍可明确继续；每次明确动作仍受共享冷却及配额限制。

计时动作只使用原任务仍活着、非认证且错误一致的后端。关闭窗口、替换后端或后续致命错误会取消自动恢复，保留选择、已保存正文、原报告与等待时间。重启后没有浏览器身份，只能由明确继续或正常登录恢复。采集等待期间先生成已有成功条目的部分报告，失败次数耗尽也能核对逐条结果。

字段只增不删，沿用现有任务JSON和冷却表，无数据库schema迁移。回退先停止服务并备份工作区；旧源码可能忽略重试计数，不能跨版本宣称同一自动重试上限仍被执行，原持久冷却仍有效。

本项不是通用网络重放器，也不是实站认证。未知发送结果、TLS/DNS错误、验证码、401/403、其他5xx、密码提交等仍停止。#63页面空白、真实完整JD/登录、跨日期样本、长期调度和跨设备账户配额仍开放。实际测试与精确head CI结果记在PR，人工夹具不得冒充真实平台样本。
