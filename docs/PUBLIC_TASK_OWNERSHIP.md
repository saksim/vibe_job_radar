# 同工作区公开任务所有权

跟踪 #89/#102，承接 #68/#30 H4/#9 R3-R4。核心所有权已由PR69合并，本次PR88整合原PR90的调度接线与PR103的公平状态锁；准确提交验收见对应PR，不代表跨设备配额完成。

## 问题与修复

旧代码只知道本实例的线程。两个工作台同时使用同一工作区时，第二实例会把第一项仍运行的任务误标为中断，并接受新任务覆盖 `public_tasks/state.json`。人工复现中第二次来源请求被已有工作区锁阻止，所以不能把问题说成底层锁失效；真实缺陷是任务状态、提交、取消和恢复的所有权错位。

现在公开任务提交前取得 OS 文件锁，直到后台任务完成并保存终态才释放。锁被占用时返回 `public_task_busy`/HTTP 409，不修改任务ID、不覆盖原记录、不启动第二线程。进程退出时 OS 释放锁，不通过 PID 或锁文件年龄猜测是否存活。

另一个工作台仍能读当前任务和最终报告，但运行时显示“另一个本机服务正在执行”，隐藏不能控制的停止/继续按钮，禁用重复提交。关闭这个查看进度的实例不会取消真正所有者的任务。需要停止时回到原工作台；所有者取消后，其他实例可以明确确认继续同一个已保存查询。

真正进程退出后，上次运行记录成为可确认的中断；不会自动联网。恢复在取得所有权后再次读取磁盘记录，阻止旧页面在竞争窗口恢复已被替换的任务。原 ID、查询、绑定、尝试次数、缓存与来源配额保持。线程创建或初始写入失败也释放锁，未启动的线程不会在服务关闭时被错误 join。

状态读写共用一个短期文件锁，避免 Windows 读取句柄阻止原子替换；短锁最多等待5秒，长期所有权锁始终不阻塞。只读返回的所有权/控制标记不写入原任务文件。

快照必须在同一短锁内观察所有者并读取记录。否则，在“无所有者”的观察之后、读取记录之前，另一实例可能发布新任务，导致页面把仍运行的任务短暂误报为中断。现在新所有者发布状态前必须等本次读取完成，观察到的是一致的旧状态或新任务；后续真实恢复仍需取得所有权并重新核对记录。此补修不更改配额、JSON格式或联网行为。

同一进程内的短元数据操作按工作区规范路径公平排队，队首仍须取得原OS锁。原#100 Windows/Python3.10的60次写入/60次观察曾超时；当时缺少锁持有时长证据，不能诊断所有系统I/O或跨进程超时。排队防止同进程写入越过已等待的观察者；超时/异常移除票据，不增加5秒上限，不串行不同工作区。跨进程争用仍可能有界失败。

## 与每日计划配合

到期计划遇到其他实例的公开任务时等待。提交前竞争中的明确busy表示未创建任务或发出请求，因此撤回本次执行标记并继续等待。调度交接遇到仍被拥有的匹配任务时等待结果，不误判进程退出；后续按原ID对账保存报告。

另一实例可以停用未来计划，但不能取消其他实例拥有的当前任务。原调度所有者读取停用状态后协作停止自己的任务；关闭中的服务完成当前只读步骤和保存后退出，原报告与缓存保留。

## 实际验证

纳入13项所有权测试（含两项调度等待/交接），并有6项公平锁测试覆盖排队、异常释放、超时票据清理、路径隔离和实际OS争用。核心测试覆盖双实例状态、重复提交与取消、旧ID竞争、缓存续接、删除旧记录、写入/线程失败清理及并发读取与原子保存。真实独立 Python 进程验证所有权阻止重复提交、正常完成报告，以及不走正常清理的进程退出；退出后需明确恢复，原限频账本仍保留两次实际尝试。

其中新增的快照回归使用真实线程和OS记录锁协调启动窗口，不依赖随机睡眠。相同用例在补修前的PR90与后续PR228源码均失败于`interrupted != idle`，补修后通过；原任务完成、报告保持、第二实例的恢复被拒绝及零额外来源请求同时验证。这个复现证实短暂状态误报，不代表实际任务接管或数据丢失。

`python scripts/run_public_owner_browser.py` 用实际 Edge/Chromium 和两个本机 HTTP 服务验证：其他实例的按钮/进度、直接重复请求409且原记录不变、原工作台取消、另一实例确认续接、原缓存生成报告、关闭查看实例不影响所有者、390px和两份报告保留。上游是人工目录，外部浏览器请求为零，不是实站认证。

新所有权脚本进入原浏览器CI；当前候选的运行结果按其准确源码单独记录，原PR90的测试成绩不能代替本次整合验收。

## 兼容与未完成范围

新增的 `public_tasks/owner/.writer.lock` 仅是 OS 锁载体；旧岗位、报告、缓存、配额与任务 JSON 格式保持。升级或回退前先停止任务和计划，再关闭所有使用该工作区的服务并备份。旧源码不使用此所有权锁，因此不能同时混用旧/新服务并宣称互斥有效。

本功能只覆盖同一设备、同一工作区的新版本公开任务。高级采集/引导浏览器保留各自现有规则；跨工作区或设备的全局账户配额、多人权限、独立持久队列、开机自启和三站现场登录认证仍开放。
