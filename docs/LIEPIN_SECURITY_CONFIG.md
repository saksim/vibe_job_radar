## 配置域名不存在时的页面行为

2026-10-10 在已升级的实际工作台，原生 Chrome 空白页与拦截健康检查通过；原网络策略对上述配置主机的解析返回 encrypted_dns_name_not_found。读取同一 SHA256 官方脚本发现：配置读取失败后脚本继续使用内置目录并执行自己的安全检查。v4 却在导航之前预取全部来源的 robots，因此将这一依赖失败扩大为整页终止。这是当前预检查行为的修复，不证明历史 about:blank 的根因，也不认证实站登录。

v5 只为该精确匿名 GET 读取声明网站能够处理域名不存在。使用同一工作区网络策略、解析器与取消机制做 DNS 检查；只有明确的 encrypted_dns_name_not_found 可以留下“本次导航不可访问”的来源记录。该来源不会获得 robots 许可，也不会发送任何目标 HTTP。浏览器随后请求精确配置时收到 NameNotResolved，页面自行处理失败；不伪造配置、改脚本、改检测条件或宣称验证成功。每次新导航重新检查，避免把先前失败永久保留。

其他 DNS/TLS/代理失败、取消、策略撤销、robots 不允许或不可读，以及网站401/403/429仍停止。正常解析时仍读取真实 robots 并执行原请求配额与响应检查。配置失败自身不能生成岗位、空结果或报告。

离线负对照在 v4 上复现导航被提前终止。受控浏览器验收增加一个合成域名不存在场景：该域名零 HTTP，浏览器执行合成页面自有的失败处理，之后仍需实际测试服务器的搜索响应、完整正文和所属报告。已有配置成功和403场景继续保留；不执行第三方安全脚本或访问招聘网站。
