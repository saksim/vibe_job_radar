# 0.19.0：应用用例与报告生命周期解耦

本轮对应 #511，由 #57 总控跟踪，支持 #316/#317/#319 的工程能力，真实材料与净机验收仍独立保留。

## 解决了什么

- 业务命令与操作互斥移入应用层，可在没有页面或 HTTP 监听器的情况下调用；原路由、同步 API、CLI 和桌面能力保留。
- 报告列表、文件和读取独立于当前岗位库。已有证据不会因无关岗位库异常而无法读取、导出或返回保存结果；原库错误仍在实际读取时报告。
- 普通分析和个人报告具备显式后台任务、持久状态与报告引用，关闭页面后继续；重开只观察，中断不自动重放。
- 队列页面丢弃早于最新操作的响应，避免旧状态覆盖已保存变更。README 已同步后台采集和正式镜像拉取说明。

## 提高了什么

页面、HTTP 协议、应用用例、报告存储与任务执行各有明确职责，服务器和桌面复用同一业务入口。报告写入保持原互斥、所有权、证据版本与落盘契约，观察不必等待长写请求结束。

## 验证结果

本文件记录实施范围；具体定向验证、准确 main CI、晋升 PR、正式 Tag 和 Docker 双原生架构匿名验收结果以本版 Release 和 #511 的实际回执为准，未执行或失败项不当作通过。不覆盖已发布 0.18.0 资产。

## 剩余问题

原18项的真实站点/完整 JD/人工标注/本人项目/普通净机/生产环境条件保持。#183/#263/#269/#436 历史因果仍待证据，不能用本轮通过代替。#210/#320 严格只读。无可信签名凭据，桌面发行仍如实标示 unsigned / unnotarized。

仍为单拥有者、单工作区、单进程的模块化单体；没有新增多租户、微服务、无限报告调度或招聘登录接管。生产主机、域名、HTTPS 和真实备份恢复另行验收，部署见 [Docker](DOCKER.md)，模块边界见 [架构](ARCHITECTURE.md)。
