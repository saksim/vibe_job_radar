# 0.15.1：保留 JD 原文并正确处理隐藏模板

关联 #431 / #432 / #434 / #55 / #56 / #315 / #316 / #57。

## 解决了什么

- #431：HTML 已解码出的 DOM 正文不再被当作 HTML 解析第二次。`std::vector<T>`、`Map<String, Integer>`、字面的 `<script>` 和转义实体能够完整进入原报告及人工复核包。
- #432：现有 BOSS/51job DOM 路径沿用浏览器已经取得的可见页面文本，避免隐藏登录弹窗触发第二次误拒绝。离线解析、标题和正文选择统一排除明确隐藏或惰性的元素及其子树，避免隐藏标题、重复正文容器和模板内容污染结果。
- #434：完整回归后的本地安装校验使用前置已准备的构建工具并禁止索引访问，避免再次联网下载构建依赖；保留实际安装入口、版本和 UI 资源检查。

## 提高了什么

原文的技术要求和引用位置得到保留，复核人员不会因解析器删掉类型参数而看到错误材料。正常完整 JD 不再因为 HTML 中明确隐藏的登录模板而失败。

只排除能够从 HTML 属性、内联样式或惰性标签确认的隐藏内容。外部 CSS 的页面级登录判断使用已有浏览器可见文本；离线快照不猜测 CSS。仍拒绝可见登录/验证码、正文内的登录占位、歧义标题/容器、未展开全文及岗位身份不一致。`aria-hidden` 单独存在不作为视觉隐藏证据。JSON-LD、原导入/报告/复核、其他采集器、网络、服务、升级功能保留。

历史数据库和报告不会自动改写。重新导入原始 HTML 可产生保留原文的新结果；旧报告继续作为当时证据。

## 验证结果

在 0.15.0 基线上新增 10 个合成测试，负对照出现 4 个失败和 24 个子场景错误，复现原文丢失、隐藏提示误拒绝及隐藏候选混入。修复后一次定向运行 121 项全部通过（3.305 秒），包括 HTML 导入→数据库→原报告→复核包、DOM 完整性/身份、可见页面判断、猎聘既有布局和结构化地址。复核包仍为 0 个人工确认，没有把合成夹具记作真实 JD 或真人标注。

不重复本机全套测试。保留 feature 与准确 main 的必需 CI；相同代码树的中间晋升去重取消单列。最终 PR、CI、正式 Tag、公开附件校验由 #57 和 Release 发布记录补齐，不能提前算通过。

首个 feature 的 macOS 实际通过全部 3389 项（298.847 秒）、demo 和源码 doctor，随后本地安装步骤重新下载构建依赖时无法解析 `files.pythonhosted.org`，该任务失败。#434 将声明的构建工具并入前置依赖步骤，之后用 `--no-build-isolation --no-index` 进行本地安装；不提高超时、不减少矩阵或断言、不增加自动重试。原失败日志保留，不将它解释成产品测试失败，也不据此改变其他历史网络问题的未知结论。
