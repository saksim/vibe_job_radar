# 正常登录跳转后的稳定观察

对应 #130，取原 #127 的独立登录观察修复，基于 main@1aec5cd2。本次只处理已确认的 URL 在一次 DOM 读取过程中改变：旧代码拒绝混合快照后把已获用户确认的等待也取消，导致正常登录返回详情仍停在需要处理。

现在用专门的 PageSnapshotChanged 标记这一个可识别事件，丢弃已有稳定签名，在原期限和频率内等待两次新的稳定观察。列表仍须符合原查询，详情仍须匹配已选职位、完整正文及执行前第三次检查。普通 page_not_ready、网络拒绝、密码错误仍需处理；关闭浏览器、停止、超时和更换所有者原规则保留。没有新增导航、登录或网络重试。

开发验收沿用现有真实浏览器与人工来源入口：自动采集在正常登录后读取 DOM 时改变一个适配器认可的跟踪参数，强制产生这个竞态；原有登录 POST1、第二条详情 GET3、第一条正文/旧报告保留和新报告两条正文断言全部保留。该注入仅在验收的 HumanBackend 中，生产逻辑不修改网页。验收失败在关闭前保存既有阶段、脚本行号、登录动作 HTTP 状态、固定人工路径计数和共享诊断器限制到24帧的函数事实；不记录账号、Cookie、DOM、任意异常正文或线程局部变量。

PR239 首次 CI 的自动接续失败（page_not_ready / needs_attention）及原工件永久保留，单凭该状态仍不能断言所有历史失败都是此原因。当前主干对照、本机 Edge 人工来源、准确候选和真正主干首次 CI 分别记录在 PR。真实招聘账号、滑块/短信和实站全文验收不由人工来源替代。PR240当时仅收口登录观察修复；#126的测试清理与旧等待超时原因分别跟踪。

后续#126测试清理候选基于已验收main/e068415a，复用原#127的独立回归：创建临时目录后立即登记删除回调，创建服务后立即登记关闭回调，保证setUp失败也按LIFO先退出工作线程、释放会话所有权，再删除目录。旧测试只在tearDown关闭，而准备失败不会调用tearDown。原5秒等待与所有既有行为断言保持；仅接入现有共享诊断器，输出白名单阶段与最多24帧函数事实，不记录输入、DOM、任意异常正文或线程局部变量。

新增两项受控测试分别注入准备失败验证清理顺序，以及在同一个5秒截止时验证诊断事实/隐私；原实现失败与修复通过必须分别保存。CI离线矩阵启用已有--progress选项，各测试与作业时限不变。生产src、现有浏览器验收、原报告及Windows打包逻辑不改。原PR123首次Windows准备超时的根因仍未知；本修复不能追溯解释全部#126/#23历史等待，真实招聘账号和实站全文仍另验。
