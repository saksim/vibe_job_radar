# 正常登录跳转中的自动接续

Refs #130 / #126 / #127 / #9 / #50 / #51。

已明确选择“登录后自动接续”时，程序只观察原浏览器的当前页面。正常登录跳转期间，浏览器可能在读取URL与正文之间改变地址；这时不能把旧地址与新正文拼成有效岗位。此前快照正确拒绝这种混合观察，但接续管理器把它当作需要人工处理的错误，终止已确认的等待，即使登录请求和返回完整详情均已成功。

现在快照使用独立的`PageSnapshotChanged`类型标记已观察到的地址变化，界面错误码仍为`page_not_ready`。接续管理器丢弃该次观察以及上一候选签名，继续原等待；必须重新取得两次稳定、匹配原查询或原所选详情的观察，详情仍在原工作线程第三次核对后才进入报告。原等待截止时间和观察间隔不变，不发起新的导航、登录或请求重试。

普通`page_not_ready`、HTTP/权限/限流错误、浏览器关闭、拒绝密码和无法分类的异常仍需处理；仅明确的快照地址变化可继续观察。停止、换任务/浏览器及原截止时间仍终止等待。该改动适用于使用同一快照实现的桥接/原生后端，不代表三站实站认证。

实际本机Edge验收捕获到：登录动作HTTP200、正常POST一次、详情GET三次、无首页绕行，但接续状态为`needs_attention/page_not_ready`。CI首次失败只保存了AssertionError，不能追溯断言它一定由同一原因造成。新脚本在人工供应方页面的真实DOM读取期间改变已知跟踪参数，确定性检验此类竞态；页面与网络均为人工夹具，未修改真实招聘站点。旧管理器与修复版对照、原请求数、部分报告和首条记录保留结果见Issue/PR。

同时修复登录详情测试fixture的失败清理：服务和临时目录创建后立即登记清理回调，准备失败也先关闭工作线程、释放锁再移除目录。单测原5秒时限、浏览器脚本原30秒等待保持；失败保存固定阶段、脚本行号、人工请求计数、任务状态与最多24个函数帧，不输出异常正文、完整路径、DOM、Cookie或局部变量。原Windows单测准备超时的最初根因由#126继续追踪。
