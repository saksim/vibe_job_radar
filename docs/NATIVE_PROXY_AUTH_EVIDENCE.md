# 原生认证代理验收的失败现场

Refs #238 / #23 / #237。真正主干1aec5cd2首次19/20：七组各1709项全0，Windows无界面的认证代理验收在HTTP正常/拒绝通过后，于socks5-normal读取人工robots时返回ERR_PROXY_CONNECTION_FAILED。原生14场景、人工猎聘14场景和有限读取重试2场景此前已通过。原日志及工件10940839060保留，未重跑该工作流。

旧结果的source_requests始终为初始化值0，finally只留下failed，缺少关闭前转发器状态。这是已确定的验收记录缺陷；尚不足以确定那一次SOCKS5连接为什么失败，也不能归因于SQLite修复。

本次仅修改开发验收：保留最后活动协议/正常或拒绝阶段，按人工来源记录的实际长度更新总请求数；最多四个阶段各保存12项有限连接事实，包括转发器线程、关闭状态、连接/活动套接字数、固定错误码，以及上游握手/认证/连接和当前阶段来源计数。首个失败在关闭前保存动作、固定异常类型/代码和事实快照，后续清理或最终检查点不能覆盖它。没有保存凭据、请求头、URL、任意异常正文、对象repr或线程局部变量。

原认证拒绝、目标不收凭据、一次拒绝尝试和正常完整人工JD断言保持；生产源码、夹具及网络等待、CI限时和认证策略不变，记录失败时仍执行原关闭。只有临时CI运行真正的原生代理流程，个人设备不运行该脚本的CA信任步骤。

同一组三个受控回归中，原验收入口1失败，修改后全部通过。入口测试显式替换CA、浏览器和连接，并禁止子进程/网络；它证明实际失败路径的计数与关闭前记录，不冒充原CI连接错误复现。其余回归检查敏感占位值不泄漏、未知字段收敛、首次失败和最后阶段保留。

候选和实际主干仍需新的首次完整CI，四个原生工件还要逐一核对HTTP/SOCKS5结果、四个阶段事实、真实来源计数和拒绝场景零目标请求。即使通过，原瞬时连接错误根因仍由#23追踪；本Issue仅收口已复现的证据缺口。
