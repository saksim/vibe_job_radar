# 明确配置的本机代理认证（#75 / N5）

0.6.0 另外提供[工作台内配置与 Windows 加密保存](WORKSPACE_PROXY_CREDENTIALS.md)。以下环境变量方式继续可用；后文“不落盘”描述仅适用于环境变量凭据，不是新方式的存储契约。两种方式不能混用，工作区已有入口不会接收环境中的其他凭据。

本分支为显式指定的 loopback HTTP CONNECT 和 SOCKS5 增加可选用户名/密码认证。已有匿名本机代理和系统静态发现保持原行为；URL 中的 `user:password@` 仍拒绝。此交付不包括 socks5h、代理DNS、PAC、远程/VM代理入口，也不证明 #63 的猎聘空白页由代理导致或已经解决。

## 配置与恢复

在启动工作台的本机进程环境中设置以下字段。程序不会替用户保存或修改系统环境；不要在聊天、日志、命令历史、启动脚本或版本库中写真实密码。

| 字段 | 用途 |
|---|---|
| `VIBE_RADAR_HTTP_PROXY` | 明确的 `http://127.0.0.1:端口` 或 `http://[::1]:端口`，支持 localhost |
| `VIBE_RADAR_SOCKS_PROXY` | 明确的 `socks5://127.0.0.1:端口` 或 `socks5://[::1]:端口`，与HTTP字段二选一 |
| `VIBE_RADAR_PROXY_USERNAME` | 独立的代理用户名 |
| `VIBE_RADAR_PROXY_PASSWORD` | 独立的代理密码，不能使用招聘账号密码代替 |

两个凭据变量都未设置时使用原匿名方式；提供凭据时两者都须非空，各1–255个可打印ASCII字符（空格允许，不会被修剪），用户名不能含冒号。密码可含冒号。暂不推测非ASCII编码、认证挑战或系统凭据库。没有显式应用代理时，凭据配置会报错，不能被自动发现的代理或 NO_PROXY 接走。

Python/PowerShell等进程仍会在内存中持有凭据；本功能不声称清除运行时所有内存副本。应用不把它们写入工作区、报告、状态API、日志或浏览器导航参数。协议只向用户指定的本机端口交付认证，目标网站只收到原有业务请求。

修改代理凭据后关闭原采集窗口并明确继续，建立新的策略会话。HTTP407、SOCKS认证拒绝或认证方式变更会停止；不会降为匿名或改走直连。原生浏览器可能同时发起多个CONNECT，因此认证握手在连接代理时串行；一次拒绝或结果不明会阻止同一原生会话后续握手再次发送凭据，关闭原会话后才能重新尝试。

## 会话与隐私契约

代理地址、DNS公共目标校验、原域名SNI/TLS和同一工作区配额保持。HTTP凭据只放在到指定代理的CONNECT头中；SOCKS凭据只放在版本1的用户名/密码子协商中，不出现在目标TLS内的HTTP头。原生浏览器连接应用自有隧道时使用另一组临时凭据，不能将上游代理密码给网站认证挑战。

进程内仍用带随机进程密钥的HMAC绑定凭据变化，公开策略ID保持原格式，每次启动不同；不会把稳定的密码哈希放入公开ID。**Windows下明确启用本机Cookie保留时，相同代理凭据现在可以跨进程恢复v2快照**。每次启动仍须提供当前代理凭据；完整工作区/平台/适配版本/后端/浏览器/网络上下文与凭据共同派生仅内存中的DPAPI附加熵。持久文件不保存凭据、派生校验值或进程密钥，加密载荷只有Cookie和保存时间。其他网络变化仍拒绝恢复，原生运行中凭据变化仍停止旧会话。

旧认证代理v1快照不自动迁移到v2，Linux/macOS仍使用原owner-only v1，认证代理跨进程绑定不兼容的限制也保留。匿名v1格式和公开策略ID保持兼容。读取或自动覆盖/删除前都会验证已有快照；错误凭据、损坏或不匹配不会被到期清理、空Cookie保存或域名过滤掩盖。明确清除本平台快照仍可执行，随后正常登录才能建立新的快照。详见[本机会话恢复](SAVED_SESSION_D04.md)。

Windows解密失败无法可靠区分“代理密码变化”“原Windows账号不匹配”和“文件损坏”。提示先核对原账号、代理凭据及网络配置，不自动换身份或重试。Cookie恢复仍只标记为未验证；真实平台仍可能要求短信、滑块等本人操作。

这是loopback代理认证；HTTP Basic和RFC1929自身不会加密本机握手。只能配置自己信任的本机监听端口。网站侧的TLS仍验证真实目标域名，没有证书忽略、代理解析或私人目标例外。

协议依据：[RFC7617 HTTP Basic](https://www.rfc-editor.org/rfc/rfc7617.html)、[RFC1929 SOCKS5用户名/密码](https://www.rfc-editor.org/rfc/rfc1929.html)。为避免Basic未协商字符集的互操作问题，本实现限定ASCII；SOCKS仍只发送经验证的数字公网地址。

## 验证与回退

`test_proxy_auth` 使用人工凭据、真实本机HTTP/SOCKS代理和TLS服务器验证成功、拒绝、分段回复、截止时间、并发原生CONNECT、配置隔离与凭据不进入站点。`scripts/run_proxy_auth_browser.py` 使用实际Chromium/Edge验证桥接请求。它的CA只注入测试HTTP客户端，不修改系统证书。Windows附加检查把实际浏览器导出的人工Cookie保存后交给独立Python进程通过真实DPAPI恢复，再验证新浏览器的首个文档请求携带Cookie；POSIX检查仍明确拒绝认证代理跨进程v1。此流程没有真人账号登录。

新测试 test_authenticated_saved_session 覆盖真实进程互斥、Windows DPAPI恢复、POSIX限制、错误凭据/绑定/元数据/载荷、旧格式、自动写入与显式清除。配额测试保留真实动作顺序：普通搜索在恢复失败时尚未预留访问，显式登录仍先计次，恢复失败也不退款。

`scripts/run_native_proxy_auth.py --controlled` 仅在临时CI运行器上执行原生浏览器测试，复用已有临时CA清理机制；非CI调用在安装证书前退出。实际平台请求为零，这些测试不替代用户VPN/代理产品的现场验收或真实招聘登录。

工作区的公开配置格式未变；Windows认证代理的私有Cookie快照使用v2。回退前停止服务；若要舍弃v2快照，用当前版本明确清除该平台会话，避免让不识别v2的旧程序写入它。原匿名/POSIX v1仍受支持。不要靠回退、清空频次库或改变身份绕过来源拒绝。
