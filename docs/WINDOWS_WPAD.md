# Windows WPAD：先发现，再确认来源（#23/N6）

在首页、引导采集页和高级采集页的“网络自动适配”中，选择“发现并确认 Windows WPAD”。只有勾选发现许可并点击按钮，才调用 Windows 的 DHCP/DNS 自动发现。查看状态、已有 PAC 许可、定时任务的策略说明和打开页面都不会触发发现。

发现成功只显示站点与完整地址摘要，隐藏路径和参数。网络提供的地址不表示可信：需要再次勾选信任说明并确认。预览只存在当前工作台内存中，5 分钟过期，绑定工作区和偏好修订号；取消、重新发现、设置变化或工作台重启后必须重新核对。API 不接收用户提供的 URL。保存不会下载或执行脚本；它授权该完整地址现在和后续提供的脚本。若需固定脚本版本，请使用原有文件导入功能。

发现通过官方 [WinHttpDetectAutoProxyConfigUrl](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpdetectautoproxyconfigurl)，使用 DHCP 和 DNS_A 两个标志，优先 DHCP。该接口仅返回地址；返回的内存用 GlobalFree 释放。应用不修改代理、注册表、DNS 或网络接口。发现放在自有 spawn 工作进程中，父进程从启动前计时，8 秒内接受结果，最多两个并发工作进程；超时或许可失效则回收子进程和管道。同步启动和清理仍受系统调度影响，因此整个调用不承诺严格在 8 秒内返回。

## 会话和撤销

schema v5 仅保存完整来源地址的 SHA256 与新的许可标识；不保存地址、下载脚本、账号或 Cookie。每个新会话第一次使用网络时重新发现，地址摘要必须与已确认来源一致；不同则停止，不能下载新地址的脚本或自动改用直连。随后复用已配置系统 PAC 的有界 HTTP(S) 下载器，每会话只下载一次并冻结脚本，也缓存失败。不是每个网页资源都重新探测。并发域名请求等待同一次初始化，等待预算覆盖发现和下载两段合计 16 秒，期间仍可撤销；两段各自的 8 秒期限没有增加。

会话内不持续发现或监测网络变化。换网后必须停止并重开会话；同一工作台明确发现了不同来源，会阻止旧快照继续使用。跨进程已冻结会话不能知道另一个进程内存中的新预览，仍会在持久许可变更、新会话核对或取消时停止。不要把冻结脚本宣称为实时网络监控。

脚本只接收 HTTPS 根地址与域名；执行、代理返回解析、目标公网 IP、TLS、robots、频次账本仍用原策略。下载不提交认证/Cookie，不跟随跳转，不绕过 TLS，仅接受有界 UTF-8 内容。返回路线仅支持 DIRECT、匿名本机 HTTP CONNECT 和明确 SOCKS5；远程/认证代理、路径分流和代理 DNS 仍未实现。

选择上方“自动发现”并保存可以撤销 WPAD 许可，恢复为 schema v2。旧会话在后续发现、下载、求值、缓存使用和新连接前检查许可；已有连接不承诺强制断开。关闭工作台会取消其发现与 WPAD 快照。DNS 单独保存保留已确认来源，重新确认来源会产生新的许可，旧会话失效。原 PAC 文件和业务数据不删除。

仅识别 v1–v4 的旧版本会拒绝 v5，不能静默直连。回退前须用本版本切换到自动或固定模式并保存 v2，再使用旧版本。其他系统拒绝 WPAD 使用，仍允许离线撤销。

## 验证范围与剩余验收

自动化覆盖原生 ABI 参数和内存释放、真实 spawn 字节管道、期限和回收、两次许可、过期与修订冲突、工作区隔离、原子保存失败、来源变化、失败缓存、关闭和撤销。真实浏览器验证三页共享设置、确认、检查、取消、回退和窄屏布局；PAC 下载是实际自有子进程，Windows 使用实际 PAC 引擎。

临时 Windows CI 的完整人工列表/JD 路径使用受控发现来源，随后执行真实 Edge → PAC → HTTP/SOCKS5 → TLS，并验证代理拒绝后没有直连。人工发现替身不会被记为实际 DHCP/DNS 成功。个人设备不做真实 LAN WPAD、不安装测试 CA或更改网络设置。

真实 Windows DHCP/DNS 服务发现、企业来源/网络切换和便携 exe 的实际 WPAD 成功仍待现场证据。本次实现不关闭 #23/N6，也不证明三站账号登录、完整真实 JD 或旧 CI 故障根因。当前提交的首次 CI、实际 main 与原数据升级证据以 PR/Issue 记录为准。
