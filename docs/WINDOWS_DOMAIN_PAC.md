# Windows 本地 PAC：明确导入，按域名选择路线

Issue #109 承接 #23/N6；本分支待审，不计为 main 已交付功能。默认关闭，支持 Windows 提供的 WinHTTP 异步 PAC 接口。它没有自动发现 WPAD、下载系统 PAC、改变系统代理或套用日常浏览器扩展。

在首页、引导采集或高级采集的“网络自动适配”中选择可信 `.pac`/`.js` 文件，阅读说明、勾选许可，再导入。文件必须是非空 UTF-8、最多 64KiB；导入和查看状态不会执行脚本。“检查脚本”只对内置 `pac-check.invalid` 域名显式求值，不连接返回的代理或目标，不等于招聘站点已通过。选择上方“自动发现”或固定代理并保存即可撤销 PAC；已有连接不被强行中断。

脚本收到规范的 `https://域名/` 与域名，没有原职位路径、搜索词、查询参数、Cookie、密码或个人材料。PAC 原生 DNS 函数仍可能解析域名，不能把执行脚本说成完全离线。每个会话对每个域名求值一次，包括错误结果；最多保留 128 个域名。时间、网络接口等动态脚本需停止并重开会话后重新求值，路径分流不在本版范围。

返回字符串最多 96 个 ASCII 字符、至多 4 项。完整检查所有项，只采用第一项；不会在第一项连接失败后推进到 DIRECT 或下一代理。支持：

- `DIRECT`：采用当前系统路线，仍执行目标公网地址与原主机 TLS 校验。
- `PROXY 127.0.0.1:端口`：匿名本机 HTTP CONNECT；也接受 localhost 和有效 IPv6 loopback。
- `SOCKS5 127.0.0.1:端口`：明确版本的匿名本机 SOCKS5，连接已验证的数字公网地址。

不猜测 `SOCKS` 的版本，不接受 SOCKS4、socks5h、HTTPS 代理、认证、远程或宿主机地址，也不忽略未知项。`UNKNOWN ...; DIRECT` 整体失败；`PROXY ...; DIRECT` 的代理失败后停止。例子是语法说明，不是可直接照填的本机代理配置。

HTTP、公开数据、高级采集、浏览器请求桥及原生 CONNECT 隧道使用同一 NetworkPolicy。加密解析沿用目标已经选定的路线，不因解析商域名而重新选 PAC 路线。目标公网地址固定、TLS、robots、频次库和登录许可保持原约束；返回 DIRECT 不会绕过这些检查。

## 原生接口的返回值与进程边界

本机人工探针发现，旧同步 `WinHttpGetProxyForUrl` 会把 SOCKS/SOCKS5 结果归成 DIRECT；异步接口也会删除未知指令，并将 SOCKS5 解析成 SOCKS 与带 `5 ` 的主机。因此不能直接把原生结果当作原脚本返回值。

实现用一个封装函数保存原始 ASCII 返回，将其编码成带随机标识的惰性 `.invalid` 主机元数据，由应用解码后严格解析。这个编码主机从不被解析或连接；它只用于完整保留原返回值与顺序，并不是针对恶意 PAC 的新安全沙箱。只应导入用户信任的脚本。

采用官方[异步 WinHttpGetProxyForUrlEx](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpgetproxyforurlex)，而非 Python 执行 JS。Windows 的 PAC 引擎在进程外运行；另建应用自有短命工作进程，在 8 秒父进程期限内等待，最多两个并行求值。关闭原生 resolver 取消操作，超时/撤销终止自有工作进程，失败不换路线。PAC 副本仅由临时 loopback HTTP 入口提供，随机 128 位路径、严格 Host/路径、无认证、无 WPAD、无系统 PAC 下载；原生自动认证关闭。

输入只有冻结脚本和规范根 URL，进程回传最多 4096 字节 JSON，不使用反序列化对象通道。原生错误转为固定代码，不回显源文件、路径、代理密码或原异常。WinHTTP 本身[限制 PAC 中的 ActiveX 对象](https://learn.microsoft.com/en-us/windows/win32/winhttp/autoproxy-issues-in-winhttp)；本应用仍不将任意脚本视为可信代码。

## 保存、撤销和回退

工作区 `network-pac/<sha256>.js` 保存内容绑定副本；偏好 schema v3 保存文件显示名、摘要和每次导入新生成的许可标识。先原子写副本，再原子写偏好，失败至多留下未启用副本。其他工作区和系统设置不改变。DNS 单独保存保留 PAC 许可，重新导入即使内容相同也会撤销旧会话许可。

每次求值/缓存使用及新建连接前重新确认许可、文件内容及应用代理凭据冲突。旧脚本缺失或被修改停止联网，但页面仍可切换自动模式。已有会话不会偷偷采用另一脚本；每日查询计划的策略绑定改变后仍需重新确认。

只支持 v1/v2 的旧源码会拒绝 v3，不能静默将 PAC 工作区直连。回退前用新版本选择自动或固定模式，确认保存为 v2；若回退目标连 v2 都不支持，再按原[工作区回退说明](WORKSPACE_COMPATIBILITY.md)处理。撤销保留已导入文件用于核对，不删除私人数据或配额库。

## 验证范围

测试覆盖原始返回保真/未知协议、长度/域名、超时/撤销、缓存与并发、偏好冲突/回退、零隐式求值、原始报告数据不被创建，以及受控 HTTP/SOCKS5→每客户端测试 CA→TLS 请求。Windows 原生求值使用自写脚本；真实 Edge 操作导入/三页面重载/显式检查/撤销，390px 无横向溢出。非 Windows UI CI 只替换求值接口，不能作为原生引擎证据。

Windows 临时 CI 另执行真实 Edge→原生 PAC→HTTP/SOCKS5→临时 TLS 列表/完整人工 JD，以及实际便携 exe 的冻结子进程检查。个人设备不安装测试 CA。完整回归、精确提交 CI 和便携证据以 PR 当前记录为准；未通过的项目不沿用旧提交绿灯。

真实 PAC/VPN/企业网络现场、系统 PAC 自动消费、其他系统、全路径规则、代理DNS，以及中国三站正常登录→完整 JD 仍开放。本机人工夹具不替代这些验收。
