# 原生控制层：减少页面运行时事件采集

关联 #63 / #49 / #50，基于已验 PR195 的源码候选。此变更仍需独立检查和实站验收，不能算作正常关键词搜索或账号登录已经打通。

## 已观察到的问题

2026-09-25 的本机离线对照使用 Edge 153.0.4234.48 和此前保存、字节未改动的公开脚本。普通 Edge、仅启用标准自动化标识的 Edge、仅启用 CDP Page 导航的 Edge 均保持页面正常；相同启动条件增加 `Runtime.enable` 后约3.68秒转为 `about:blank`。普通 Playwright 和微软官方 WebDriver 也复现清空。完整条件、阴性结果和结论边界见 [Issue63 的实验记录](https://github.com/saksim/vibe_job_radar/issues/63#issuecomment-5829546119)。这些实验没有请求招聘站、使用账号、解锁或修改原脚本，也不能证明全部历史实站失败同因。

本机 Playwright 页面初始化会无条件订阅 Runtime 事件。应用删除 console 回调并不能取消底层订阅。新的 native 控制层只执行工作流需要的 DOM 读取、标准 Input 输入和页面导航，不订阅整页控制台对象。`navigator.webdriver` 保留，站点脚本和 console 方法保持，现有 VibeJobRadar 网络标识继续由原请求控制器设置。

## 实现边界

- 默认 HTTP bridge 仍使用原 Playwright 后端。显式 native 选择使用本候选的控制器；失败不自动切换路线。
- 只启动应用专属进程、全新临时 profile 和隔离 context。控制通道使用父子进程继承的匿名管道，不开放调试TCP端口；不连接日常 Edge、读取其 profile 或导出账号。协议内容不写日志。
- 复用当前Playwright发行包已有的Node可执行文件；小型桥接脚本只转换管道消息分隔符，不修改SDK或过滤站点脚本，没有新增安装依赖。单消息8MB、接收队列16帧、同步待答命令32个，操作只在所有者线程执行。站点网络继续经过原 NativeTunnel 和已选择的网络策略。
- 原 Fetch 请求/响应检查、robots、共享配额、逐跳校验、业务关联、401/403/429、取消、TLS验证和会话同意逻辑继续使用 NativeBackend。DOM/Input 层不发送或拼造站点业务API。
- 每份原生文档在保留发布方所有 CSP 的同时追加限制：同页表单与脚本可执行；弹窗、frame、worker和WebSocket保持不支持。文档解码正文保持，限制在执行脚本之前交付；robots仍是不可执行的控制数据。HTTP/HTTPS的 `connect-src` 不匹配 WS/WSS，依据 [CSP scheme 匹配](https://www.w3.org/TR/CSP3/#match-schemes)。
- 正常表单点击与输入采用浏览器 Input 事件。字段内容不进入诊断；Cookie仍由浏览器保存。导出保持原 SameSite默认和分区Cookie排除规则，不扩大持久保存范围。
- 实际主页面清空仍是失败，旧结果仍会清除。没有吞掉错误、重试被拒绝的登录、修改保护逻辑或改变完整JD标准。

此处的小型 DOM 接口只覆盖已审查适配器的 selector、可见性、输入、点击和分页需求，不承诺替代整个 Playwright API。新控制器也没有扩大站点契约、开放BOSS/51job原生采集或解决默认带参数搜索入口的访问规则问题。

## 验证

本机已完成无网站导航的真实 Edge 启动检查：原控制器成功绑定主页面/临时页面、DOM读取、标准文本输入/按钮点击、自动化标识及专属profile清理通过。独立的离线原型还验证了表单→HttpOnly会话→搜索→自建正文、拒绝未知写请求及403停止；这不是本候选完整TLS/CORS资格。

把原公开脚本放入实际新后端的自建页面后，首个完整观察因脚本上报请求不属于测试域名而以`resource_domain_blocked`停止。该失败保留；随后独立的只读观察保持后端原错误与halted状态，记录可见页面约10.06秒未清空、输入和Cookie形状可读、实际发送0请求。它只补充页面行为证据，不能算作可用的采集流程；没有删除该请求校验或把错误改为成功。

单测覆盖控制事件归属、嵌套命令、不必要订阅拒绝、协议内容脱敏、线程所有权、消息限制、管道分帧/断开、页面退休及Cookie兼容。原 Linux/Windows、headless/headed 的真实浏览器人工TLS、CORS、认证代理、分页、保存和报告检查继续执行，不能用单测或该离线原型替代。当前提交的实际成绩以对应PR为准，不预写未来通过数。

PR196 的早期CI暴露了启动和输入兼容性问题，原工件与每次提交的结果均保留在PR记录中。控制器恢复旧启动器对Linux、固定试验配置和后台组件扩展的参数；本机配套Chromium的空白未知目标后来变为内部工具栏，恢复配置后即可启动，无需放宽未知目标规则。点击先等待绘制并核对命中位置，随后等待其引起的新文档，不把输入确认当成导航完成、不重复表单提交。延迟400ms的自建表单已验证点击在新DOMContentLoaded后返回，带原限制CSP仍可正常提交；最终TLS/CORS资格仍以同提交CI为准。
