# 明确使用 AI 的长句要求

默认规则补充一种明确的候选人能力表述：句首要求具备使用、运用、驾驭或借助 AI/语言模型的能力，同一条中明确说明能够在代码生成、编写、重构、审查或评审环节使用。模型知识和适用范围的说明可以位于中间，不再仅依赖旧规则中模型名称到编码词的16字符距离。

新模式分别限制中间说明与编码行为前后的长度，并服从原句、独立义务、否定和编号边界；它不拼接不同要求，不识别所有表达方式。句首主体限定避免把“开发一个具备这些能力的产品”算作候选人使用工具；公司、福利、歧义与摘要仍沿用原处理。“代码评审”与已有“代码审查”归入同一能力。

普通 GPT、Claude 或 LLM 名称不会因此进入专用编码工具实战列表。否定和不要求条款仍按原极性呈现；规则接受不等于人工审核，更不等于用户本人具备能力。原文、字符位置和已有要求ID保持，新能力行使用原ID规则。

变更位于原默认规则配置。用户显式替换 `direct_patterns` 时仍以用户配置为准；每份报告保存自己的 `effective_config.json` 和摘要。重新分析会生成独立报告，不改旧报告、原采集时间或既有个人证据。旧报告复核仍使用旧快照，不能把重新提取记作新岗位或新采集日期。
