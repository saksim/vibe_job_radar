# 已有配额库打开不再申请初始化写锁

Refs #227、#210/G06、#126。本项修复原 RateLedger.__init__ 在完整库上仍无条件 BEGIN IMMEDIATE 的依赖，不把它认定为所有 Windows 慢测试的根因。

## 已复现的行为

在同一个已有人工配额的临时库上重新打开五次，原实现执行五次写事务、四十条幂等建表/索引语句、五次提交，数据库字节完全不变。另一个真实 SQLite 连接持有保留写事务时，原 summary 正常可读，而构造器在 300ms 观察期内等待；释放写事务后才完成。该实证只说明不必要的写锁依赖，没有模拟招聘请求，也不是 CI 600 秒现场复现。

## 修改与兼容范围

构造器在原连接检查后，用一次 SELECT 对照本版本八项表/索引定义。只有完整且定义完全一致才直接结束；不缓存就绪结果，不写版本号或另设持久标记。SQLite 的记录会去掉 IF NOT EXISTS，对照保留其余原定义。

缺项、旧结构或未识别的定义继续执行原 BEGIN IMMEDIATE、原幂等语句和一次提交。两个初始化者同时看到旧结构时，仍由原写锁和 IF NOT EXISTS 串行完成；初始化途中失败仍回滚并关闭连接。这不是对任意数据库的完整性认证，未识别结构不会被重新建库或自动清空。

只读检查仍遵守 SQLite 的锁规则；排他写入或实际 I/O 阻塞期间不承诺无等待。

实际 reserve、set_publisher、defer/cool 的写事务和提交不变；不改 SQLite 日志/同步设置、连接等待、配额、冷却、时钟保护或发布方窗口。新建对象遇到不存在的文件仍按原契约初始化；已有对象操作时文件被删除仍报错，不把它当作新额度。

## 验证边界

新增回归使用真实临时 SQLite 文件，覆盖同进程/另一真实进程持有写锁时的打开、新建与旧结构、缺失索引、未识别定义、初始化失败回滚、并发新建扣减、持续配额/发布方窗口/时钟保护及原删除/损坏/符号链接拒绝。完整库重复打开用 SQL 轨迹与字节/数据快照同时核对，实际写入必须仍提交。

这些检查不申请登录、访问站点、重置用户账本或升级工作台。#126 中 pipeline.as_completed / fsync 等历史等待与本项分开记录；后续 CI 通过也不自动证明那些根因已解决。
