# 猎聘真实验收的本机观测账本（D08 / #54）

这份工具保存正常浏览器采集的预登记范围，并在本机离线核对证据，不会主动访问招聘平台。工具的结果仍为 `not_live_verified`，真实账号、运行环境和逐条人工核对需分别完成。公开路径已有四日期/91个不同完整URL的历史记录，见[取数证据](CURRENT_ACQUISITION_EVIDENCE.md)；这些独立报告不替代正常登录搜索的认证，也不代表已完成真人全文审核。

## 先登记范围，再开始正常取数

使用已经提交、没有未提交改动的源码和已存在的独立业务工作区。工具保存源码提交、源码文件哈希、猎聘适配器版本、检索词、岗位方向、搜索条件、选取规则、时区，以及声明的浏览器版本和网络模式。不要把账号、密码、Cookie 或私人 JD 填入命令。

Windows 通常没有系统 IANA 时区库，先安装可选依赖：`python -m pip install ".[acceptance]"`。[Python zoneinfo 文档](https://docs.python.org/3/library/zoneinfo.html) 说明了系统时区库和 `tzdata` 的加载顺序。时区缺失时会拒绝登记，不默认为 UTC。

示例中的路径、浏览器版本、网络模式、时区和选择规则应改成实际值：

```powershell
python scripts/check_live_acceptance.py --workspace D:/radar-acceptance plan --keyword "时间序列算法" --role time_series --backend native --selection-rule "在预先选定的检索条件下按列表顺序保留全部选中项和失败项" --timezone Asia/Shanghai --browser msedge --browser-version unknown --network-mode system --yes
```

浏览器声明 `--browser` 接受 `msedge`、`bundled` 或 `chrome`，应与实际采集时的选择一致；登记本身不会启动或验证浏览器。

可重复传 `--role`；有地区等筛选时传对应 `--search-url`。只接受猎聘搜索页和与 `--keyword` 一致的检索词，查询字段不得重复。登记后返回 `plan_id`。`--yes` 仅确认本机保存这些范围字段，不能代替平台访问范围确认。

随后在同一工作区正常创建向导任务。任务必须晚于计划，平台、关键词、岗位方向、搜索 URL 与后端必须完全一致。计划里的浏览器、OS、网络模式仍是登记者声明；新任务另行记录实际采集进程与浏览器会话的观测，复核时对比原计划。

## 保存整批观测，离线复核

等待任务完成或暂停后运行：

```powershell
python scripts/check_live_acceptance.py --workspace D:/radar-acceptance capture --plan <plan_id>
python scripts/check_live_acceptance.py --workspace D:/radar-acceptance verify --plan <plan_id>
```

占位的 `<plan_id>` 必须替换。计划早于数据是必要条件，不能在看到结果后登记并把旧成功任务充作预先选择的样本。其他查询和计划前任务记为排除，不纳入该计划。正在运行、缺失卡片、重复选择或观测期间改变的任务会使本次保存失败，不截断困难项。

每次保存包含同一范围下的全部已选条目，失败、未完成和 robots 拒绝均保留。重复保存不增加分母；后续取消选择不会抹掉此前记录的失败；观察到的状态变化另行统计。新版本的逐次详情记录还能保留两次观测之间的失败和重试，旧检查点缺失的历史不能重建。这里的比例仍以**观测到的选中条目为分母，不是全部 HTTP 尝试数**。

## 逐次正文处理记录（#140）

新任务在原检查点中保存 `detail_attempt_history`。每次选择发生变化时保留选中 ID；每次正文处理前先原子保存开始标记，完成后保存结果、记录 ID、UTC 时间和单调时钟耗时。失败后成功、拒绝后取消选择都不能抹掉前次记录。原 `guided_acquisition.json` 报告带有生成当时的历史，后续报告不改写旧报告。

`detail_attempts` 单独统计服务执行过的详情处理，重复 `capture` 不增加次数。耗时包含正文处理期间的等待、页面读取、解析及正文入库，不包含登录等待、报告生成或最后检查点写盘；从已经登录返回的当前页读取也单独记录为 `login_returned_detail`，不会为计数再请求该页。它不代表 HTTP 数量、纯网络延迟、许可证明或完整目标岗位数，不能拿 `ok` 尝试数替代原报告的目标筛选和全文核对。

没有结束记录的尝试为 `unfinished`，结果和耗时未知，重启后保留，不补写成功或估算耗时。旧任务标 `legacy_partial`；若回退旧程序更新了检查点而没有同步记录，新版本同样标出历史缺口。该检查点标记用于发现普通版本回退，不是防伪签名。

每任务最多500次详情处理、200次选择变化；到达上限会停止新处理，保留已有记录，不滚动删除失败或重置额度。记录损坏、已观测的开始被删除或完成结果被改写时，离线账本拒绝追加。当前选择之前已选但未进入正文处理的岗位仍显示在选择分母中；`recorded_selections_without_detail_start` 仅表示缺少对应开始记录，旧任务不能据此推断从未请求过。

成功项必须同时匹配原任务、原报告、原报告文件哈希和原数据库中的该次入库观测。检查岗位身份、标题与正文哈希、解析版本、来源、完整正文级别及本批目标岗位筛选。手工导入、摘要、合成数据、报告未选入的岗位和正文错配均不计入。核对过程只读业务数据库与报告；SQLite 仍可能创建 WAL/SHM 协调文件，保留这些机制才能正确读取尚在 WAL 中的已提交观测，不能为隐藏文件变化而忽略它们。

不同岗位按站点身份去重，同一岗位跨日期重取不增加不同岗位数。日期来自原报告的采集时间并换算为登记的 IANA 时区，不取保存账本的日期。计划前、任务前和未来的采集时间均拒绝。

退出码：`0` 为成功登记计划；`1` 为输入/证据损坏或状态不一致；`2` 为复核仍有证据缺口。当前 `capture`/`verify` 正常也返回 `2`，调用脚本应读取 JSON 中的 `gaps`，不能把它误报为程序崩溃。

## 实际采集环境与旧记录

正常工作台在导入采集服务前记录本次进程的源码快照、Python/Playwright/系统版本和启动时间。源码模式保存原字节指纹及独立的文本换行归一指纹；Git HEAD 是当时读到的修订，不单独证明磁盘没有改动。新计划使用 schema 2 同时保留两种指纹；schema 1 原计划继续按原字节指纹核对。登记允许根目录续接笔记和 TEMP，仍拒绝资格源码中的未提交修改和未跟踪文件，包括被 Git 忽略的源码。

便携程序读取构建时的源码清单并核对正在执行的 exe 哈希；这是本机未签名的构建关联，不是发行签名或抵抗恶意修改的证明。安装为普通库、较晚导入工作台、缺少清单或已更改的源码均明确显示未知/变化，不把当前磁盘内容补作旧进程的证明。

acquisition_environment_history 保存每次服务动作的浏览器实际版本、所选通道、适配器、进程及所属浏览器会话编号、原后端绑定的网络策略。复用同一浏览器仍保留原会话编号；重新启动产生新编号。记录不包含命令行、机器名、路径、账号、代理地址、凭据、Cookie、PAC 脚本或原始页面。每任务最多200次环境观测，到达上限保留历史并停止新访问。

每次详情开始与其环境观测一起进入原检查点。失败和未完成的尝试同样保留；detail_attempt_history 的原版本和计数口径不变。guided_acquisition.json 保存报告生成时的环境副本，原文件哈希继续覆盖它；离线账本拒绝缺失、改写或不能关联原尝试的副本，不以重启后环境覆盖旧报告。

runtime_environments 显示有记录的动作、已绑定及与计划源码/浏览器匹配的详情次数，并明确列出差异。旧任务、旧版本继续写入造成的缺口、第三方后端以及缺失的运行信息仍为未知。没有开始详情的选择项继续留在原分母里，不补造环境记录或成功状态。

所记网络事实是后端已经绑定的代理/DNS/PAC配置，读取时不执行网络请求或PAC求值。物理VPN/TUN路线、每次动态PAC决策、实际账号有效性与网站许可仍需独立证据；配置相同不等于这些现场条件已验证。

## 当前尚不能证明的事

即使计数达到30个不同完整目标岗位、3个本地日期和建议90%比例，也不会自动认证或修改默认后端。现场许可、搜索/登录/HTTP的完整尝试分母、逐请求成本及延迟、实际物理网络路线、旧数据缺失的运行绑定、逐条人工身份/标题/全文复核、会话恢复与冷却证据均需补齐。新记录补服务层逐次处理、实测耗时及当时观测到的进程/浏览器/网络配置。90%是 #54 的建议值，尚待用户核准。

`verified_full_target_items` 只表示保存的本机材料通过一致性检查，无法从元数据证明正文在现实中完整、页面未混入推荐或本地材料未被人为重造。单测使用明确标识的人工岗位和人工日期，只验证计数与拒绝行为，绝不作为现场验收成绩。

## 保存、隐私与回退

文件位于工作区 `.radar-acceptance/<plan_id>/`。追加的 `capture-NNNN.json` 保存条目状态、ID、哈希和时间，不复制 JD 正文；原文继续留在原报告。哈希链和尾指针可检测常见缺失、变化或未完成写入，但不是数字签名，也不能防止有本机写权限的人重造整套历史。

计划含关键词和环境声明，应与原工作区一起本机备份。不要公开整个目录；若移除原报告或入库观测，再次核对会失去相应证据。源码候选包拒绝源目录内的账本，Git 默认忽略该目录。当前最多200个任务/200次观测，超过上限明确报错，不静默丢数据。

停止使用或回退旧源码不会改变已有岗位、会话、频次与报告。保留账本及工作区备份；旧代码不理解逐次记录，回退后继续采集会形成历史缺口，重新升级时明确标出，不能声称覆盖这段执行。没有采集默认、定时访问或认证状态需要回滚。

运行环境比较中的网络模式只表示已绑定配置：direct/system对应system_route（未配置显式代理），static_http对应HTTP代理，static_socks5对应SOCKS5代理，包含明确的本机或VM宿主机入口。它不证明实际物理直连、VPN/TUN或逐请求PAC/绕过结果；声明unknown保持不可比较。某个字段未知时，其他已知源码、浏览器、适配器或网络差异仍分别报告，不把未知当成匹配。

计划的浏览器版本为unknown时，不能将实际版本计为匹配。新CLI将planner_os保存为system/release，能直接与运行时核对，包含Darwin内核版本。旧planner_os仍与实际系统家族及可比较的release核对；Linux计划在Windows运行或同系统release不同会列出差异。无法解析的声明、未声明版本，以及macOS营销版本与Darwin内核版本之间无法直接比较的情况保持缺口，不推定匹配。
