# 猎聘短信登录、人工验证和原任务接续（候选）

关联 [#50](https://github.com/saksim/vibe_job_radar/issues/50) 与 [#49](https://github.com/saksim/vibe_job_radar/issues/49)。本轮基于 v0.20.3，属于候选改动，尚未完成真实账号到完整 JD、报告与重启复用的验收，不能当作正式版本已支持的承诺。

## 使用流程

1. 在浏览器采集向导保留原猎聘任务。需要人工登录时，勾选“本次登录返回原列表或所选岗位详情后自动继续”，再打开登录浏览器。
2. 默认 HTTP 桥的标准关键词任务进入猎聘官方独立登录页，返回地址固定为本站搜索入口。手机号、短信、平台协议和图形验证均在程序独立浏览器的官方页面由用户完成。程序不代收短信、不自动点击发送验证码或接受协议。
3. 短信框、扫码页和腾讯验证框可见时，任务持续等待人工处理，不把背后的匿名列表当成登录成功。二次短信验证页的 ticket、表单值和验证码不进入页面快照或诊断。
4. 回到原搜索入口后，连续两次稳定观察和执行前复核通过，程序才用页面原有搜索框提交原关键词；返回原列表或所选完整详情时，沿用既有接续。任务 ID、选岗进度、页数/岗位数上限、正文及报告引擎保持。等待最长 10 分钟；挑战出现不延长期限，停止或错误会撤销自动接续。
5. 只有原先明确选择“本机保留 Cookie 会话”才保存程序自己的 Cookie。Windows 使用当前用户 DPAPI；其他桌面系统沿用文件权限保护。快照最多 7 天，恢复仍需正常页面验证。失效会回到人工登录，不自动发短信或重复登录；不读取日常 Chrome/Edge 的登录资料。

未启用自动接续时，仍可使用原来的读取列表、重新搜索和继续按钮。原密码登录、其他平台、手工导入、公开来源和报告入口保留。原生网络实验的 `liepin_search_login_v5` 契约没有扩大；本项验证码子框架支持只用于默认 HTTP 桥。

## 请求与正文边界

新增规则仅允许观察到的官网短信、二维码、二次验证、协议记录操作，以及腾讯验证码 SDK、指定子框架、图片和验证请求。站点页面自己构造请求，桥接一次原样转发。人工验证码子框架必须属于当前猎聘页面，不能成为新的主页面；不生成挑战答案或伪造成功响应。

官网独立登录页为 `https://www.liepin.com/login`，正常返回参数指向本站 `/zhaopin/`。采集仍检查实际网络文档的 robots：禁止的带查询参数文档不会因为开启本功能而放行。标准检索使用查询参数为空的搜索入口和其页面原生表单；只接受同一页面、同一关键词和当前请求序列的业务响应。重载、换页或新检索立即淘汰旧结果。显式地区等额外筛选保留原入口校验，不擅自删掉条件。

桥接补齐官网安全脚本读取的 `dalisi4api.tongdao.cn/static/cfg/v2.json`，范围与已有原生规则相同：精确 HTTPS 主机/路径、GET、XHR/Fetch，先检查 robots并计入原配额。只对该依赖的名称不存在错误把原始失败交还官网已有处理逻辑；不伪造配置。TLS、过期 DNS、其他通信失败、拒绝和冷却继续停止。

猎聘人工登录期间，普通图片的连接失败保留为可选资源失败，不再单独中止人工等待；仍中止该图片请求，不返回伪造资源或重试。验证码依赖、脚本、DNS、TLS 与公网地址校验不适用此例外。这个局部修正不代表真实跳白已解决。

页面从已加载的 HTTPS 主文档跳到 `about:blank` 时，淘汰旧结果并报告页面已清空；不回退跳转或修改官网安全脚本。之前已有网络失败时保留原原因。空白页、摘要及没有正文的任务不会生成成功报告。原有 DNS 时效、代理、证书、公网地址、共享请求与登录频次限制不变。

## 空白页离线对照（2026-10-28）

为区分表单/短信与浏览器控制方式，在自建测试页中加载上述 SHA-256 完全一致的公开安全脚本。全部 HTTP 由本地夹具响应或中止，没有真实账号、短信或平台请求；脚本及其默认配置保持原样，配置依赖按真实失败路径中止，不伪造成功配置。每个独立窗口只做一次有界观察，原任务和现场浏览器未动。

| 测试条件 | 结果 |
| --- | --- |
| 程序默认桥，Edge 无界面，自建页面不加载该脚本 | 观察期内不跳白 |
| 程序默认桥，Edge 无界面，加载原样脚本 | 页面提交后约 3 秒跳白，浏览器报告 `scriptInitiated` |
| 最小 Playwright，Edge 无界面，加载原样脚本 | 同样约 3 秒由脚本跳白，不依赖项目的请求桥 |
| 程序默认桥，Edge 有界面，不加载该脚本 | 观察期内不跳白 |
| 程序默认桥，Edge 有界面，加载原样脚本 | 同样约 3 秒由脚本跳白 |

公开搜索页 HTML 直接引用该脚本；本次取得的独立登录 HTML 没有直接引用。这与用户观察到的表单可见、返回搜索页后跳白相符，但离线自建页不等同于完整实站，实际登录错误原因也没有因此得到确认。

项目已有 `CDPBrowser` 控制层另以 Edge 做了离线检查，有/无界面均在页面创建阶段失败，尚未加载测试页。一次补充诊断定位在 `Page.enable`，返回 `browser_closed`；不能把这当作该替代方案已可用，也没有修改现场后端、浏览器身份或官网脚本。原始证据分别在忽略目录的 `offline-blank-comparison*.json`、`offline-existing-control-comparison.json` 和 `offline-existing-control-diagnostic.json`。

候选诊断现被动记录空白跳转的浏览器原因（脚本、HTML 刷新、HTTP 刷新或未知），只有同一主文档实际提交到空白时才报告；已取消的计划、其他标签和子框架不混入。未知值脱敏，不增加浏览器控制命令。66 项相关回归通过；真实 Edge 离线复现中新增字段正确记录 `scriptInitiated`。这项诊断改动不是阻止跳转的修复，当前现场服务尚未重启加载。

接下来先解决受控浏览器兼容性，并通过无账号页面稳定加载/搜索的验证；之后再进行一次有明确目的的人工短信登录，以及同一任务完整 JD、报告、重启会话复用。若该接入方式最终不可兼容，需要另行实现正常浏览器中的人工接管与当前页面交接，不能把反复收码作为替代方案已完成的证据。

## 验证与现场限制

346 项定向回归通过，覆盖正常短信转发一次、严格请求范围、验证码子框架、拒绝与限额、原关键词和页面身份、手工交接时限、保存会话和过期恢复，以及密码登录原功能。安全配置和空白页回归先复现 5 处失败，再修改实现。随后普通图片连接失败的回归先复现 1 处失败，修正后相关 60 项通过（包括 3 项新增测试，与前述组有重叠，不合计为独立总数）。

`python scripts/verify_liepin_sms_login.py --channel msedge` 使用真实 Edge 和生产服务/桥接，但所有站点 HTTP、账号、短信和挑战均由本地夹具提供。它验证人工步骤后同一任务取得完整合成 JD 与报告，重启先恢复 Cookie 再读取，以及失效后不重新登录或编造报告。它不证明真实短信能送达、真实验证码可用或真实账号登录已成功。现有 `verify_password_form.py --channel msedge` 的 17 项检查通过，外部账号未测试。新验收已接入 Linux 浏览器和 Windows Chrome 的原 CI；本机结果不能替代未运行的远端 CI。

现场仍有以下未完成项，进度同步到 #50：

- 用户日常 Chrome 可打开搜索页和独立短信登录表单；程序专用 Edge 改为官网独立登录入口后，用户截图也确认了完整表单。
- 用户在原 Edge 窗口尝试短信登录，确认收到一条短信，页面提示验证码错误或过期，随后跳空白。用户说明因点击后没有反馈而多次点击，不确定收到的短信对应哪次点击。脱敏记录包含一次发送短信请求和两次登录提交；两次提交分别在短信接口响应后约 21 秒、39 秒，HTTP 状态均为 200。这些状态不证明业务登录成功，也不足以认定验证码过期、输入错误或程序重复提交。
- 未再发送短信、重新打开登录或关闭浏览器，沿用当前上下文尝试一次原任务搜索，仍短暂显示后跳到 `about:blank`。任务进入 `waiting_manual / native_page_cleared`，自动接续关闭；认证为 `manual_pending`，保存会话为空，没有实际 JD 或本批报告。用户确认再次跳白后已停止实站重试。
- 程序 Edge 可通过启动检查，但真实搜索入口曾先显示再转到 `about:blank`。静态资源请求曾出现 `encrypted_dns_expired_answer`，后一次出现 `encrypted_dns_unavailable` 及其冷却。安全配置缺失已补齐，但其真实请求仍可能受上述 DNS 失败影响。
- 程序专用 Chrome 在空白页启动阶段返回 `browser_native_heap_corruption` / `0xC0000374`。用户确认是既有问题；本次应用错误日志时间窗未发现对应事件。#50 历史记录已有 DLP 模块出现在异常栈中的线索，但本轮未取得新调用栈，不能据此解释 Edge 跳白。未循环重装或改变系统安全配置。
- 原任务、当前浏览器及脱敏诊断已保留；最新普通图片失败修正只在离线回归中验证，没有重启现场服务加载。短信送达已由用户确认；真实登录成功、人工验证后的接续、完整 JD/报告和保存会话重启复用仍未验收。
