# 先在本机跑通：公开岗位查询，不依赖自建服务

关联 #3 / #30 / PR #31。2026-09-16 用户明确：本机功能先完成，Linux 生产部署以后考虑。
这是当前开发分支的交付说明，不代表已合并 main 或通过全部实站/网络验收。

## 默认用户流程

启动原工作台，在首页“按岗位查询公开来源”输入原文关键词（例如 Architect、Engineer），
选择来源和地区，确认后获取并在本机筛选。无需填写产品服务器地址、API Key、代理端口，
也不需要先部署网关。默认本地提供者与以后可选的远端服务共用本地任务和报告接口。

原已合并范围为 **Anthropic 的 Greenhouse 公开招聘目录**，本分支按#95增加Cloudflare固定目录，每次明确选择一个来源，详见[来源契约](PUBLIC_SOURCES.md)。不是全市场搜索，
不是 BOSS、猎聘、51job 认证，也不会用这个来源冒充指定平台成功。关键词是原文子串匹配，
不调用模型翻译或扩写岗位。接口未提供明确远程属性时保留未知，不自行推断。

## 实际执行路径

`网页确认 -> 本机任务 -> 固定公开 GET -> 本机校验/筛选/分页 -> 本机 Store -> 独立报告`

固定接口分别为`GET https://boards-api.greenhouse.io/v1/boards/anthropic/jobs?content=true`和`GET https://boards-api.greenhouse.io/v1/boards/cloudflare/jobs?content=true`，不是用户输入的URL。
Greenhouse 官方文档明确公开 GET 不需要认证，并提供包含正文的列表查询：
https://docs.greenhouse.io/job-board.html#list-jobs

程序不接受用户指定 board、远端 URL、请求头、Cookie 或认证信息；不提交申请。
查询词和地区只在本机筛选，不发送给公开接口。对方仍能观察到本机的网络出口、请求时间
和固定请求路径；这是联网，不是匿名访问保证。原系统代理策略、TLS、域名与公网地址检查保持。
本次没有解决 Fake-IP/PAC/认证代理问题，不能把本地提供者当作这些问题的替代修复。

首次请求有界获取一个目录，最多32MB/10000条；检查条目ID、指定board路径、公开来源域名、
目录总数、正文完整性、重复与时间。响应不完整或有非法来源时拒绝，不补写正文。
职位URL来自发布方响应，未另外逐个访问验证；“正文完整”不等于“岗位一直有效”。

## 缓存、分页与限频

每个来源的缓存、错误和变化基线分别保存，缓存10分钟内复用。查询词变化只在已有目录上筛选，不再向上游重复请求；本地分页游标
绑定查询、目录版本和本机密钥。重启可继续有效缓存的分页；未知/错范围/过期游标不触发外部抓取。
每页生成独立报告，页面显示本页条目数和本次目录的匹配数；不是覆盖率或全市场岗位数。

与既有单岗位公开案例共用同一个工作区的限频库、来源键及30秒/12次每小时/24次每天约束，
更换入口、关键词、来源标签不能重置额度。429保存至少300秒或更长Retry-After，不自动重放。
网络或临时服务故障可展示不超过7天的缓存并标明过期/刷新错误，保留采集时间；无缓存不造数据。
401/403、证书问题、Fake-IP/非公网目标及坏响应不能用缓存掩盖。损坏缓存失败可见，不通过删库提速。

默认提供者采用惰性初始化，打开工作台及状态页不发网络请求；公开缓存出问题不应让用户
必须先修一个可选服务器才使用其他本地能力。

## 隐私和后续服务化边界

公开来源的“本地访问审查”和“允许分发审查”是不同标志。默认来源只有本地访问标志，
**未被授予分发标志**；远端客户端和公开网关仍默认要求分发审查，不能把本地快照直接公开上线。
本地密码、Cookie、简历、个人证据、私人报告不作为查询输入，不写入公开网关。
用户选择混合模式没有授权购买服务器、部署生产服务或公开个人数据。

后续 Linux 部署仍需单独确认来源使用条件、认证、配额、保留/删除、运维和成本；
这些属于后续阶段，不再阻塞当前本机版本。

## 验收与回滚

新增本地提供者回归覆盖：固定GET、零配置默认入口、确认/Origin/令牌、来源不可偷换、
本地访问不授权分发、缓存重启、查询隔离、分页/游标、错误/429、时间回拨、共享额度和独立报告。
真实 Chromium 界面流程加入原 run_recovery_browser.py，远端内容是明确标注的人工夹具。
另有 check_live_local_public.py --live，明确确认后只请求一次固定真实目录，只输出计数/元数据，
正文保留在临时工作区。默认仍检查Anthropic；`--source cloudflare`只检查第二个固定来源。既有公开案例CI继续保留，真实请求之间间隔31秒，不上传第三方全文。

本地回归不等于 Windows/macOS/Linux 远端已通过，也不等于真实浏览器或目标招聘平台已认证。
最终结果以对应提交的 CI 和真实来源烟测为准。

回滚不删除工作区、旧报告或共享限频库。可显式设置 LocalServer(public_client=None) 停用公开查询，
不把停用视为必须上线服务器。可选远端客户端仍是产品代码侧的注入接口，普通用户不填endpoint。
