# 多组公开查询的一次性待办

Refs #131 / #9 R3 / #30 H4。本分支基于统一候选 #129，新增本机有限队列；当前提交的 CI、浏览器与便携产物结果见对应 PR，不沿用父分支绿灯。

## 使用

首页公开来源查询中选择来源、查询词和地区，展开“保存多组查询，依次获取一次”。核对后勾选“同意按上方来源与查询获取一次”，点击“加入待办”。立即查询、每日计划和待办各有独立同意；更改表单会清除待办勾选。最多同时保存5条，每条固定一个已批准的本机公开来源、首屏最多20条，不保存游标或自动翻页。来源选项仍为 Anthropic、Cloudflare、Cursor。

工作台服务或[独立进程](PUBLIC_WORKER.md)保持运行时按加入顺序执行。关闭网页不会停止服务；关闭整个进程后，尚未开始的条目保留。每条许可自确认起24小时有效，已经过期的条目留历史且不联网。每次尝试结束到下一条至少间隔30秒，包括缓存结果；原共享30秒/每小时12次/每日24次与429冷却继续生效。手动查询和每日计划也使用同一额度及任务锁，可能使待办等待或失败暂停。

“移除”只适用于尚未开始的条目。“暂停队列”取消队列自己的当前尝试及后续条目；当前只读请求或已经开始的本地保存结束后停止。已有任务、报告、缓存和配额保留。失败、过期缓存、来源/网络路线改变、时间回拨或不确定结果会暂停。核对原因和列表后单独勾选“继续”许可，才会按当前条件重新确认剩余未运行条目；已尝试的条目不会因此重放，需要重试时明确新建一条。

每条结果链接指向原报告。同样的查询也生成独立批次，不覆盖旧报告。“完成”表示该次查询和报告流程结束，不保证报告有符合目标岗位的 JD 或已接受 Vibe 要求。取回数量、岗位分类纳入数量和已接受要求分别查看报告；例如人工验收中 Architect 和 Engineer 各取回20条，但原岗位分类分别纳入20和0条，不把取回数算成合格证据。

## 执行与恢复

队列使用独立 OS 所有权；工作台和多个独立进程共用同一工作区时只有一方执行，其他可读取和更新暂停操作。界面同时显示真实队列状态与另一进程所有权。原 PublicTasks 的任务锁使每日计划、手动查询和待办不并发取数。

先持久保存启动标记再提交原任务。提交后的记录写入失败会取消刚创建的原任务；服务重启遇到不确定启动标记时留中断历史并暂停，不猜测成功或自动补跑。通过[原完成回执](PUBLIC_TASK_OUTCOMES.md)核对任务 ID、首次尝试和查询绑定；另一个手动查询替换当前记录也能找回原报告，同 ID 人工续接是另一尝试，不会被队列误停。回执缺失或损坏不能当作成功。

数据仅保存在原工作区 `public_queue/queue.sqlite`，schema/user_version 均为1。缺失时默认空，读取和启动空队列不创建此目录或请求来源。严格限制条目、字段、修订号、许可和有限时间值；重复字段、未知版本、异常大小或符号链接拒绝执行，保留原记录。保留最近20条执行历史，移出历史不删除对应报告。页面更新携带修订号，旧页面不能覆盖新列表。

## 验证范围与回退

单测覆盖 FIFO、首屏范围、共享额度、缓存/硬失败、24小时许可、原任务忙、暂停与人工续接保护、损坏/未来记录、报告保留、实际第二进程重启/所有权竞争及强制终止后的不重放。HTTP 控制沿用会话令牌、同源检查和原变更锁。真实浏览器覆盖勾选撤销、旧页面冲突、暂停/移除/继续、原报告链接、390px，以及关闭整个网页服务后真实独立进程执行。

便携验收新增实际冻结 worker 读取人工预置缓存并生成原完整 JD 报告、零来源请求、原缓存与配额字节保持；同时检查资源、默认空队列和空闲独立入口。源码预检与最终冻结 exe 结果分别记录，只有同一提交的实际冻结验收通过才算后者通过。人工来源、注入时间与临时进程不代表真实网站或24小时长跑认证；中国三站正常登录→完整 JD、跨设备权限/额度、生产服务和无人登录运行仍未通过本项验收。

升级或回退前暂停队列、停用不再需要的每日计划，等待当前步骤结束，关闭全部同工作区进程并备份。旧版本忽略新增队列文件，不改原任务/报告格式；不得和新版同时写入。重新启动新版时，未撤销且未过期的待办许可可能继续执行，暂停状态则保持。不要删除队列、回执或频次库来消除不确定结果。
