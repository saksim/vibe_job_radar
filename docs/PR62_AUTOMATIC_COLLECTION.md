# 明确选择后的搜索到报告自动采集

本增量关联 #49/#50/#46，仍属于未合并 PR62。原报告、Store、浏览器后端、登录接续及共享频次策略不变。

## 使用范围

在第2步勾选“搜索成功后，按本次查询的返回顺序自动采集前 N 个岗位并生成报告”，N 使用原有本批岗位上限。默认关闭，旧任务缺字段时保持原人工选岗。选项只能在创建任务时明确设置，不能在运行中的 action 请求中修改。

完整流程是：用户给定查询/预算并确认 → 正常搜索得到有效非空列表 → 按原发现顺序冻结最多 N 个岗位 ID → 现有逐条采集 → 完整正文入原 Store → 同批原报告。没有第二个下载器，不使用模型猜链接、账号或岗位相关性；返回顺序不等于目标方向判定，报告仍如实做后续分析。

自动选择在第一条详情请求前持久保存，审计 selection_source=query_order / auto_selection_applied=true。手动选择保留为 selection_source=manual。一次任务只应用一次自动选择；读取、暂停后恢复或进程重启不得改变已选批次或把后面的易抓岗位替换掉失败岗位。

## 登录与恢复

公开可正常读取或已有有效会话时，不提交登录动作。遇到原有登录/验证/访问限制立即保留原停止决定，不自动填密码、不忽略隐藏模板判断、不改变访问域名或权限。前面已经成功保存的正文及部分报告不丢失，原有本机登录及明确开启的登录后接续可接回同一选择。

集合阶段触发速率等待时，原 worker 的后续动作必须是 resume（恢复正文阶段），不是重做 search。仍遵循原持久配额与来源等待；取消/停止不再自动进入下一岗位。明确零结果、响应结构错误和等待登录都不能用旧卡片自动造一批报告。

## 开发验收与已知范围

- 独立纯选择测试：默认关闭、严格布尔值、顺序/上限、重复或异常行、明确空结果和既有选择。
- 原 GuidedService/Store/报告：一次 search 到报告，API-only 列表，阶段停止、部分报告、恢复不重抓成功项、速率等待恢复阶段。
- 既有 Chromium 工作台的登录返回测试保留人工选岗模式，另增加 --automatic 模式，验证真实 checkbox 到原生产流程而不点击 Collect。
- 四组原生浏览器的既有搜索测试保留，追加一次 create 到完整报告及自动模式明确零结果。

测试只使用独立人工数据，不认证实际猎聘、用户账号或所有网络环境。自动采集不是自动填写平台登录表单。此前已记录、工具未能交付的隐藏登录模板误判仍保持保守停止，本增量不绕过或重新提交被拦截修正。不能因此宣布 PR 已没有已知功能问题。

当前无需用户陪测、上传凭据或手工重跑 CI；开发侧先完成本提交的工程检查。真实账号的集中验收与本轮自动化功能验收分开。关闭新选项或回滚代码不删除旧报告、原文、证据、Cookie 快照或配额。
