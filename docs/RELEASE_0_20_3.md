# 0.20.3：岗位去重、搜索等待与连接关闭边界

以文档整理提交 `93e2c74f195650506f70ea08aa75363d7c8f29fb` 为开发起点，保留完整文档导航和历史归档。Refs #55、#56、#263、#183、#57。正式交付以本版 PR、准确 main 的验收、Tag 和镜像回执为准。

## 解决了什么

BOSS、51job 的新浏览器采集任务使用与既有详情/入库一致的规范 URL 身份：同一岗位仅有已知跟踪参数变化时，保留首个实际访问链接，只占一个岗位名额；翻页重排不再绕过重复页识别。未知查询参数、不同路径和主机仍区分，原访问范围不扩大。旧任务的身份模式、卡片 ID、选择与断点记录保留，不重写历史任务。

原生 CONNECT 隧道关闭时，将已接收请求的处理者纳入清理结果。处理者仍在建立连接或尚未完成释放时，不能提前报告清理成功；在既有有限关闭预算内无法完成，就保留明确错误，让工作区现有所有权保护继续生效。已接收连接即时关闭、取消、认证、配额与原业务期限保持。

Windows PAC 验收的额外请求错误改为中性计数描述。原总数断言没有识别请求调用者，不能仅凭多一次 GET 就归因于缓存 worker；原断言、追踪、期限与失败记录全部保留。

猎聘原生搜索等待自身业务响应时，不再重复复制整页 HTML、逐节点读取样式并尝试不可能成功的列表/详情解析。仍检查页面挑战与取消，只在当前搜索响应满足原条件时结束等待；缺失响应仍在原 15 秒期限后报错，详情页与其他站点保留原解析路径。

## 验证结果

两站去重的旧代码在人工受控两页中保存了 4 张卡片，而不是 2 个不同岗位；修后三项定向方法一次通过，包含两站的新批次、原链接、自动/手工选择及旧任务断点兼容。原生连接的旧代码在处理者仍等待连接、上游未关闭时于约 47 毫秒返回成功；修后 22 项相关检查一次通过，覆盖在途关闭失败、所有权保留、正常完成、共享原两秒预算、原错误优先级和接收生命周期。

另有七项文档/PAC 断言契约检查一次通过，220 份 Markdown 的 726 个本地路径链接无缺失；这不代表外部链接或标题锚点全部验证。文档检查首次准备因本机日志目录权限失败，尚未执行用例；取得项目写入权限后首次实际执行通过。原首红、日志、检查输入摘要与独立审查分别保留，没有本机全矩阵、浏览器实站采集或旧 CI 重跑。

完整产品门槛、源码一致性、dev→release→main 晋升与正式产物核验保持。旧版本或文档提交的 CI 不算本候选通过，最终结果以准确发布提交的回执为准。

搜索等待优化有受控首红：旧实现对缺失响应和只有默认推荐响应都调用无用的全页快照。修复后 48 项相关定向检查通过，覆盖原 15 秒期限、迟到的当前结果与空结果、挑战/拒绝/取消，以及详情和其他站点的 DOM 路径；开发过程中一次测试夹具不一致的失败保留，修正为与生产快照一致的业务响应观察后通过。

先前候选 `ecf075c` 的 Windows Edge 无界面验收曾发生 45 秒搜索等待失败，唯一补验另在本机代理连接失败；原失败继续保留。搜索现场显示请求准备已消耗约 31 秒，与后续缺失响应等待叠加；底层延迟来源及代理连接失败原因尚未确定。本次减少重复 DOM 工作不冒充这两次事故的根因证明，新代码须取得自己的完整 CI 结果。
