# 本机公开来源历史

关联 #9/R5、#30/H3、#57。工作台的“按岗位查询公开来源”下，展开“查看来源更新历史与异常”。查看、刷新和导出只读取本机，不访问招聘来源。

原公开查询和已确认的每日计划在现有请求完成后自动留下摘要，覆盖已接入的 Anthropic、Cloudflare、Cursor 固定目录：
- 完整目录：总量、首次基线或新增/修改/本次未出现/未变计数。
- HTTP 304：确认时间更新，正文观测时间和原目录内容保持。
- 请求或完整性/结构校验失败：保留错误码，不把历史成功作为当次成功，不推进有效目录。
- 字段结构摘要变化：比较顶层字段/类型及前256条记录的不同字段/类型组合。它仅是提示；完整响应仍经过原适配器逐条验证，不是所有来源的结构认证。

每来源保留最近128次摘要及累计记录次数，重启后仍可读取。摘要只含来源、版本、时间、哈希、计数及错误码；不保存用户查询、凭据、JD正文或个人材料。历史从功能启用后开始，不从旧文件补造观测。进程在请求完成与摘要落盘之间中断可能留下缺口；累计次数只代表成功保存的摘要，不是完整请求账本。

缓存读取、本地分页、改关键词、刷新页面和查看状态均不会制造新观测。缺少最近10分钟内的成功确认或发生时钟回退时，页面明确新鲜度不足。导出固定为当前显示的摘要。完整岗位ID差异仍在原缓存与各自报告的 catalog_changes.json 中；本次未出现不等于岗位关闭。

新增 local_public/observations-v1.sqlite 独立文件，原v1/v2目录、校验时间文件、请求额度、工作区数据和报告格式保持。旧版可以继续打开原目录；不会理解新历史。历史损坏不自动清空：查看报错，查询继续按原响应处理并提示摘要保存失败。没有后台追加请求、跨设备同步或自动修复来源规则。

本项交付本机固定目录的连续观测记录，不替代真实目标岗位覆盖、三站访问契约、人工JD质量、全天服务、跨设备水位或24小时现场运行验收。
