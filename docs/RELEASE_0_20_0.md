# 0.20.0：高级工作台的草稿、故障与执行边界

本轮工程项 #517，关联总控 #57，支持 #317/#319 的工程可靠性；不代替真实项目材料和普通净机验收。

## 解决了什么

- 资料刷新与草稿版本分离，防止上传附件或采集完成后，旧编辑内容携带新版本覆盖另一窗口保存的修改。
- 高级页各模块独立初始化，无关的岗位库、证据或采集故障不会把整页锁在初始化状态；受影响模块保留明确错误。
- 个人证据服务按需初始化，证据历史库异常不再阻断整个桌面或服务器应用启动。
- 创建并执行采集移入应用层用例，后台接纳不再依赖页面随后刷新历史成功；保留已创建任务与接纳结果，不自动重放不确定请求。

## 提高了什么

页面负责编辑和展示，应用层负责用例接纳，原服务负责执行与持久化。桌面和服务器使用相同边界，旧接口、原报告、后台采集、配额和所有权继续保留。

## 验证结果

实施范围与实际验收分开记录：定向正反向回归、准确 main 的 CI、晋升 PR、正式三类 Tag/资产与 Docker 双架构匿名验证，均以 #517 和本版 Release 的实际回执为准。尚未执行或失败的检查不会记为通过。

## 剩余问题

原 18 项的真实站点、完整 JD、人工标注、本人项目、普通净机及生产部署条件仍单列。#183/#263/#269/#436 历史根因缺少现场证据，不以新版 CI 通过代替。#210/#320 保持只读；#23/#30 原本期范围不扩大或重开。

没有可信签名凭据，桌面发行仍如实标示 unsigned / unnotarized。仍采用单拥有者、单工作区、单进程；生产主机、域名、HTTPS 和备份恢复需要真实环境。部署见 [Docker](DOCKER.md)，模块边界见 [架构](ARCHITECTURE.md)。
