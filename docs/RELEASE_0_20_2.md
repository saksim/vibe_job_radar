# 0.20.2：分站搜索范围与原生连接关闭

基于正式 0.20.1，Refs #55、#56、#263、#436；#183、#269 继续按各自证据调查。实际完成状态以配对 PR、准确 main 的 CI、正式 Tag 和镜像回执为准。

## 解决了什么

BOSS 和 51job 已有任务翻页时，另一关键词的列表可能混入原任务。两个独立适配器复用纯关键词范围校验，对已明确包含关键词的标准搜索入口逐页核对原任务；创建时拒绝不一致或重复关键词参数。旧任务同样校验，保存的检查点和执行绑定不重写，手工列表入口及无已知关键词契约的入口仍保留原行为。51job 的 `/pc/jobdetail` 路径改为精确匹配，避免将相似前缀误认作岗位详情。

原生隧道先前在处理线程开始后登记客户端连接，关闭操作可能遗漏已接收但尚未调度的连接。本版在接收时登记并与关闭操作共用锁；线程启动失败也先关闭再撤销登记，释放原并发槽位。连接处理结束时先关闭再撤销登记，保留原取消响应、目标隔离、认证、配额和等待期限。

## 提高了什么

站点的关键词访问规则由适配器负责，任务服务只调用其契约，页面不承担该业务判断。PAC 拒绝场景复用已有守卫和握手观察，关闭前保存固定计数与阶段；观察失败不伪造零事件、不覆盖原业务失败，也不把缺失的必要观察判为成功。没有放宽网络权限、删除原断言或复制另一站的分页规则。

## 验证结果

在原 0.20.1 代码上，离线快照复现了两站跨关键词混入和 51job 相似详情路径误识别；真实本地回环连接复现了关闭遗漏晚调度连接。PAC 夹具证明原业务拒绝断言失败前缺少守卫/握手观察，仅用于验证诊断接线，不代表复现了旧云端 SOCKS 故障。修后连接生命周期17项和PAC观察链路18项首轮通过；适配器33项补验通过。适配器首次驱动在子进程返回后因日志目录权限失败，结果未知；原记录保留，仅同一33项在预先打开日志文件后补验一次，不写成首轮成功。生命周期驱动另有一次执行前的目录权限拒绝，当时0用例，修正输出位置后首次执行17项。三组均无失败、错误或跳过，实际输出与源码摘要保留；没有本机全矩阵或旧CI重跑。完整必需 CI 和正式发行各自使用新提交证据。

## 剩余问题

#55/#56 仍需要可核实的正常动态访问契约、真实完整 JD 与分页证据；本版不把人工夹具或官方网页可见卡片算作实站认证。原 30 个岗位／3 日期口径保持。#183 的旧额外 GET 来源、#263 的其他旧启动/连接故障、#269 的历史慢因和 #436 的旧拒绝阶段物理原因仍未确认，不以新版通过代替。#269 本次只运行一个原有分类用例一次，1.55 秒通过、未复现；没有重复采样求绿。

保留既有服务器单人工作区、桌面、CLI、团队服务、升级与报告功能。原人工标注、项目材料、普通净机及生产环境验收继续单列；没有签名凭据，桌面发行仍 unsigned / unnotarized。#210/#320只读。
