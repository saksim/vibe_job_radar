# 猎聘页面初始化与关键词结果

关联 #63 / #49，实施在 PR196。初始化响应只用于页面加载，不能成为用户任务的岗位列表或“没有匹配岗位”的依据。

## 实际发现

2026-09-25，提交 `8ba8b53` 在自身 21/21 CI、四种原生模式、Windows 源码资格和实际 exe 既有流程分别通过后，执行了一次正常 `/zhaopin/` 入口观察。FLog、TLog 和营销预检均在本机终止，未使任务停止；页面继续产生筛选初始化 POST。随后正常网页自行产生的搜索 POST 被原查询绑定拒绝：页面尚无查询参数，`mainSearchPcConditionForm.key` 为空字符串，`currentPage` 为整数 0、`pageSize` 为整数 40。该搜索 POST 在本机拒绝，没有发送，也没有取得默认推荐响应。

结果为 `liepin_search_query_mismatch`，关键词尚未输入或提交。停止时计数：文档 1、业务 3（两个 OPTIONS、一个筛选 POST）、静态资源 20、robots 3、登录 0。观察期间未记录主页面空白；这不是完整活态、关键词搜索或账号通过。专属 profile 已清理，原始请求内容、页面与失败证据仅留本机。

该次保留的 DOM 已出现 `input[type="text"][placeholder="搜索职位、公司"]`。这里只记录实际元素，不把停态 DOM 的存在当作交互成功。早先保存的官方搜索 bootstrap 代码也区分初次条件加载与用户搜索，并在用户搜索前更新页面内地址；其完整源码不提交仓库。

## 当前处理

- 仅精确的无查询参数搜索入口、空关键词、第 0 页、每页 40 条的已观察初始化请求得到 `entry_bootstrap` 标记。带任何查询参数、用户关键词不匹配、其他页码或页大小仍按原规则拒绝。
- 页面收到初始化响应后可以继续加载；解析器拒绝将其业务 JSON 或同页推荐链接作为关键词列表。默认推荐为空也不构成用户任务的“无匹配结果”。
- 原关键词请求仍要求 URL、正文关键词、筛选和分页对应。后续匹配结果不会被迟到的初始化响应替换；请求体和查询原值不进入诊断。
- 使用原已审核搜索接口、Origin/预检、robots、配额和响应检查。没有新增主机、拼造 API 请求、修改页面脚本、提交账号或重试被拒绝请求。

回归覆盖精确初始化边界、错误关键词/筛选/页码继续拒绝、JSON 与 DOM 推荐不能进入列表、推荐不能成为空结果及迟到响应隔离。人工 HTTPS 流程新增无查询入口实际请求和推荐 DOM，并保留之后的原关键词→完整 JD→原报告流程；当前提交成绩以 PR 为准。

## 剩余主线

产品默认导航现接入[正常可见搜索表单](LIEPIN_NORMAL_SEARCH_FORM.md)，区分实际文档与同页地址更新，并要求当前查询自身的业务响应。新修改仍需本提交资格及实站；当前官方筛选映射和完整查询结果配对需要继续实测，不能删除主站文档的 robots 限制或用默认推荐替代用户检索。真实账号、会话复用、完整关键词链路和人工全文审核继续开放。
