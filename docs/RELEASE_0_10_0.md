# 0.10.0：NTLMv2 本机代理认证与复核构建发版

## 解决了什么

[#391](https://github.com/saksim/vibe_job_radar/issues/391) 补齐本机 HTTP 代理的 NTLMv2 认证选择。工作台、CLI、HTTP、请求桥和原生 CONNECT 使用同一路线；Windows 可加密保存、独立重开、清除并接续既有后台身份。

[#395](https://github.com/saksim/vibe_job_radar/issues/395) 修复 Windows 构建复核后保留同名工件时自动发行被阻断的问题。按成功轮次的准确 ID 下载，校验外层 ZIP 的大小和 SHA-256，再解包；失败轮证据继续保留。

## 提高了什么

认证进程强制 NTLMv2、只使用明确输入的凭据并省略工作站名；一次同连接握手共用原期限，失败停止。新增离线组件诊断和真实冻结程序证明，正式发行同时检查组件协议、凭据重开、清除及原报告。既有 Basic/Digest/SOCKS/PAC、升级续传和自动交接、团队、采集与原报告均保留。

## 验证结果

本机九项人工代理/TLS/HTTP/桥/原生守卫检查 14.853 秒通过；41 项设置、实际 Windows 加密重开和发行相关检查 6.732 秒通过；源码离线组件检查通过。本机 Edge 155.0.4283.45 的三个页面、390px 布局、凭据保存/清除与重开通过；实际浏览器代理完成 4 次人工目标请求，错误凭据拒绝后零目标请求，没有原站认证头或直连回退，实际 DPAPI 独立子进程和新浏览器首文档恢复通过。当前仍为开发候选；准确主干完整 CI、真实 EXE 和正式 Tag 的最终结果由对应 PR/Release 回填，不预填完成。

自查复现三种NTLM故障在向导任务和HTTP采集结果中只显示通用说明；补齐组件安装、并发等待和原连接超时的具体提示。首次失败和修复后的实际任务状态检查记录在 #391，原错误码及业务期限保留。

发行工具 28 项定向检查通过；使用 v0.9.0 实际复核记录复现旧选择失败，并核验新选择与已保留实际证据 ZIP，无远端变更或重复下载。该改动仅限 Windows 单构建作业；Python 多作业的部分复核继续使用既有独立规则。
