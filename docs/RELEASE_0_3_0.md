# 0.3.0：质量复核、来源历史与团队协作

本次沿 dev → release → main 晋升。关联总控 #57，交付 #318（PR #343）、质量 #316（PR #344）、来源变化 #9/#30（PR #345）、团队服务 #346（PR #347）。下载包的精确提交、构建运行和校验值以随包 provenance.json、SHA256SUMS.txt 为准；相同版本号不能替代这些记录。

## 解决了什么

- 质量复核原来依赖CLI和手工编辑JSON：现在从具体报告进入独立JD标注和并排去重裁决，填写方向、完整性、要求与判断依据，保存草稿、确认或撤回。
- 多窗口导出可能与页面显示的标注版本不一致、请求期间编辑可能被覆盖：导出和保存都绑定版本，请求期间锁住编辑控件；JD与文档对分别保存时保留另一处未保存输入。
- 无网址岗位在质量包中缺少来源引用：新包保留 source_ref，页面和纯文本导出显示来源、公司与地点。
- 公开目录只有相邻两次差异，难以回看多次更新与异常：为已接入三项固定目录记录每来源最近128次摘要及累计记录次数。
- 新的本地标注/来源历史文件损坏时不能被重建为“正常的新历史”：明确报错并保留现场；来源历史故障不丢弃原采集结果。

- 多设备各自计量不能约束同一账号总额：新增可选中央配额服务、成员/资源权限与设备撤销；服务不可用时停止联网，不静默退回本机额度。原本机模式默认保持。
- 公开数据跨设备同步缺少版本和持久确认：增加完整/增量快照、每设备水位、一致性游标，部分失败保留旧数据。旧快照导入不会被标成新的来源确认。

## 提高了什么

- 可在同一份原报告上完成独立JD与重复岗位标注、查看适用分母下的指标、导入或导出复核包；原报告、原岗位分组和本人材料保持不变，原CLI继续可用。
- 来源页面区分完整更新、304未变化确认、请求失败和结构/内容校验失败，分别显示正文观测与最近确认时间。缓存读取、翻页、改关键词和查看历史不会增加来源请求。
- 本机每日计划自然记录目录观测。字段结构摘要提示变化，完整响应仍经过原适配器校验；本次未出现不被当作岗位关闭。
- 晋升PR与发行材料统一写明解决内容、改善、验证和剩余问题；发行说明进入 CHANGES.md、草稿正文及校验/来源记录。功能先进入dev，再进入release和main。

- 设备发证失败会回滚，连接安装完整写入后才启用；查询正文和新鲜度使用同一数据库快照。团队请求沿用工作区网络策略，过期审计在后续读取/健康检查/备份前清理，发行包拒绝重命名后的设备凭据。
- 提供认证公开查询、本机权限/配额/同步面板；只处理已独立获准分发的公开来源，沿用原岗位与报告链路。Windows设备凭据使用当前用户DPAPI，私人材料和平台登录态留在本机。
- 提供Linux/systemd、Caddy HTTPS反向代理、固定来源受控刷新、备份、撤回和成员擦除命令。部署配置纳入发行源码指纹，私有团队凭据禁止进入源码包。生产主机尚未准备，操作说明见 [团队服务](TEAM_SERVICE.md)。

## 验证结果

- 发行与晋升：20项定向检查通过；PR343自身26项CI检查成功后进入dev。
- 质量：原评估与新服务/HTTP检查39项通过；实际Edge研究→本人材料夹具→原报告→JD复核→导出→并排文档对10项通过，检查版本冲突、草稿保护、确认/撤回和390px布局。最终候选26项CI全部通过。
- 来源历史：55项原目录/条件请求/多来源检查、新增8项历史检查以及三来源隔离/Cursor计划定向检查通过；实际Edge查询、分页、双来源、注入每日到期、报告、历史导出5项通过，恰好3次人工目录请求；最终候选27项CI全部通过。
- 团队服务：相关118项回归通过（91.170秒），最新来源时间及发行凭据隔离24项通过（6.473秒），中央公开目录原限额补充3项通过（1.183秒）。实际Waitress进程、两个独立客户端与Edge的5项验收覆盖共享限额、重启保持、同步、撤销和原报告。首次回归发现的注入时钟兼容问题及浏览器退出清理持锁问题均保留记录，修复后相关复验通过。前序团队候选27项CI全部通过。6项审查修正另经31项定向检查覆盖；其中成员擦除夹具混用时钟的1项失败已修正，受影响项复验通过。原共享额度及发行资格另有50项通过、2项本机平台跳过；最终CI仍须完整通过。最新实际服务/浏览器5项通过，权限错误导致的旧结果写入失败也保留记录。
- 本机浏览器检查无页面错误、无真实招聘请求。全部人工JD、项目材料和标签均为合成夹具，不作为真人质量结论。
- 每个最终候选与main的实际CI、构建运行和资产校验另绑定到确切提交；发行工具要求选定main的8个验证工作流全部成功。已有完整测试矩阵与Windows程序检查保留，不重复在本机全跑。

## 剩余问题

- Windows候选未签名。便携包/CI通过不等于干净Windows、新手现场、正常账号或三站实站验收通过。
- 独立真人JD金标准、本人真实项目材料、目标方向样本和实站分页边界仍待相应输入；本功能不自动生成真人确认。
- 连续24小时及实际Windows重登录须独立验收，不能把注入时钟或多个中断时段拼成通过。
- main342及PR344初版的原生等待首失败已保留在#269；后续绿灯不证明全部历史机器慢因、PAC额外请求或浏览器故障根因已解决。
- 团队服务等待用户提供生产Linux主机与域名；真实TLS、两个物理设备、来源分发许可、容量和运营现场未认证。共享配额只约束已登记设备和管理员绑定的资源，不验证平台账号身份；不支持多副本共享数据库或擅自采购主机。
- #23中的其他网络协议、系统与真实网络产品范围保持原跟踪。

升级前停止任务和计划、关闭同工作区程序并备份完整工作区。新版解压到新目录，沿用原工作区；保留旧程序与配套备份供回退。新 history 文件与原目录缓存分开，已有JD、报告、个人材料和额度不迁移或清空。详细步骤见 [便携发行](PORTABLE_RELEASE.md) 和 [工作区兼容](WORKSPACE_COMPATIBILITY.md)。
