# 公开查询与旧报告响应的交接

Refs #229 / #210 / #30。第一页任务完成后，页面会启用下一页，同时还在加载该页报告。快速开始下一页时，旧版的单个轮询标记会丢弃新观察请求；旧报告随后还会固定页面，留下后台已完成、界面仍显示进行中的不一致。

现在每次明确触发观察都会更新请求版本。已有观察继续处理新版本，过期状态或报告不结束当前观察，也不覆盖或固定新的任务结果；旧报告请求失败时仍接回等待的新观察。没有新增采集、来源重试或取消，原120次本地状态查询上限和用户明确选择的报告保持。

原PR80首次浏览器CI停在公开列表第二页，有限重试与代理认证用例已通过。确定性本机Edge对照扣住旧报告响应，再完成新任务；旧代码停在进行中并显示旧报告，局部修复显示第二页及对应新报告。准确PR80候选和最新开发源码均完成这一对照，相关代码与当时已合并主干相同。

新增原浏览器回归分别放行旧报告成功响应、返回人工旧报告错误，均要求新任务无需刷新页面即可显示状态和报告。两个场景各仅一次人工来源响应，分页使用缓存，原报告哈希保持，真实上游传输被测试夹具显式阻止；CI同时保留原恢复流程。该证据不解释其他Windows等待问题或认证真实招聘账号。
