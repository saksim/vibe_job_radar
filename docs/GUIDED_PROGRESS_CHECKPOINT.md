# 浏览器进度只更新当前动作

Refs #197 / #63。原 `d6239d9` 工作台实际搜索返回42张卡片，选定车载数据架构师的详情收到302，保存了选择、一次尝试及无正文结果。随后一次明确登录动作期间，任务却变回先前的列表快照：选择与尝试清空，`manual_pending`变为`not_checked`，显示`ready/rate_wait`。该现场单独保留，不视为账号登录成功。

根因可独立复现：`GuidedService._backend`创建的进度回调捕获首次动作的整个任务字典；浏览器复用于采集、登录以及空闲页面处理时，回调仍将旧字典整体写回。这不影响此前保存在其他工作区的正文，但能使当前任务丢失选择、尝试历史、登录接续或报告引用。

修复在原检查点锁内读取最新状态，仅在任务仍运行且未取消/退出时更新进度字段。空闲、等待人工、已排队、暂停、完成及停止的状态不再被迟到进度改写；实际配额、网络请求节奏、登录提交及重试规则不变。

五项人工场景覆盖后续采集中的选择/已开始尝试、正常登录等待、已生成报告与完整正文、排队/暂停/停止的新动作，以及取消/退出。旧实现产生8个失败断言（包含子测试），原日志保留。网站302的目的地及是否需要登录仍待正常流程核实；这项确定的状态覆盖修复不等于完整实站链路已经通过。
