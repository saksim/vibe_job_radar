# 猎聘批次与恢复进展（#51 / #52）

## 已实现的有限分页

新任务保存 `identity_strategy=platform_entity_v1`。列表卡片按适配器验证过的
平台实体去重，保留首次观察到的实际导航链接。猎聘的主机、`job` / `a` /
`lptjob` 路径族与职位编号共同组成实体；不假设不同路径族或主机互为别名。
跟踪参数变化不增加本批岗位数，不会据此构造新的请求 URL。

新建猎聘批次还冻结关键词和显式筛选。首个有效列表记录实际观察到的默认筛选，
后续读取/翻页/恢复时新增、删除或更改筛选均停止，保留旧卡片和选择。
可选列表地址必须与输入关键词一致；不会把另一查询的卡片混进本批。
明确的 `currentPage` 可递增，重复页码即使展示了不同卡片也会以
`repeated_cursor` 停止。没有显式页码的 DOM 仍使用实体/页面签名终止，不猜游标。
旧任务不自动补写该冻结规则。

新任务的页面签名与卡片顺序无关。分页明确记录 `repeated_page`、
`no_new_entities`、`no_next_button`、`confirmed_empty`、`page_limit` 或
`card_limit`。后续空页不会抹去先前发现的岗位，也不再把整个批次说成零结果。
每批仍最多 5 页、100 张候选卡片、20 个选中岗位。

没有 `identity_strategy` 的旧任务继续使用已有 URL 卡片 ID 和顺序签名，
不改写旧选择或已保存结果。未知策略明确停止，不静默使用另一套身份规则。
这是批次内去重；尚未改变全局 Store 的历史记录身份或证明跨任务增量同步。

## 验证边界

新建搜索和 HTTP 转交任务保存版本化执行绑定：原查询/筛选角色/预算/访问范围、
适配器版本、后端及原生访问契约摘要。兼容性检查先于浏览器启动和登录预算预留。
原同意继续有效；软件升级若改变这些约束，会保留结果并明确要求兼容版本或新任务。
摘要用于发现不一致，不是防止本机用户修改文件的数字签名。

任务文件采用有界读取，验证 JSON 重复字段、schema、卡片唯一性与选择引用。
损坏或未知版本文件不重写，界面提示该任务未加载。旧任务明确标记
`legacy_unversioned`，不补写伪造的历史版本。恢复时校验所选成功记录真实存在、
来源类型与正文哈希一致；缺失时不自动重抓或把它们计为成功。
读取已有记录使用只读 SQLite 连接，不创建缺失数据库。原持久配额不重置。

Windows 中短暂打开的任务读取句柄也可能阻止 `os.replace`。服务内 `_load`
与 `_save` 使用同一把可重入锁，避免界面轮询打断登录接续的原子保存。
并发测试确认读取结束前写入不能替换文件；不通过重复登录弥补保存失败。

`test_guided_batch_identity.py` 使用明确的合成多页列表，覆盖参数变化、
跨页重复、重排、子集页、页面与卡片上限、不同路径族、旧任务和重载后的选择。
本轮相关 171 项测试通过。它们不是真实岗位样本，不满足 #54 实站验收。

原PR62记录的真实列表曾受 #63 主页面空白阻塞；后续原生实验模式已在本机Edge取得一页42张关键词卡片，见[当前证据](CURRENT_ACQUISITION_EVIDENCE.md)。正常账号后的完整JD、实站分页与恢复仍未验收，单页列表不能替代这些条件。
