# 猎聘公开详情：复制链接到本批报告

关联 [Issue #144](https://github.com/saksim/vibe_job_radar/issues/144)、[真实取数 #49](https://github.com/saksim/vibe_job_radar/issues/49)、[搜索入口 #63](https://github.com/saksim/vibe_job_radar/issues/63)。

2026-09-24 用户确认日常 Edge 未登录也能阅读所给职位的职责和要求。同编号公开详情 `https://www.liepin.com/job/1985859731.shtml` 通过正常匿名 HTTP 和应用专用 Edge 均可读取。已有解析器取得相同的 1,128 字正文；原 Collector → Store → 本批报告实际完成，1 个完整 JD 组、明确 AI 编程要求 0、分析错误 0。这是一个岗位样本，不是账号登录、自动搜索或三站认证。

## 使用原入口

1. 工作台进入“自动采集 / 原文复核 / 附件与量化指标工作台”，选择“我有职位链接：套用 URL 入门参数”。
2. 粘贴实际打开的具体职位链接，每行一个；检查岗位方向、来源许可、用途及正文预算。
3. 预检会说明已识别的猎聘分享链接将使用同一职位编号的公开地址。确认执行后，原采集器取得正文、核对身份、入库并生成本批报告；不需要搬运正文。

## 输入处理范围

仅处理新建 URL 批量任务中的 `https://www.liepin.com/job/<数字>.shtml`。当全部查询参数都是本次实际分享链接中观察到的字段时，移除 `pgRef`、`d_sfrom`、`d_ckId`、`d_curPage`、`d_pageSize`、`d_headId`、`d_posi`、`skId`、`fkId`、`ckId`、`sfrom`、`curPage`、`pageSize`、`index`，主机、路径和岗位编号不变。

凭据检查在此之前执行。未知参数、岗位身份参数、其他主机/URL 家族不适用此处理；现有通用 URL 校验仍生效。没有先请求被拒链接再换地址的重试。每个实际请求仍由原 robots、TLS、跳转和预算逻辑决定。

任务和 `collection_manifest.json` 保存 `liepin_share_v1` 及删除的参数名，不保存跟踪值。处理后的详情通过现有 LiepinAdapter 核对最终页面和正文身份；串岗位、挑战、下线或不完整内容不会入库为完整 JD。旧任务、浏览器选择、搜索发现和历史记录不被迁移。

该职位没有 HTML canonical 声明；不将输入处理宣称为服务端 canonical 重定向。依据为用户原链接中的同编号路径、实际可读正文及既有身份检查。真实完整页面、跟踪参数和私有报告不提交仓库。
