# 工作区内的本机代理凭据

0.12.0 补齐 Linux/macOS 系统密钥库保存，覆盖已有四种认证方式。默认密钥库、错误恢复和 schema 12 回退规则见[系统凭据说明](SYSTEM_CREDENTIALS.md)。

0.8.0 增加“本机 HTTP Digest＋保存凭据”，原 HTTP 模式明确标为 Basic；[Digest 协议与回退范围](HTTP_DIGEST_PROXY.md)单独说明。其认证方式参与密文、运行中会话和后台恢复身份，旧版 0.6/0.7 会拒绝新的模式名。

0.6.0 在基础页、高级采集页和采集向导的“网络自动适配”中增加本机 HTTP / SOCKS5 认证代理。用户可直接输入代理地址、用户名和密码，明确同意后加密保存，不再需要为这个工作区设置进程环境变量。对应网络总项 #23/N5 和总控 #57。

## 操作

1. 停止当前采集并关闭已有采集会话，在“本工作区的代理”中选择“本机 HTTP Basic＋保存凭据”“本机 HTTP Digest＋保存凭据”或“本机 SOCKS5＋保存凭据”。
2. 填写可信的 loopback 入口（例如自己的 localhost 地址及端口），在独立字段输入代理用户名和密码。不要填写招聘账号密码或把凭据放进代理 URL。
3. 阅读并勾选本工作区加密保存说明，再保存。保存不连接代理或招聘网站；状态只显示是否配置，不回显用户名、密码或加密载荷。输入框在成功或失败后清空。
4. 新公开查询、CLI、后台工作和新浏览器会话使用原有统一策略。旧会话不会悄悄换身份，须停止并重开。环境中已有专用代理或凭据时明确拒绝冲突，不转交给新入口。
5. 修改凭据需重新输入并确认；过期页面不能覆盖新设置。点击“清除已保存凭据并停止新连接”会保留所选入口，但停止新连接，不降为匿名或直连。若希望回到自动或匿名代理，另行明确选择并保存。

HTTP Basic / SOCKS5 用户名密码仍采用原有1–255个可打印 ASCII 字符范围，用户名不能含冒号。目标公网地址、原主机 TLS、请求额度、代理拒绝后的停止行为以及已有匿名/环境变量/PAC/宿主机入口均保留。

## 保存与迁移

Windows 保存方式继续使用现有当前用户 DPAPI，额外上下文绑定工作区规范路径、协议和代理入口，不保存密钥；凭据和版本8网络偏好一次原子更新，失败保留旧值。状态 API 排除加密载荷。DPAPI 的账号范围、完整性与漫游例外见 [Microsoft CryptProtectData 文档](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。这不隔离同 Windows 账号下的其他程序，不承诺清除进程内存、浏览器内存或操作系统备份中的所有副本。

重启程序可恢复；已确认的每日计划和队列使用绑定加密副本的持久身份，不会仅因进程重启而暂停。运行中的浏览器继续使用进程内凭据绑定，修改凭据或入口仍会失效并要求重新确认。移动工作区、更换系统账号或代理入口后需重新输入。不能解密时停止所选路线，不改用其他网络。Linux/macOS 从0.12.0可使用系统默认密钥库，缺失或锁定时停止该入口；原匿名代理或应用环境配置保留，不把密文解释为明文。

Windows Basic/Digest/SOCKS5 网络偏好使用 schema 8，NTLMv2 使用11；POSIX认证凭据使用12。旧版0.5.1会拒绝，防止忽略凭据后匿名联网。仅查看状态不迁移格式。回退前先停止任务，在新版明确改回自动/匿名代理并保存为 schema 2，再按原工作区回退说明处理。单独清除凭据仍保持相应 schema 和停止状态。完整工作区备份可能包含旧密文；本功能不删除备份。保留原数据库、报告、个人材料、配额与Cookie格式。

## 验证和仍未完成的范围

定向回归验证跨工作区/入口/协议绑定、原子保存失败、修订冲突、清除、字段不回显、旧路由保留、真实 HTTP/SOCKS5 TLS 传输和实际 Windows 独立进程恢复。三个真实网页入口以及冻结程序的保存/重启/清除另有验收，具体结果以对应提交的 PR/CI 记录为准。

工作台与系统加密保存覆盖上述平台和四种认证方式；其他认证协议、代理端 DNS/socks5h、真实企业代理和 VPN/TUN 产品矩阵继续开放。本机人工代理不代表现场认证；正常账号登录仍由原专项处理。
