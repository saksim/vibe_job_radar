# 0.6.0：工作台配置与加密保存本机代理凭据

## 解决了什么

本机HTTP/SOCKS5认证原先只接受进程环境变量，工作台用户无法为单个工作区直接保存、修改或清除。现在三个工作台提供独立用户名/密码字段，明确同意后用当前Windows账号加密保存，并绑定工作区位置和具体入口。环境冲突、无法解密或清除后停止所选路线，不降为匿名或直连。

## 提高了什么

重启后可恢复原入口，修改后原会话按已有规则停止重开。输入框在成功或失败后清空，状态只显示是否保存；清除操作可在密文无法解密或当前系统不支持时执行。新格式使旧版本明确拒绝，已有匿名/环境/PAC/宿主机方式和自动升级、JD、原报告、团队功能保留。更新检查明确提示这类凭据问题。

## 验证结果

本机首轮47项中46项通过、1项新测试的SOCKS夹具取值错误；修正测试后该模块11项全部通过，原36项不重复运行。实际Windows独立Python进程恢复、真实本机HTTP/SOCKS5认证和原域名TLS通过。实际Edge三个网页入口保存/重载/改密/过期页面拒绝/清除通过，0外部浏览器请求、0页面错误。冻结程序增加同工作区保存、独立进程恢复和清除断言；本候选及准确main的CI/实际程序结果由对应PR和正式Release记录，不能预填。

## 剩余问题

仅Windows提供这项加密保存，原ASCII协议范围保持。其他认证协议、代理端DNS、其他系统发行及签名仍未完成；真实企业/VPN/设备、人工JD金标准、本人材料与生产主机域名要求单列。未宣称全部非登录完成或真实招聘登录通过。Windows包未签名；0.4.1及更早版本首次取得自动升级器需手动启动新版。

回退与迁移详见[工作区代理凭据](WORKSPACE_PROXY_CREDENTIALS.md)。清除当前凭据不清除旧备份；不得通过删除工作区、配额或Cookie恢复网络。
