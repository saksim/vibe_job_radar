# 明确使用语言模型审查代码

默认规则识别候选人使用、利用、运用或借助 AI/语言模型进行代码审查或代码评审的要求。模型到代码动作之间只允许已列明的辅助、执行与程度词，不按任意词距连接。要求从句首或同句明确的分隔处开始；模型产品名称后缀、代码审查产品开发和单独的模型知识不会因此成为工具使用能力。

原独立义务、否定、不要求、公司/福利标题与摘要规则保持。普通模型名不会被登记为专用编码产品；规则接受仍需人工复核，不是个人经历或能力认证。用户显式覆盖 `direct_patterns` 继续生效，规则配置及摘要随每份报告保存。

Issue #181 跟踪。人工例句覆盖明确使用、产品/知识误判、词边界、跨条款、负面要求、配置覆盖和旧报告保持；实际程序另验证原文位置、CSV和新进程重启后的同一报告。真实保存样本仅在本机对照，重新分析生成独立报告，不改原正文、采集时间或旧要求ID。

## 审查动作之后的边界

“使用Claude进行代码审查工作”表达审查活动，但“代码审查工作台开发”“代码审查流程设计”“代码审查工作流开发”不能仅凭其开头被认作相同活动。默认规则只接受完整的工作、任务、实践、流程、环节、工作流或工作流程词语，后面须到达条款边界或明确的连接词；不吞入后续产品开发词。原十项回归保持，另加产品复合词反例和正常活动词回归，实际便携程序的原四要求断言也包含三条产品开发反例。
