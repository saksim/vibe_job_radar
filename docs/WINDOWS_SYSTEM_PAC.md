# Windows 已配置 PAC：确认来源后按会话读取

Issue #135 承接 #23/N6，从统一候选 PR134 分出，尚未合并 main。它补齐“系统已明确配置 PAC 地址、但应用仍要求用户导出文件”的入口；不进行 WPAD 自动发现。手工导入固定副本仍见 [本地 PAC](WINDOWS_DOMAIN_PAC.md)。

首页、引导页、高级页的“网络自动适配”增加“使用 Windows 已配置的 PAC”。页面只读取当前 Windows 用户的配置，显示来源的 scheme/host/port，隐藏路径和参数。核对来源后单独勾选“信任现在和后续提供的脚本”，点击确认。保存不下载、不执行；实际新网络会话第一次选路才读取一次。也可点击“读取并检查系统脚本”，下载后对固定 `pac-check.invalid` 求值，不连接返回的代理或岗位网站。检查成功不代表登录或完整 JD 已通过。

“重新读取系统配置”清除页面上的旧勾选；多个页面保存共享原有修订号，旧页面的操作拒绝覆盖新设置。客户端只提交来源身份、修订号和许可，不接收 URL。来源地址发生任何变化，旧会话停止，新会话也不能直接沿用旧许可；刷新并重新核对后再确认。选择自动发现或固定代理并保存可撤销，原有报告、额度、手工 PAC 副本均保留。

## 来源、下载与会话

- 使用官方 [WinHttpGetIEProxyConfigForCurrentUser](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpgetieproxyconfigforcurrentuser) 读取当前活动连接配置，释放三个非空原生字符串。没有明确 URL（包括仅开启自动发现）、其他系统或 API 失败均返回固定说明。没有扫描代理端口、读取浏览器 profile 或改系统设置。
- 只接受最长 4096 字符的 ASCII HTTP(S) URL，无内嵌账号、片段、空白、控制字符或反斜线。路径与参数仅存在运行内存及读取该来源的请求中；不进入偏好、任务、诊断或日志。页面显示来源站点，不显示完整 URL。
- 来源读取为专用 bootstrap HTTP：直接连接一个已经解析并固定的数值地址，不经过 PAC 本身或自动静态代理，避免代理递归。不跟随跳转、不提交 Cookie、自动认证、环境代理凭据或第二个来源请求。响应只接受 200、完整 UTF-8（可含 BOM）、最多 64KiB；拒绝压缩、冲突长度、异常传输编码。HTTPS 使用原有证书链验证与来源主机 SNI，不关闭 TLS。
- PAC 来源可能是本机或公司内网，所以该专用来源读取允许公网、loopback、RFC1918 和 IPv6 ULA；拒绝未指定、多播、链路本地、映射/保留等其他地址及混合异常解析。此例外不进入岗位 URL 的验证器：采集目标仍必须通过原公网 IP、原主机 TLS、robots、授权来源和共享额度校验。
- 一次下载在应用自有 spawn 子进程内完成。8 秒总等待期限包括启动、DNS、TCP/TLS、响应头和正文；到期或撤销终止该子进程，随后有界回收。最多两个并行下载，不保留 URL 或响应异常文本。Windows TLS 的系统证书服务请求仍遵守 [现有证书说明](WINDOWS_CERTIFICATE_CHAIN.md)。
- 同一会话只读一次，下载错误也缓存；并发资源不各自重试。成功脚本在会话内冻结，不受同址后续内容变化影响；新会话可读取同一已许可地址的新脚本。这是“信任来源持续提供脚本”，不是文件摘要锁定；需要固定内容时应使用手工导入。
- 许可撤销、配置地址变化、凭据环境冲突、任务取消和浏览器关闭会阻止后续下载/求值/缓存使用/新连接。正在读取的来源进程在下一轮许可检查中停止；不把关闭当作撤回已经发出的字节。

下载后复用原 `PacSnapshot` 与 Windows 原生求值。脚本仅收到规范 HTTPS 域名根 URL 和域名，不得到岗位路径、搜索词、Cookie 或密码。原生 DNS helper 可能解析域名；这不是恶意脚本沙箱。完整保留原始 PAC 返回，验证全部指令，仅采用第一项：DIRECT、匿名本机 HTTP PROXY、明确 SOCKS5。未知指令、认证/远程代理或第一路线失败均停止，不隐式直连。每域名结果/错误缓存和 128 域名上限沿用原实现。

## 存储与兼容

网络偏好 v4 仅保存模式、来源 URL 的 SHA256 身份、随机许可标识及原修订/DNS字段；不写 URL、脚本或来源名称。策略标识绑定来源许可，不冒充下载内容的摘要，状态另标记“每会话冻结内容”。状态页、任务/队列/每日计划绑定只读取配置，不下载或执行。

v1/v2/v3 源码不认识 v4，会明确拒绝联网。回退前在新版本中撤销成自动或固定代理，保存为 v2，或切换成固定导入文件的 v3；再遵循 [工作区回退说明](WORKSPACE_COMPATIBILITY.md)。DNS单独保存保留来源许可；再次确认来源会更换许可标识，使旧会话失效，原队列/计划也须确认新绑定。

## 验收边界

单测使用人工本机 PAC 服务，真实 spawn 下载进程、Windows 原生脚本、原 HTTP/SOCKS5→验证 TLS→完整人工正文，覆盖默认离线、失败缓存、并发冻结、更新、认证/跳转/编码/大小拒绝、真实超时与撤销、地址边界、版本和两页面冲突。浏览器脚本替换的仅是系统配置来源；Windows Edge 使用真实下载和原生求值，Linux仅对原生求值使用夹具。默认本机测试不写个人系统代理或证书。

临时 Windows CI 另以 Edge 有头/无头经过原生 CONNECT 取得列表和完整人工 JD，代理拒绝后零目标请求。便携验收的独立 `--verify-system-pac` 参数只允许临时 CI：临时设置并最终恢复 HKCU `AutoConfigURL`，让实际 exe 用官方接口发现来源、自有冻结子进程下载与求值；同时验证独立冻结公开 worker 在相同策略下处理人工缓存而不额外下载 PAC。该 worker 缓存测试不冒充真实外网采集。CI 文件和实际结果以当前 PR head 为准，失败不得沿用旧 #110 证据。

仍未覆盖 WPAD、其他操作系统、全路径 PAC、代理 DNS、认证/企业远程 PAC 路线或真实企业 VPN 现场。系统配置服务自身须可直接访问；若只允许自动认证或跳转，此功能明确停止。猎聘 #63、BOSS/51job 规则及三站账号→完整 JD 的实站验收继续独立跟踪。
