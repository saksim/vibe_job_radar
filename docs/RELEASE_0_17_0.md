# 0.17.0：单拥有者服务器工作台与应用层拆分

基于正式 0.16.0，按 dev→release→main 晋升；正式交付以通过验收的 Tag 和附件为准。

## 解决了什么

- [#502](https://github.com/saksim/vibe_job_radar/issues/502)：将服务创建、任务生命周期和升级协调移入 WorkbenchApplication，将 HTTP 路由、业务调用和响应移入无 socket 的 WorkbenchHTTP。桌面入口保留原来源校验、令牌、请求边界及升级链路。
- 新增独立单拥有者服务器入口 vibe-radar-web：密码文件登录、HttpOnly/SameSite 会话、精确来源、请求令牌、8 小时会话期限、登出/重启撤销和有界登录限速。私有页面、脚本、报告、附件和 API 均受会话保护。
- 新增非 root Dockerfile、只读根目录 Compose、完整工作区持久卷、健康检查和 HTTPS 反向代理示例。服务器公开采集、导入、分析、证据、质量和报告复用原业务代码。
- 服务器明确拒绝桌面浏览器/登录接管、浏览器转交、Windows 开机启动、桌面包下载安装和宿主配置修改；原桌面功能保留。

## 提高了什么

桌面和服务器入口共用业务契约，后续页面调整不再要求复制一套采集、配额或报告实现。上传材料在服务器处理，报告通过原下载接口取回；升级容器保留完整工作区。此版本没有宣称更高并发吞吐或多用户数据隔离。

## 验证结果

- 28 项应用/桌面定向回归通过（3.570 秒）：原 HTTP 与安全边界、响应前释放锁、升级协调、幂等关闭、无 socket 导入与报告链路。
- 11 项服务器定向测试通过（17.565 秒）：匿名拒绝、Host/Origin/CSRF、会话过期/登出/轮换、限速、能力边界，以及真实业务代码上传→分析→原报告下载。前端隔离修复后仅补验对应一项，通过（2.313 秒）。
- 独立静态复核确认原 Handler 安全边界、启动/升级 main 的 AST 和公开静态路由集合保持一致。
- 首个候选浏览器 CI 发现一个旧验收夹具仍向 workbench.GuidedService 注入账本，拆分后触发 AttributeError。仅将夹具注入点迁到 application，保持全部断言与期限；对应真实 Edge 配额页面五项验收通过，外部请求/变更请求/JS异常均为0。原失败保留，新提交重新取得资格，不重跑旧作业求绿。
- 后续候选浏览器 CI 又定位到挂起响应夹具只识别 dict，而共享 HTTP 层现在传递已序列化 bytes，导致夹具没有扣住预期的采集响应。仅让夹具解析观察值并保留原响应，维持所有等待期限与状态断言；对应真实 Edge 挂起响应场景五项验收通过，页面异常为0，采集响应挂起期间登录按钮保持禁用，释放后首个登录请求成功且两条 JD 进入原报告。原失败保留，新提交重新取得资格。
- Python 发行相邻门槛 2 项通过（0.081 秒）；安装验证已补查服务器命令入口及三个静态资源。
- 实际 Windows Waitress 3.0.2：一次 HTTP 验收 34/34，通过人工 JD 导入、分析、原报告下载与登出失效。使用现成 Edge 的页面验收 17/17，JS 异常和失败请求均为 0；服务、浏览器与端口均已清理。Ctrl+C 终端包装返回 1，未单独采集子进程退出码，不能将其写成退出码 0。
- Linux Docker 实测 53 项通过：非 root、只读根、无新增权限、健康检查、登录、人工 JD→原报告→下载。最终镜像为 0.17.0 / Python 3.12.14 / Waitress 3.0.2；重建复用同卷后旧会话拒绝，记录、报告 manifest 和文件摘要保留，两次停止均 exit 0。
- Compose 本机与 HTTPS 两种配置静态解析通过；实际公网 HTTPS/反向代理尚未部署验证。测试使用独立数据卷，无真实岗位采集或用户资料；镜像未发布到容器注册表。
- 候选与准确 main 的必要 CI、正式 Tag/附件仍由发布流程核验，本地不重复完整矩阵。

## 剩余问题

服务器第一期是一个拥有者、一个工作区、一个进程；没有多人账号/数据隔离、远程招聘登录协助或容器注册表正式镜像发布。高级非分类采集仍由页面逐步推进，后续需保留许可/配额/所有权语义迁入后台。当前 Docker 依赖仅 service，不含桌面浏览器和系统密钥环。

真实生产主机、域名、TLS、出口网络及备份恢复仍需实际部署验收。历史18项问题与 #183/#263/#269/#436 根因调查不因架构拆分自动关闭；既有条件见 [0.16.0 问题范围](ISSUE_SCOPE_0_16_0.md)。#210/#320保持只读。无 Windows/Apple 签名凭据，桌面发行仍如实标示 unsigned / unnotarized。
