# 猎聘当前搜索页依赖验证（2026-09-23，PR62）

关联 #45、#49、#50，新确认的实站卡点单独记录于 [Issue #63](https://github.com/saksim/vibe_job_radar/issues/63)。目标仍是原关键词的一页真实列表、一个完整真实 JD 和同批报告。本记录不能作为该目标已通过的证据。

## 判断与改动

当前公开 `/zhaopin/` 使用异步加载的界面。实际原生浏览器观察到，营销和统计 XHR 被当作未知业务请求后会中止整个搜索任务；只有允许的静态脚本仍不足以完成初始化。

- 精确识别 `api-wanda.liepin.com` 的营销展示/统计，以及 `statistic.liepin.com/statisticPlatform/standardFLog.json`。这些请求在本机直接终止，域名不进入隧道许可，不发请求；诊断标记为可选依赖，不把它们当作正文失败。
- 补充 `feim.liepin.com/lp-manifest.json` 的 GET、其公开加载器使用的 `/lp-manifest.js`，以及 `concat.lietou-static.com/fe-im-pc/v6/` 静态资源。它们是搜索页使用的共享界面依赖，不赋予聊天、消息或任意接口访问权限。
- 补充已观察到的 `/api/com.liepin.searchfront4c.pc-search-job-cond-init` POST/OPTIONS，只读取筛选项。沿用搜索 API 的固定页面 Origin、预检检查、robots 和配额；它的响应不能成为岗位卡片。

未知业务请求仍停止。平台拒绝、验证码、登录错误不作为可选依赖忽略。未修改浏览器身份、网络出口或平台脚本。

## 新确认的实站卡点：主页面跳转为空白

补齐官方实际预检中的 `x-fscp-fe-version`、`x-fscp-bi-stat` 和 `x-xsrf-token` 名称后，再用产品默认的可见 Edge 153 验证：

- 主页面正常到达 `https://www.liepin.com/zhaopin/`，产生筛选初始化和搜索的 OPTIONS。没有人工构造或重放业务 POST。
- 随后同一个**主框架**导航到 `about:blank`；这与被 CSP 阻止的页脚子框架 `chrome-error://chromewebdata/` 是两个独立事件。
- 没有输入账号、提交登录或执行页面清空代码。诊断现报 `native_page_cleared`，清除旧业务观察并停止，不把空白页当作零岗位，不自动再次导航。
- 实际计数：文档 1、业务预检 2、静态资源 19、robots 3、登录 0；尚无业务 POST 成功、真实列表或完整 JD。

官方页面引用的 `https://concat.lietou-static.com/fe-lib-pc/v6/security/1.0.0/security.min.js` 包含检测开发者工具后导航到 `about:blank` 的保护逻辑。它与上述现象吻合，**但仅凭页面事件不能确定该次触发的内部检测条件**。没有关闭、改写或规避该脚本，也没有修改 webdriver/UA、替换身份或出口。

先前部分 `Invalid InterceptionId` 发生在页面离开后，不能据此统一诊断为控制器故障。新逻辑只报告已观察到的主页面清空；其他协议失败仍按原逻辑停止。初始空白页、robots 临时页、页脚子框架和普通 SPA 地址变化不会触发该结果。
