# 0.14.1 发行说明

## 解决了什么

- #415：任务续租、业务账本与团队面板使用不同连接对象时，同一工作区的请求可能重叠并触发自身限流。
- #416：团队服务返回 Retry-After: 1 时，客户端误套用网站冷却规则，提示等待300秒。

## 提高了什么

同进程、同工作区的团队连接共用请求队列；上一响应完成后才开始下一请求的间隔计算。凭据在排队结束后重新核对，失败释放队列且不自动重发。不同工作区互不占用队列，租约仍按包含排队时间的原有效期限判断。

仅已配置团队服务的传输使用至少1秒的等待下限，并保留服务要求的更长等待；无效值继续保守处理。招聘站点、公开目录和升级下载的原300秒下限、持久配额、撤销权限、TLS核验和失败停止行为保留。

Windows/Linux/macOS升级、签名接入、采集、完整JD、原报告与离线缓存均保留。

## 验证结果

在0.14.0准确main复现两请求进入传输、一次限流，以及1秒被解析成300秒；原始结果保留。定向回归涵盖真实本机HTTP续租与查询、工作区隔离、失败后释放、凭据变更拒绝、服务/网站不同等待口径。具体数量、准确提交和完整CI结果以配对PR及正式Release为准，不重复本机全量测试。

## 剩余问题

本机请求协调的范围是同一进程、同一工作区；真实跨设备或多进程仍由原中央服务配额、租约和明确限流结果协调，不宣称已完成生产多设备验收。

[原24项逐项清单](OPEN_ISSUES_2026_10_18.md)继续保留真实网络/净机/生产主机域名、真实JD与人工标注、本人材料和历史未知故障的条件。Windows无签名凭据，本版仍unsigned；macOS签名与公证另需账户。不得将本轮两项工程修复计作全部非登录目标已完成。
