# 检查稳定版与准备 Windows 升级

关联 #356。首页“版本与升级”提供显式检查与下载，沿用当前工作区网络偏好。启动程序、打开面板和读取状态不会联网；点击“检查稳定版”后才访问官方 saksim/vibe_job_radar GitHub 仓库，不发送岗位、私人报告、个人材料或团队凭据。

## 使用步骤

1. 点击“检查稳定版”，核对当前版本、最新稳定版及四段变更说明。只接受标准 v主.次.补丁 稳定渠道，不将草稿或预发行当成升级，不自动降级。
2. 点击“下载并准备新版”。程序核对8个资产、来源提交、原 CI 记录、SHA-256 和包内版本，再下载 ZIP，解压到当前工作区 updates 下的独立目录。页面显示完成路径。已有同名但不一致的文件会保留并报错，绝不覆盖。
3. 停止任务、队列及每日计划，关闭旧登录启动登记和所有使用该工作区的程序，备份完整工作区。再从显示的新目录运行 VibeJobRadar.exe，继续选择原工作区；按需从新版重新启用登录启动和计划。
4. 保留旧程序与对应完整备份。回退前关闭新版，核对[工作区兼容](WORKSPACE_COMPATIBILITY.md)、[网络偏好](WORKSPACE_PROXY_SETTINGS.md)和[团队服务库升级](TEAM_SERVICE.md)，不要删除配额或凭据以绕过错误。

## 校验、失败和范围

下载超时、哈希不符、外部跳转、非本仓库资产、异常 ZIP 路径/链接/重复名称或解压超限时明确失败。普通失败清理本次临时下载及不完整解压目录；退出中止后原程序和工作区保持原样。异常断电可能留下 .partial 或没有 READY.json 的暂存目录；停止程序后核对再处理，不要执行其中的程序。已校验 ZIP 可以保留并复用。程序不会执行下载文件、替换当前运行程序、迁移工作区或自动重启。

当前合同是未签名 Windows x64 包。GitHub HTTPS、资产摘要和来源清单说明文件一致性，不是代码签名，也不代替干净个人机器、真实账号或全部安全软件的现场验收。稳定渠道只是选择经过项目规定 CI 的公开版本；签名证书、自动替换/重启、其他系统包继续独立跟踪。源码启动与手工从 Release 下载始终保留。

生产服务与本机程序分别升级；不要把 Windows 客户端升级视为 Linux 服务已部署。若没有最新稳定版、官方接口限流、网络不可用或磁盘不足，保留原程序并检查发行页与网络后重试，不要降低 TLS 或摘要检查。
