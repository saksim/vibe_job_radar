# 稳定版检查与 Windows 自动升级

关联 #23、#30 H6、#356。首页“版本与升级”沿用当前工作区网络偏好。启动程序、打开面板和读取升级记录不会联网；点击检查后才访问官方 saksim/vibe_job_radar GitHub 仓库，不发送岗位、私人报告、个人材料或团队凭据。

## 大包中断与断点续传（0.7.1）

下载 ZIP 断网、超时或工作台退出时，保留当前官方资产的未完成前缀；它仍是未校验数据，不会解压或安装。再次启动后先点击“检查稳定版”，再确认下载或自动升级。同一发行ID、资产ID、大小和完整SHA256才使用同一前缀，旧版本/其他资产的残留不会拼接。自动升级仍须独立同意、停止其他任务、备份和等待新版就绪。

按 [HTTP Range 语义](https://www.rfc-editor.org/rfc/rfc9110.html#name-range) 请求剩余部分，只接收起止与总长完全匹配的单段206；服务器忽略Range而返回200时，用独立临时文件接收这一次完整响应，在完整校验通过前保留原前缀，不自动发第二次请求。该回退最多同时占用原前缀加一份完整包的空间，失败时清理本次临时文件。每次从官方资产入口重新取得跳转，不保存临时签名地址；原代理/PAC、公网目标、TLS、四次跳转上限与单次15分钟期限保持。完整SHA256始终重新核验；部分字节没有单独认证，不等于可信程序。若字节已收齐但随后超时，下次确认可先在本地核验，无需再次下载。

异常范围、压缩、多段、整包损坏会拒绝并清理本次拥有的前缀，需重新检查后再次确认；网络失败保留有界前缀。下载互斥使用操作系统锁，第二工作台不会并发修改。断电造成的磁盘字节损坏仍会在完整摘要阶段被拒绝，不承诺所有中断均可恢复。残留位于工作区updates的 `.resume-*.partial`，每份不超过原包大小/1GiB；旧版本前缀保留供核对，停止全部实例后可自行删除这些下载缓存，不要删除个人工作区或备份。旧程序不因发布Tag自动获得续传能力，须先运行0.7.1或以后版本。

## 使用步骤

检查遇到网络中断时，可在当前工作台中稍后再次明确点击检查。0.5.1起最多保留7份、合计不超过7MB的已核验小文件，只在本次会话内使用；每次仍先获取官方Latest清单，只有摘要和长度一致才复用，全部发行关系仍重新校验。退出工作台后缓存消失，不保存过期DNS回答，不自动重试或换路。页面会区分DNS连接失败、解析过期和PAC执行/清理失败。

0.7.1另区分系统DNS失败与目标解析为非公网地址，并指向“网络自动适配”的现有说明。非公网拒绝可能来自VPN映射，也可能是真实私网/混合回答；不能据此认定某个VPN产品故障或自动启用其他解析方式。需按原网络设置明确选择并确认，目标公网限制与TLS保持。

1. 点击“检查稳定版”，核对当前版本、最新稳定版和四段变更说明。只接受标准 v主.次.补丁 稳定渠道，不选择草稿、预发行或降级。
2. 可继续点击“下载并准备新版”，核对8个资产、来源提交、CI记录、SHA-256和包内版本，解压到工作区 updates 中的独立目录，然后手动启动。
3. 从0.5.0起，Windows便携包也可单独勾选自动升级确认，再点击“备份并自动升级”。先停止采集并关闭采集浏览器、其他工作台和独立 worker；当前实例有活动采集或团队同步时会拒绝升级。
4. 自动流程复用已校验ZIP，重新解压并核对全部程序和依赖，运行新版离线启动检查。随后关闭当前工作台，取得任务拥有锁，备份原工作区，再启动新版。新版绑定本机端口并确认就绪后才提交当前版本；未完成交接前不启动计划或队列。
5. 新版继续使用原工作区。原0.5.0及之后的便携入口会跟随已提交的新版本，原 Windows 登录启动命令及回执保持不变；请保留原入口目录。手动移动目录仍按[登录启动说明](WINDOWS_LOGIN_STARTUP.md)重新登记。

**0.4.1及更早版本首次取得自动升级器仍需手动启动新版。** 旧进程不会自动获得尚未运行的新代码。自动交接只接受带 upgrade_protocol=1 的后续便携包；源码启动、手工从 Release 下载和原手动准备入口均保留。

## 备份、失败和恢复

备份位于工作区 updates/backup-*，保留工作区普通文件和空目录，包含SQLite及已提交WAL内容；只排除下载/安装缓存 updates、已持有的运行锁标记和可重建的SQLite SHM索引。备份元数据在 BACKUP.json，用户同名文件保留在 workspace 子目录中。上限5GiB、50000文件、2分钟复制期限；拒绝链接/重解析点、空间不足和复制期间变化，原数据保留。超过上限请手动备份升级，不删除资料来绕过检查。

升级记录在 updates/install-*/，当前选择在 updates/current.json。首页会显示上次交接状态和备份路径。超时、验证失败或新版未就绪时不提交入口、不改写原程序、不用旧备份自动覆盖当前数据；失败可能发生在新版已读取/迁移工作区之后，因此也不会盲目重启旧程序。旧目录、已校验ZIP和已完成备份保留供核对。

断电可能留下未完成记录或暂存目录；未提交的安装不会由原入口自动采用。恢复前关闭所有实例，核对[工作区兼容](WORKSPACE_COMPATIBILITY.md)与[团队服务库升级](TEAM_SERVICE.md)。可用原程序的 --ignore-installed-update 参数跳过入口转发进行恢复；若需回退已迁移的数据，请先另存当前完整工作区，再从匹配版本的备份恢复。不要删除配额、凭据或无关文件。

下载超时、摘要不符、外部跳转、非官方资产、异常ZIP路径/链接/重复名称或超限会失败。0.7.1起网络中断保留未完成前缀，核验失败清理本次拥有的前缀；不完整解压目录仍只清理本次拥有的目录。0.4.1的Windows长路径处理保留，不改系统注册表；外部文件管理器的路径能力可能不同，安装位置仍建议简短。

## 验证与剩余范围

本地测试覆盖授权、繁忙拒绝、备份/WAL、损坏包、就绪交接、失败保留和启动登记归属。Edge验收使用人工元数据和不执行的测试包；Windows候选构建额外使用同一真实编译包启动两个进程，验证备份、退出、就绪、提交和新版HTTP服务。该检查是同构建进程交接，不冒称跨历史版本现场升级。

当前是未签名Windows x64发行。GitHub HTTPS、摘要和来源记录说明文件一致性，不是代码签名。签名证书、其他系统发行、干净个人机器、真实安全软件和跨历史版本现场验收继续单独跟踪。生产Linux服务另行升级；用户尚未提供生产主机和域名，本机升级不代表服务已部署。
