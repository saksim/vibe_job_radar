# 0.7.1：升级大包断点续传

## 解决了什么

[#378](https://github.com/saksim/vibe_job_radar/issues/378)补齐官方升级ZIP中断后必须重下的问题。可在重新检查并确认后接续，跨工作台/进程重启保留前缀；手动准备和Windows自动升级共用。

## 提高了什么

严格绑定发行资产身份和完整摘要，验证206范围，200完整响应从零接收，拒绝多段/错误编码/损坏包；跨进程下载锁防止并发覆盖。旧网络策略、完整核验、备份/就绪交接、Python分发与原业务功能保留。

下载网络失败区分系统DNS异常与非公网解析。Chrome原生控制命令确实达到期限时，启动界面明确显示超时；普通协议拒绝仍单独失败。原期限与停止规则保持，底层浏览器无响应的原因继续由[#263](https://github.com/saksim/vibe_job_radar/issues/263)跟踪。

## 验证结果

定向测试及真实本机HTTP中断/独立进程接续、真实网页提示已纳入验收；当前提交、完整主干和正式Tag结果以对应PR/Release实际证据为准，不预填通过。旧失败须保留，不把受控网络当作企业现场认证。

## 剩余问题

已下载前缀未经单独认证，完整SHA256通过前不会安装；磁盘损坏可能要求重新下载。旧程序需先运行新版才获得续传。签名、其他代理协议、真实网络/干净机器、人工JD/本人材料与生产主机域名条件继续单列，详见[升级说明](UPDATES.md)。
