# PR62：开发侧完成工程验收后，再交付用户测试

## 合并前检查

不将用户反复本机陪测作为修复程序错误、通过 CI 或复跑受控测试的前置条件。当前同一提交必须完成完整回归、原工作台流程、独立 Edge 检查、四组原生采集和搜索测试。失败保留，不能拿旧提交绿色替代；不自动合并或关闭真实数据目标。

## 本轮交付范围

仅修正独立 Edge 工作台启动验收：一次导航等待 DOMContentLoaded，再要求 HTTP 200、原页面 JavaScript 经鉴权接口实际填充记录数、URL 中认证片段已移除、导航入口可见。只有 HTTP 成功但界面未初始化仍失败。导航错误不重试、不吞掉，不延长导航超时，也不删掉后续 Edge 选择、重启及原反例。

每次运行额外使用第二个独立浏览器上下文验证冷启动；任一次失败即整项失败，并非失败后自动重试。两个上下文都只访问本机工作台，不访问招聘站点，不共享浏览器缓存或 sessionStorage。

失败证据只保留固定阶段、固定本地路径类别和状态码；不输出导航异常中含有的本地 #token。历史 Page.goto 等待 load 超时的根因仍未唯一证明，新的成功只能证明修改后本次完整验收通过，不能抹去原失败。

参考 Playwright 官方导航文档：https://playwright.dev/python/docs/navigations 。页面 load 是全资源加载事件，不等于应用鉴权和交互就绪。

## 不混淆的登录能力

当前 PR 已有的公开搜索响应、所选详情登录返回和保存会话机制保持原样。公开可读内容不必先提供密码；平台明确要求本人登录/扫码/短信/验证时，操作限于本机平台窗口。Cookie 存在不证明账户有效。没有在本轮新增真实平台自动填密或 SSO 接口。

代码审查发现的隐藏登录模板误判修改因发布工具安全检查拦截而撤出本次提交，未转用其他接口发送，也不计入已交付功能或最终测试源码。当前生产访问/挑战判断完全保持原先实现。

工程全绿不等于真实猎聘账户和当前站点均已验证，#49/G1 与 #50 的完整实站目标保留。无需用户现在提供密码、短信码、Cookie、完整 HAR 或 `.radar-sessions`，也不再要求用户先手动复跑 CI 再处理研发。
