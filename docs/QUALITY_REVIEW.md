# 独立质量标注与评估

Refs #217 / #210 G03。用于内部质量核查：从一个既有报告离线生成新检查包，以独立标注检查原输出。它不联网、不重新提取/分类/去重，不改原报告、业务复核和本人材料。助手草稿不能充当人工金标准。

## 生成和使用

在源码环境运行以下命令（将路径替换为实际目录，PYTHONPATH 指向 src）。检查包和评分文件都必须是新路径，且位于原报告目录之外。

    python -m vibe_job_radar quality-pack --report path/to/original-report --out path/to/new-packet
    python -m vibe_job_radar quality-evaluate --packet path/to/new-packet --out path/to/new-score.json

可用 --annotations 指定另存的标注版本；默认读取包内 annotations.json。命令输出统计摘要，不在控制台打印JD或标注内容。评估结果中的 annotations_sha256 将本次结果绑定到精确标注字节。

先读 REVIEW_PROTOCOL.txt 和 documents.txt 的完整正文，再独立填写 annotations.json。predictions.json 是原报告预测，用于对照和定位错误，不能直接复制为标准答案。corpus.json 保存精确正文与评估范围；labels.json 固定原报告的能力和岗位目录；source.json 记录原报告来源、哈希、规则版本、模式、筛选与统计；packet_manifest.json 绑定这些不可编辑文件。文件哈希用于发现意外改变，不是身份认证或数字签名。

必须保留每份记录的空白行和包ID，不删除未核查文档；新建标注版本时复制整份标注文件。草稿/人工确认必须填写 author、带时区的 reviewed_at。human_confirmed 是填写者对真人确认的声明；工具不会判断操作者身份，助手不得自动作此声明。roles=null 表示岗位分类未核查，roles=[] 表示明确不属于配置方向。

requirements_complete=true 需要整篇逐段检查并独立补齐所有适用能力要求；明确没有要求也必须这样确认。条目使用原文 Unicode 码点的 start（含）/end（不含）及逐字 quote，不使用字节或UTF-16偏移。允许新增原预测漏掉的要求。同一位置、同一能力不可重复或冲突；未知字段/标签、错包、坏偏移、缺少记录、重复文档对均拒绝。

详细语义、强度、否定、边界与岗位标注规则在生成的协议中。原始JD只以JSON和纯文本输出，不生成可执行HTML/Markdown页面。真人终审、标注一致性及验收阈值仍需另行完成；生成工具不会自动完成G03。

## 分母与指标

| 项目 | 入选范围 | 计算和未知值 |
|---|---|---|
| 抽取位置与能力 | 真人确认且整篇完成、原selected、完整正文、同真实/演示模式、原去重代表记录 | 精确位置+能力的一对一TP/FP/FN、precision/recall/F1；边界差一个码点算FP和FN |
| 语义 | 同上 | 额外精确匹配relation与strength；原输出的待复核/拒绝行也列入此原输出检查 |
| 已接收正向AI | 同上 | 原规则接收或人工批准且direct/contextual、非否定行，对照独立正向AI标签；仍要求精确语义 |
| 否定 | 同上 | 对齐负向金标签的强度正确数/分母；另列漏抽负向、无对应负向金标签的预测、两种负向强度混淆 |
| 岗位分类 | 真人确认且roles已填写；同模式、所选平台的完整快照，包括原未匹配与过期项 | 多标签逐方向/micro TP/FP/FN、整份标签完全一致率；只算原声明方向，原已知重复组只计代表 |
| 去重 | 主动声明且真人确认的文档对；双方均有原selected完整正文分组 | same_job为正类的TP/FP/FN，另列已评对数与正确数；未选/摘要对为不可比较 |

任一比率分母为0就保留null；没有真人标注时所有质量比率未知，不输出100%或虚假0%。待核查、助手草稿、部分标注、已完成却范围不适用的数量分别列出。roles可独立于全文要求确认。

抽取指标不包含原筛选漏掉的文档，不能代替端到端召回率。岗位分类按保存快照核查，不代表当下在招；未选记录没有原去重分组时不做新合并推断。多角色分母不可简单相加。少数主动选中的去重对不能代表全库。原报告可能已有业务人工复核，因此这里测的是对应报告输出，不能自动标为纯规则引擎质量。

## 历史一致性与失败

先逐字节核验原 run_manifest 对 jobs、requirements、input_audit、duplicate_groups、effective_config 的哈希，再校验记录/偏移/分组与统计一致性。旧报告没有 audit job_group_id 时，只使用保存的完整 duplicate_groups，剩余selected记录作为独立单例；不调用当前分类器或指纹重新解释历史。原重复成员与代表必须完整且无重叠，预测偏移只适用于其原代表。

源文件、标签、偏移或数量不一致时，不创建包目录。写入途中出错时，保留部分文件且没有完成清单；评估拒绝这种包。现有路径不可覆盖，新评估也必须另存。真实正文、助手草稿与人工标注留本机；GitHub只应提交代码、人工合成夹具和汇总结果。

## 验证范围

合成回归覆盖空分母、独立漏抽、否定错误、严格Unicode边界、完整性门槛、待复核/拒绝预测、方向多标签、重复来源/文档对、未知/冲突输入、旧分组、不可变性及原管线/CLI离线路径。合成夹具中的“人工确认”字段只是边界测试，不是实际人工评审。

旧分支记录的89份原报告、9份助手初查（5份AI证据岗位、4份算法岗位）属于当时本机历史材料：0份真人确认，质量指标未知。94条原预测或24条规则接收不是金标准。本次整合没有重新读取或标注这些私人正文；只运行独立合成回归和离线CLI人工夹具。

当前只整合旧 PR #218 六文件净范围。CLI 新增两个独立命令，其他命令、原报告、规则配置、登录和采集行为保持。缺少真人终审的 G03 仍单列；不自动把助手输出改成人工确认。
