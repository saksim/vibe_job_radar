# 本机 Cookie 会话恢复（D04，部分实现）

目标是“已正常登录一次后，重启程序仍能尝试继续读取岗位”，而不是每次重新登录。此改动不声称真实猎聘登录/搜索/详情依赖已经适配；#49 的真实完整 JD 门槛和 #50 的完整登录目标继续保持开放。

## 使用

在 `/guided` 第 2 步勾选“在此工作区本机保留该平台 Cookie 会话”，然后正常搜索。需要登录时仍在平台原生窗口完成登录/扫码/短信/验证；取得可读列表或完成正文采集后，程序才保存本站 Cookie。可与已合并的“登录返回后自动继续”配合。

退出并重新启动工作台后，为新任务再次明确选择本机保留。同一工作区、平台适配版本、后端、浏览器选择、网络策略匹配时，Cookie 在新浏览器打开第一个页面之前恢复。仍正常执行站点规则、配额、TLS 和请求检查；不因恢复失败切身份、网络或重试登录。`restored_session_unverified` / `saved_unverified` 只表示 Cookie 的恢复/保存，不是账号认证证据。实际登录有效性仍取决于平台正常响应。

“停止并关闭登录会话”关闭当前采集浏览器，但保留已明确同意保存的快照。“清除此平台保存的会话并关闭采集浏览器”才删除本工作区该平台快照，并撤销其旧任务的保存选项，不删除岗位、正文、报告、个人证据和配额。其他工作区不受影响。

快照超过七天不再使用，并在下次尝试读取、验证成功后清理；这不是后台自动删除服务。保存和恢复时也按 Cookie 自身的过期时间逐条过滤，不延长有效期；没有固定到期时间的会话 Cookie（expires=-1）保持原语义。如果全部过期、为空或不属于已声明域名，则在验证已有快照成功后删除本平台旧快照并显示“本机尚无保存会话”，不再标为已恢复。保留用户的保存偏好，正常重新登录、取得可读列表后可更新快照；岗位、报告和配额不变。部分 Cookie 尚未过期也不能证明账号有效，网站要求重新验证时仍按正常流程完成。

## 保存内容和保护

只保存应用自有浏览器上下文中、平台声明域名下的普通 Cookie；不读取日常浏览器，不读取/存储表单密码，不保存 DOM、截图、localStorage、IndexedDB、sessionStorage、分区 Cookie 或其他平台 Cookie。依赖这些未覆盖存储方式的登录可能无法恢复，不能宣称所有平台都已支持。导出使用浏览器 Cookie API，不创建临时页面、不会为快照发送 HTTP 请求。

文件只位于所选工作区的 `.radar-sessions`，不接受用户指定的任意存储路径。Windows 使用当前用户 DPAPI 加密，不存自建密钥；Linux/macOS 使用 0700 目录与 0600 文件，**不加密**。Base64 只是文件编码，不是加密。快照等价于敏感登录资料，不应分享、提交 Git、同步公共目录或放入数据导入路径；同一系统用户运行的恶意软件仍可能取得登录资料。`.gitignore` 排除该目录，源码打包与输入发现也拒绝其中内容。没有新生产依赖、密码库、云端同步或上传动作。

文件锁由操作系统持有，进程退出后自动释放；第二个进程不能并发恢复/覆盖同平台会话。符号链接、Windows reparse points、硬链接以及宽松的 POSIX 权限被拒绝。写入先生成私有临时文件、刷新后原子替换，避免半写入覆盖有效快照。损坏、解密失败、绑定不匹配都显示固定原因，不输出 Cookie 内容。保存失败不会回滚已经取得的岗位和报告。

## Windows认证代理快照v2

在原有保存选项下，Windows明确配置的本机HTTP/SOCKS5认证代理使用v2；无需新的保存选项。每次启动都由调用者重新提供代理凭据。公开网络策略ID继续使用原进程随机绑定；私有快照另绑定完整网络上下文和原有工作区、平台、适配版本、后端、浏览器。用户名/密码与该上下文通过独立用途的HMAC派生DPAPI附加熵，派生值仅在内存中使用，不写入文件、任务、诊断或报告。Windows仍使用当前用户DPAPI，未启用机器共享或交互提示；不承诺清除Python运行时所有秘密内存副本，也不额外承诺无法随Windows漫游用户配置恢复。

v2加密载荷严格只有Cookie和保存时间，公开保存时间必须与解密结果一致。没有保存代理密码、密码验证器、nonce或自建进程密钥。改变代理用户名/密码会导致解密失败；改变代理协议、地址、端口、DNS偏好、旁路或其他已绑定上下文会拒绝恢复。DPAPI错误不用于断言具体损坏/凭据/系统原因，用户应先核对原Windows账号、代理凭据和配置；清除只能是明确操作。

所有当前版本实例（包括匿名/v1）在自动更新或删除已有快照前都先校验版本、绑定、保护方式及载荷。Windows解密先于到期删除；空Cookie、过滤后为空或新Cookie覆盖也不能丢弃损坏/不匹配的旧文件。显式“清除此平台保存的会话”不需要解密，仍只作用于该平台、该工作区，不改岗位、报告或账本。保存失败继续保留已采集结果。

匿名v1保持读写兼容；旧认证代理v1与v2明确不兼容，不静默迁移。Linux/macOS仍为未加密owner-only v1，认证代理重启后的限制未被放宽。回退前停止服务，需要舍弃v2时先在当前版本明确清除，避免旧程序写入不识别的格式。

## 验证与仍未覆盖

定向测试使用非真实 Cookie，包含跨进程恢复/互斥、过期、损坏、绑定冲突、取消、清除、旧任务撤销、保存失败和无秘密状态返回。完整工作台测试扩展为“正常人工测试登录 → 原报告 → 关闭旧服务/浏览器 → 新服务/新浏览器恢复 → 无新增登录 POST 的正文到报告 → 清除”。四组 native 测试验证恢复的 Cookie 出现在**首个文档请求**，不是进入页面后临时塞入。

上述自动测试均为人工上游，不替代真实招聘站点认证。当前程序另有猎聘[明确授权的单次正常密码表单](LIEPIN_PASSWORD_LOGIN.md)和[本次程序内的会话复用](IN_PROCESS_SESSION_REUSE.md)，与本页的跨进程 Cookie 保留是不同选项。恢复 Cookie 不会自动填写或重试密码；只有在第 3 步另行授权本次提交，才启用密码表单。条款未勾选时，须本人在猎聘页面勾选后再点击“登录”；图形验证、短信和扫码继续由本人完成。

普通关键词查询与完整正文已有[独立实站记录](CURRENT_ACQUISITION_EVIDENCE.md)，不能据此认定账号有效。真实账号登录成功、有效/过期会话恢复及同任务正文到报告的认证链路，仍按 #49/#50/#54 的原条件验收。localStorage/IndexedDB 型会话尚不支持。默认保留关闭，旧任务的内存会话和已有报告路径保持兼容。
