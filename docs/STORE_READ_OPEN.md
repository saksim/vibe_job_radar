## 新库初始化的事务与异常关闭

PR254 首次 Windows 3.12 回归出现原5秒等待失败，失败瞬间线程位于新建批次 Store 的 executescript，测试主体尚未开始。首次日志、任务阶段和原断言保留；这个栈不能证明数据库初始化解释了全部等待。

独立复核旧196中的 d6239d9：原新库的四条 CREATE 与版本写入未在同一显式事务内，后续建表或版本标记失败会留下部分结构；构造函数未完成时也未进入上下文管理器，原连接无法依赖 __exit__ 清理。这是可以确定性复现的独立缺陷。

版本0改为先取得 BEGIN IMMEDIATE，重新读取并检查版本，再将结构与版本标记作为一次事务提交；失败或中断时关闭连接并回滚。版本1保留原补建规则，不新增初始化写锁或重复版本写入。WAL、同步级别FULL、外键、30秒数据库等待及测试原5秒时限保持。
