# 猎聘网络失败归属与首次匿名搜索（2026-10-28，#531）

## 2026-10-29：连接握手期间的关闭缺陷与错误串用

从最新 dev `4940071`（PR #544）继续，只处理 #531 尚未归因的旧网络/退出异常。#544 最终 35 项既有 CI 全部成功；本轮不重复 60 秒匿名页面、5 候选搜索、登录交接或重复提交功能，不访问猎聘、不要求真人收码。

历史证据仍有边界：PR #536 的失败只保留 `network_error`，城市目录响应头之后出现加载失败，未保存当时的浏览器具体错误；PR #537 的退出只保留 `RuntimeError` 类型，未保存异常来源。PR #538 一次正常关闭不能反推旧异常原因。本轮没有给这些旧记录补造根因。

代码检查找到并用本地真实 socket 复现一个确定缺口：`NativeTunnel` 直到 TCP 与代理握手完成后才登记上游 socket。HTTP CONNECT 等待响应、SOCKS 等待握手时停止，关闭只能碰到浏览器侧 socket，仍在等待的上游连接不在关闭清单中。两种首次负对照均在原来的 2 秒收尾期限后报 `native_tunnel_cleanup_incomplete`；这是一条已证实的 RuntimeError 路径，但不能断言历史那一次就是它。

修复让原生连接从创建起归当前隧道所有，并在连接前原子核对关闭状态。TCP 连接用有界非阻塞等待响应停止信号，仍使用已核验的数字 IP、已选择的代理和原超时预算；代理握手仍由现有 HTTP/SOCKS/Digest/NTLM 实现完成，通过可选 socket 工厂保留同一个受管连接。其他 HTTP 调用默认保持原实现。关闭可直接中断尚未完成的握手；等待代理认证锁的连接也及时响应取消，关闭后的新连接不能逃出关闭快照。没有增加连接重试、认证重放、直接连接回退、DNS 重新解析或 TLS 放宽。原 2 秒未完成检查继续保留，未完成的处理器仍必须如实报错。

同时修复错误归因：普通 `ERR_CONNECTION_RESET`、`ERR_FAILED` 等加载失败，原先会继承隧道上一次连接留下的代理/DNS 错误。现在仅明确的代理/CONNECT 错误可以采用该隧道原因，其他失败保留自身浏览器分类，未知仍未知。停止引起的预期 socket 异常也不再改写此前网络原因。旧网络记录仍不足以判定是连接重置、代理故障、CORS 或其他问题，不能用本次修复追溯认定。

已有脱敏诊断新增关闭阶段 `pacing` / `controller` / `tunnel`、固定异常类型、仍存处理器/socket 数和监听线程状态。已知 `native_tunnel_cleanup_incomplete` 单独标记，不保存异常正文、完整堆栈、地址、请求或凭据。第一处清理异常仍原样抛给调用方，其他独立资源仍继续释放，诊断器故障不改变行为。

## 修正的问题

上一轮的 `network_error` 没有保留失败请求的归属和浏览器原因；HTTP 200 又可能只是响应头，不能证明正文完成。本轮将已有开发检查的有限字段过滤提取到运行时共用函数，使正式采集路径也能在删除请求记录前，将首次停止绑定到该请求的主机、脱敏路径、方法、资源类型和已核对规则。

- 记录固定 CDP 网络错误、阻止原因、CORS 原因及布尔取消标记；未知值保持 `unknown`，缺失的可选结构保持空值。分类值参考[官方 CDP Network 协议](https://github.com/ChromeDevTools/devtools-protocol/blob/master/json/browser_protocol.json)，兼容已有旧版分类。
- 阶段只区分 `before_response`、`response_headers` 和 `body_complete`；后者仅表示收到 `Network.loadingFinished`，不等于正文已解析、岗位可读或账号认证成功。
- 不记录任意错误文本、请求头/正文、查询值或 CORS `failedParameter`。保持原诊断开关、环形缓冲、首次停止保存及观察器容错。
- 原公共错误码、拒绝/取消决定、请求频率、网络契约和浏览器行为不变；不增加浏览器命令、重试或自动切换。
