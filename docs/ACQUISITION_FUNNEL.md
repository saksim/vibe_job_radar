# 同批采集漏斗与原报告引用（#53）

浏览器批次现在分别显示：发现岗位、所选岗位、完整正文、符合目标的岗位、
有已接收正向 AI 要求的岗位，以及提取要求/已接收要求/待复核要求的条数。
岗位按本批来源实体计数；原报告 `target_jobs` / `ai_jobs` 继续表示去重分组，
不能将一条岗位的多项要求或合并后的一个报告分组当成多个来源岗位。

`guided_acquisition.json` 的每条结果关联原 `record_id`、平台实体、观察链接、
最终详情链接、采集时间、正文/原页面哈希、解析器与适配器版本。分析状态来自
原报告 `input_audit.csv`，要求 ID 来自原 `requirements.jsonl`，不运行第二套
分类器。相同正文被原报告合并时，要求仍指向其全部来源记录。

逐条结果区分：未尝试、未确认完整正文、访问未完成、等待、岗位下线、
完整但被筛除、完整但没有已接收的正向 AI 要求，以及完整且有相应要求。
被筛除的具体原因保留在 `analysis_status`，例如角色不匹配或记录过期。
没有任何成功正文时不生成空报告，任务仍保留全部所选条目的结果。

这些是可追溯的本批样本结论；不证明全市场没有岗位、不等于个人能力证据，
也不替代 #49/#50/#54 的真实完整 JD、正常登录和跨日期实站验收。
