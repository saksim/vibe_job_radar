# 高级采集使用工作区网络偏好（#64）

问题：网络检查、公开目录与浏览器使用已保存的 Fake-IP 修复偏好，
高级 `Collector` 却直接创建默认网络客户端，导致同一工作区行为不一致。

搜索 API、URL 正文和授权 feed 的每一个新步骤，现在先读取并校验工作区偏好，
再预留尝试次数并创建/绑定网络客户端。工作台与 `vibe-radar-collect` CLI
走同一条 `Collector.step` 路径，不依赖 HTTP 请求线程的隐式环境。
损坏设置在请求及预算预留之前失败；离线查看和报告生成保持可用。

设置改变时，下一步更新同一个客户端的策略与 resolver，保留请求时间、
主机拒绝状态和 robots 缓存。关闭加密解析不再继续沿用旧许可；进行中的
解析仍由已有许可回调控制。没有因改偏好重建客户端、退回另一出口或清空预算。
该行为不修改已有浏览器会话，也不自动重新执行此前失败的采集条目。

`test_collection_network_settings.py` 验证三条入口、缓存客户端变更/撤销、
工作区隔离、损坏偏好无请求/预算变化、离线报告以及独立 CLI。
外部响应使用受控数据，不代表 VPN、TUN、认证代理或 PAC 的现场兼容认证。
