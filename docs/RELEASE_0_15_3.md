# 0.15.3：个人报告与证据历史完整性

## 解决了什么

- #445：个人报告在暂存目录完成原分析、冻结要求语义核对、个人证据版本来源和最终文件摘要及临时输入清理后才一次公开。来源记录或最终清单写入失败，不再留下完成态报告；原来源报告不变。
- #446：个人证据库只有全新状态才初始化。既有零字节、缺表、未知版本或不兼容字段明确拒绝，保留原文件；运行中或重开既有无附件目录时缺失的库不会被隐式创建。完整旧无版本号数据库（含正常 ANALYZE 统计表）可直接使用，重开不改写其字节。

## 提高了什么

个人报告列表只呈现已经完成版本来源绑定的报告。损坏历史不再与新工作区的空记录混淆；明确错误便于保留原库并使用已有备份恢复。

原分析、要求复核、项目/责任/指标映射、附件与导出、撤回和历史版本保持。数据库格式不变，不重建损坏记录，不推测或补造用户经历。采集、完整 JD、网络、调度、团队服务、升级和备份功能保持。

## 验证结果

基于已正式发布的 0.15.2/main `9481bd1e237ac6d58875e6783b52e3b94f482e11`。开发前 dev/release 已 rebase main，无分叉。

7 项人工临时工作区负对照实际 5 失败/1 错误/1 旧库兼容通过，用时 1.792 秒。首次夹具有两个未关闭的 SQLite 连接，修正后另存负对照，首日志保留；该清理错误不归因于产品。修复后新用例及相关个人证据、报告、标注、导出、HTTP 与旧数据回归共 60 项通过，19.482 秒；本地未重复全套测试，未访问真实站点或修改用户工作台。

自动审查指出无附件历史库丢失后重启仍可能初始化；新增单项负对照复现（1失败，0.251秒），补齐目录既有状态判断后8项直接回归通过（1.993秒）。旧提交与首轮结果保留，新提交重新使用自身必要CI。

复审又确认正常 SQLite ANALYZE 统计表兼容与临时输入清理失败边界；两项负对照得到1失败/1错误（0.603秒）。排除SQLite内部表并在报告公开前完成输入清理后，28项个人证据与报告回归通过（8.548秒）。

本说明记录候选代码及本地验证。候选与准确 main 使用原必需 CI；按 dev→release→main 晋升后发布 Windows v0.15.3、Python python-v0.15.3、Linux/macOS desktop-v0.15.3。准确 main、公开资产与旧版升级兼容的实际结果由 [总控 #57](https://github.com/saksim/vibe_job_radar/issues/57) 最终交付记录补齐；计划不代表发行已完成。
