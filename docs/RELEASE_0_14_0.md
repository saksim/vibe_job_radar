# 0.14.0 发行说明

## 解决了什么

- #411：Windows构建、发布与升级硬编码“未签名”，未来签名版本无法被原升级器接受。
- 引入明确配置的签名步骤，位于最后摘要与实际程序验收之前；签名失败不自动退成未签名发行。
- 下载和自动启动前绑定实际文件、发行者证书与时间戳，界面和Release按实际证据显示状态。
- 修正Windows PowerShell子进程受父PowerShell模块路径影响的签名探针兼容问题。

## 提高了什么

- Azure Artifact Signing/OIDC和本机证书库签名均有明确入口，原未签名构建与旧元数据继续兼容。
- 保留Windows、Linux/macOS自动升级、Python分发，以及已有网络、团队、采集、完整JD和原报告。
- [24项逐项核查](OPEN_ISSUES_2026_10_18.md)列清工程现状与具体现场/材料条件，不把旧历史清单或未知事故当成已完成。

## 验证结果

定向测试覆盖错误身份、无时间戳、篡改、签名证明不一致、PR签名拒绝、旧版读取和自动交接。真实系统验证使用现有微软签名文件、篡改副本及实际未签名PE，未执行被检查文件、未修改证书。具体数量、准确提交与CI运行号以配对PR及正式Release说明为准；微软文件验证不代表本项目已获得签名。

## 剩余问题

目前没有发行者签名凭据，所以本次正式包仍标unsigned；工程接入不会生成可信证书。维护者按[签名说明](PUBLISHER_SIGNING.md)完成身份认证与配置后，才可发布真实签名版。Windows SmartScreen信誉和macOS公证有独立条件。0.13.0及更早先升级到此过渡版，或手动取得未来签名版。

真实站点/账号、人工JD标签、本人项目材料、净机/企业网络、生产主机和域名仍按原Issue条件开放。
