# HTTP与浏览器使用同一规则匹配

Refs #85 / #9 / #55 / #56。修复前，`SiteFetcher` 使用标准库解析器，浏览器用独立的通配规则解析器。人工复现同一 `Disallow: /*?*` 对 `/search?query=test`：旧HTTP发送robots和页面两次请求，浏览器拒绝。换采集入口不应改变同一有效规则的决定。

`robots_rules.py` 提取原浏览器已有的有界UTF-8规则解析与匹配。三条路线共同处理明确User-agent、通配和末尾锚定、最长匹配、Allow同长优先、编码路径以及多个同名组。HTML、空正文、异常编码、超限和不支持的模糊规则停止。延迟可保留小数，HTTP保留原先的更严格间隔，并取所有已声明Request-rate的最严格间隔；这不是新增跨设备窗口配额。

保持原路线边界：高级HTTP仍要求200的有效规则，404/410仍报不可用；浏览器只有通过既有操作契约才能采用原先的404/410处理。高级HTTP兼容旧的缺失Content-Type但有效UTF-8文本规则，显式HTML及HTML正文不能因此通过；浏览器原严格类型要求保持。共用匹配器没有扩大域名、方法、入口或来源权限。

每次重定向继续按目标来源规则检查，来源之间不共用许可；已有规则拒绝和不可用结果在当前客户端缓存，不能重复探测来制造成功。目标公网、原域名TLS、原任务预算、部分报告和旧数据不变。

## 验证与真实观察

10项新增测试包括决策矩阵、身份/组选择、拒绝缓存、无效HTML/编码/规则、缺文件边界、旧无类型文本、小数延迟、同源跳转、跨来源隔离和真实本机HTTP CONNECT/TLS。被拒路径在真实夹具仅产生一个robots请求，明确允许时才有后续页面。实际浏览器和完整CI结果按当前PR提交记录。
