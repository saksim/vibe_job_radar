# 显式宿主机代理入口

Refs #83 / #23 N7。此实现建立在 #82 的工作区代理设置之上。选择“宿主机 HTTP”或“宿主机 SOCKS5”，填写宿主机已经授权给该来宾的完整代理地址和端口，阅读说明并确认后保存。应用不会配置宿主机监听、防火墙或虚拟机网络；来宾的 `127.0.0.1` 不代表宿主机。

支持匿名 HTTP CONNECT 和 SOCKS5 数字目标 CONNECT，入口必须为 RFC1918 IPv4 字面地址（10/8、172.16/12、192.168/16）。没有默认宿主机地址，不猜网关、不扫描端口。主机名、IPv6、其他网段、PAC、socks5h、URL userinfo 和代理凭据不接受。本机和自动模式仍然只支持原有 loopback 范围；自动发现的私网地址不能静默启用宿主机模式。

只有代理入口可为私网。目标仍须是获准域名解析出的公网数字地址；HTTP/SOCKS 均不转交域名解析。原域名 TLS/SNI、robots、限频和失败停止保持。宿主机代理可观察目标 IP 与流量时间；本功能不向它发送代理密码，遇到应用专用代理或凭据环境配置冲突即停止。代理失败不会改用来宾本机端口或直连。

三个工作台、公开目录、高级采集、CLI 和新浏览器会话使用工作区同一策略。保存不连接网络；已有会话固定原快照，需要停止并重开。界面回显明确区分“已保存”和“已测试”。实际宿主机监听是否授权、具体 hypervisor/VPN/企业网络是否可达，仍须在相应环境中验证，代码或受控 CI 不作现场认证。

## 兼容与回退

沿用 v2 文件结构，增加严格枚举 `vm_http`/`vm_socks5` 和独立同意版本 `workspace-anonymous-vm-host-v1`。原本机许可不能代替宿主机许可；旧版严格枚举读取器拒绝未知模式，不能悄悄直连。DNS和代理共用修订，工作区隔离不变。

回退前停止服务并备份工作区。回退到 #82 时恢复此前已知有效的 v2 本机/自动代理备份；回退到 main@ec458799 时恢复此前已知有效的 v1 备份。不要手改版本号、删库、删除配额或复制其他工作区的 Cookie。没有兼容备份时保留配置并使用支持它的新版本处理，参见[原工作区回退](WORKSPACE_PROXY_SETTINGS.md)。

## 验证边界

- 离线测试拒绝未知地址、凭据、私网目标、自动发现扩权、混用许可和旧修订，并检查路由快照及环境冲突。可移植协议测试使用人工的“私网入口→本机夹具”映射，单独声明这一点。
- 实际 Edge 运行三个页面、保存/重载、明确许可、拒绝来宾loopback、工作区隔离及390px布局；不探测用户代理或网站。
- `run_vm_proxy_network.py` 仅能在临时 Linux GitHub Actions 中以 root 执行，创建独立的宿主端/来宾端 network namespace 与 veth；两端没有默认路由。真实 TCP 经私网端点，服务器核对来宾源地址；仅人工域名 DNS 和代理内部的公网符号目标映射是夹具。检查 SafeHTTP/浏览器请求桥的 TLS、发布方计数、拒绝、超时与不直连，finally 清理自己创建的 namespace。不安装 CA，不修改用户电脑。

上述 CI 网络验证执行状态与精确提交以 PR 为准；network namespace 不是完整虚拟机或真实招聘网站。Windows/macOS/具体虚拟化产品的实际宿主机路径、N8现场网络、PAC/代理DNS、#63页面清空和#54跨日期采集仍开放。
