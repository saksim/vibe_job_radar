然后运行 `python scripts/build_candidate.py`。没有通过且精确匹配当前源码的结果时拒绝构建，不能只用浏览器截图、旧日志或另一个分支的测试数字替代。ZIP 名包含实际 ZIP 内容摘要前缀；版本仍从 src/vibe_job_radar/_version.py 读取，当前不修改已合并版本。

这两个命令是维护者的验收工具，不是普通用户获取岗位的新增操作。原网页流程不变。CI 的浏览器验收后也自动执行同一个源码验证器再打包，不要求用户手动准备云服务。

## 拒绝条件和一致性

- 对 src/scripts/tests/docs/examples/demo_output/.github 及已列明根文件建立逐文件字节 SHA-256 清单；新增、删除或改动文档同样使旧证据失效。运行目录、根 .env、缓存字节码和日志不作为源码。
- 拒绝源码符号链接及源目录中的明显私密数据库、.env、密钥文件。仅既有两个明确 test-only PEM 夹具可入包；这不是通用秘密扫描器，维护者仍须审查源码。
- 解析所有 Python 源文件并检查单一版本源。版本不能含路径分隔符；不会通过字符串拼接把文件写出候选目录。
- 测试数必须为真正的正整数，失败/错误/跳过必须全部为整数零；布尔值不能冒充计数，顶层 success=true 不能盖过失败。四步顺序、退出码和源码不变条件同时验证。
- 每次验证使用独立临时单测结果路径，旧报告不能被误用；超时/失败覆盖本次结果为失败。生产者与打包器共用严格验证函数。
- 构建时再次逐文件验证，并在结束前核对完整清单，拒绝读取期间改动。独立临时文件、原子替换及按 ZIP 摘要命名避免混用半成品；失败不删除先前的有效候选。
- CANDIDATE.json 带源码清单及本地证据；manifest.json 带 ZIP 摘要。每个候选可追溯，但它不是签名证明，不能防止有权改源码/证据的攻击者伪造。
- 明确 browser_bundled=false、live_sites_certified=false、远端 CI 需另外验证。不是免安装包、正式 Release 或实际 VPN/三站认证。
