# 计划结果与后续手动查询

Refs #124 / #9 R3 / #87 / #115 / #30 H4。

原每日计划只读取当前公开任务。若计划任务已经生成报告，而用户在调度器下一次核对前开始另一查询，当前任务记录会改变，计划便保守暂停为“中断”；原报告仍在，但计划历史缺少链接。本分支让调度器依据原任务的完成回执确认结果，避免成功查询因正常操作被误判。

新查询替换当前终态任务前，在原任务所有权锁内将最小回执事务性写入`public_tasks/outcomes-v1.sqlite`，然后才覆盖当前任务记录、启动线程或联网。回执写入失败会拒绝新查询，原任务/报告/配额保持。崩溃若发生在回执成功而新任务尚未保存时，原状态与同一终态回执仍可核对，不能凭它新发请求。

回执只保留任务ID、尝试号、类型、来源契约摘要、完成/失败/取消状态、报告ID与过期标志。没有查询、地区、正文、URL、个人材料、登录态或路径。只保留最近64个终态尝试；原报告不因此删除。已有同身份/尝试回执不能被另一结果覆盖，损坏/未来版本/符号链接/异常大小会明确拒绝。

计划启动的是新任务的第1次尝试。后续手动查询使用新ID，人工续接则增加同ID的attempt；两者都不能替代原计划结果。计划核对原ID、首次尝试和来源摘要，找回原完成报告；停止旧计划不会取消正在人工续接的另一尝试。已过期、失败或取消的原结果仍暂停。真正中断、缺少回执、旧版未记录或超过64条保留范围仍保守暂停，不扫描报告目录猜成功，不自动重放。

同进程、另一工作台实例和重启都使用同一回执；状态读取不联网。原单个24小时计划格式、所有权、配额和公开任务格式保持，不是多任务队列。原旧版本不读取新增数据库；回退前仍须停止全部同工作区进程并备份，旧源码不得同时写任务。回退后发生记录替换时可能恢复原来的保守暂停，不能删除报告或配额来“修复”。

验证包括原代码确定性复现、原CSV字节保留、实际第二Python进程替换任务后重启恢复、同ID人工续接保护、写入失败先拒绝、缺失/损坏/尝试隔离/保留上限。真实浏览器验收先完成计划查询，再从页面发起手动查询，核对计划继续、历史打开正确原报告、手动报告保留、停用与390px布局。人工目录与受控时钟不代表真实24小时或三站现场认证；当前提交结果以Issue/PR为准。
