从零开始：先打开，再找岗位

本文描述当前待审候选的使用方式；已合并 main 与候选功能范围见交付清单。下载时选择要使用的完整分支/提交，同为0.2.0不代表能力相同。源码需要Python 3.10或更新版本；Windows便携候选有自己的提交与验收记录，仍不是正式发行。

1. 下载与启动

在GitHub仓库页选择本次版本的代码，点击Code → Download ZIP，将ZIP完整解压。不要只下载一个脚本，不要在压缩包里直接运行。解压后的目录应同时有scripts、src和start_windows.bat。

已安装Python的Windows用户可双击start_windows.bat；没有Python时，先从Python官方安装程序安装3.10或更新版本。Windows终端可执行 py -3 --version 核对。macOS/Linux可执行 python3 --version 核对。

你已用Anaconda启动成功时，完全不必重装。停止旧终端，再进入新源码目录，执行原来的命令：

/d/code_environment/anaconda_all_css/py312/python.exe scripts/start_workbench.py

其他Windows环境在源码目录运行 py -3 scripts/start_workbench.py；macOS/Linux运行 python3 scripts/start_workbench.py。Windows可在文件夹地址栏输入cmd并回车打开当前目录的终端。Git Bash用户右键空白处打开Git Bash后使用上面的Anaconda命令。

浏览器自动打开时保持终端不关闭。没有自动打开，则复制终端中完整的127.0.0.1地址，包含#token后的部分。端口每次可能变化，旧书签未必可用；地址不要发给别人。工作台页面与采集浏览器是两个不同窗口。

2. 最简单的第一份结果：无账号、无API

点击“运行合成演示”，它是程序合成的测试数据，不是真实招聘。看懂结果后，在基础页粘贴一份你有权处理的真实完整JD，填写实际标题、平台、来源与使用范围，点击“保存到真实数据库”，再选岗位并点击“分析真实数据并生成报告”。

下载requirements_zh.csv核对逐条原文；descriptions.md是模板，没有本人证据的数字应保持待填，不是程序已经证明你满足了岗位。演示库与真实库隔离。只拿到片段就标记摘要，不要为了有结果谎报为完整正文。

3. 不整理URL：先区分公开分类和浏览器搜索

想先取得实际正文，可在首页主动选择“进入猎聘架构师公开分类采集”或“进入猎聘算法工程师公开分类采集”。填写实际用途和访问依据，核对每批1～5项后确认。程序读取固定主列表、完整正文并生成本批报告；本批结束后可预览下一批或平台下一页，再分别确认。这条路径已有实站证据，不需要账号、浏览器组件或搜索Key，但不使用自定义关键词/地区。见公开分类操作。

需要验证关键词搜索或正常登录时使用下面的浏览器向导。猎聘关键词入口仍会转为空白，BOSS/51job也未完成浏览器闭环认证；不要把下面的按钮步骤当作三站均已验通。

在首页点击“新手推荐：选平台 → 找岗位 → 勾选采集”。这条入口进入/guided，不是旧的/advanced大表单。

第一次先点“检查浏览器（不采集）”，再按需点击“安装 / 修复采集浏览器”，确认后程序使用当前Python下载Playwright与Chromium。网络和安装状态都在页面显示。没有此依赖时基础页仍能分析粘贴文本。

按以下顺序操作，不需要自己准备一串职位链接：

顺序点击或填写应看到什么
1选择本次要验证的平台、实际关键词、1页/1个岗位使用范围和确认项，请按实际依据填写，不编造授权
2点击“打开搜索并读取岗位”弹出独立采集浏览器，或提示需要登录/处理页面
3需要登录时点“打开登录浏览器 / 人工接管”在采集浏览器完成正常登录/验证；猎聘另有本机明确授权的单次密码表单，实站尚未验通
4已打开网站列表时点“我已打开结果列表：读取当前列表”；只登录了则点“登录后重新搜索”工作台出现自动识别的岗位卡片及详情链接
5勾选岗位，再点“采集所选并生成报告”顺序采集并显示每条结果；可下载CSV、模板和收集到的URL

完整逐步说明见浏览器采集按钮指南。不能识别列表、robots拒绝、DNS非公网都不是靠增加预算解决。内置三站适配尚未实站认证，首次请从1页/1个岗位尝试。

4. 已有URL或搜索Key：旧入口仍然可用

高级工作台/advanced除公开分类外，保留URL、Search和JSON三条路线，字段按路线隐藏。已有真实详情链接，点“我有职位链接：套用 URL 入门参数”；希望用搜索引擎找链接，点“我想先搜索：套用搜索入门参数”，填自己的Brave Search API Key。搜索入门参数为1次搜索、1页、正文预算0，只拿标题/链接/摘要。没有数据供应方的JSON接口，就忽略数据源路线。

先点击“检查填写 / 预览计划（不采集）”核对缺项，再明确执行。预检不认证Key有效性，也不代表网站一定可取。旧URL方式不使用本次新浏览器会话。逐格案例见字段来源与案例。

5. 填本人证据，生成个人描述

在高级页选择已生成的真实报告，点击“加载原文要求”。在完整原文中复核条目，上传自己的证据附件，填写项目、负责范围、阶段、指标基线与当前值、样本量、观察窗口和口径。勾选实际支持的要求，再点击“保存个人证据”。最后点击“生成个人报告”并下载。

没证据时保存草稿；批准原文不等于自动满足岗位。离线测试不能冒充生产成绩，文件哈希只能证明字节一致。详细说明见采集与证据操作。

6. 等待、停止、更新和数据保留

/guided的新任务由后端线程执行，关闭工作台网页不会取消已经确认的批次；暂停或停止按钮会停止后续动作，关闭终端退出程序。默认不保存登录Cookie；第2步明确选择在本机保留后，下次任务可尝试恢复。停止浏览器不删除已保存快照；需用“清除此平台保存的会话并关闭采集浏览器”撤销。恢复不代表账号有效，密码不保存。

/advanced的公开分类当前小批也在后台执行，可关闭网页，退出应用后保留检查点并等待明确继续；其他高级HTTP路线仍由网页驱动。固定公开目录另有可选每24小时查询计划，Windows便携候选另有登录后启动。它们不自动登录三站、不安排分类定时采集，也不是无人登录全天服务。

默认目录在用户主目录下.vibe-job-radar，基础页显示完整路径。保持同一工作区，重启或升级可以继续读取原数据；不同目录相互隔离。先停止服务，再备份整个目录，包括数据库、reports、guided、imports及个人证据。升级代码不等于删除数据，别用“清空工作区”来更新程序。

0.2.0新增browser_fetch来源类型，旧版本不保证认识新记录；回退时恢复对应的完整备份。不要同时运行两份工作台操作同一任务。不要将本机端口开放公网。

7. 看错误，而不是反复点开始

现象下一步
找不到Python检查安装/版本；已经能打开页面的人不需要再安装Python
页面没有新手向导入口停止旧进程，确认完整新源码目录，重新启动，不是只刷新网页
缺令牌或403从本次终端的完整地址重新进入，不要把127.0.0.1改成别的主机名
non_public_address或198.18开头向导里点网络检查，核查代理Fake-IP/DNS。不是网站登录错误，不删除公网检查
0条卡片在采集浏览器手动打开正确列表再读取；仍为空可能是适配不兼容
native_page_cleared / 搜索页转空白保留失败原因并停止本次尝试；当前猎聘关键词入口尚未验通，不是零岗位或密码错误
robots拒绝或403/429停止并核对访问条件/冷却，不加预算、不换身份反复访问
安装失败核查下载网络、磁盘与Python权限；本地粘贴分析仍可用
报告为空看正文数、岗位匹配和条目失败原因；不代表市场没有需求

页面默认15秒导航间隔与共享配额，显示等候不是卡死。网络检查用于定位当前网络策略及失败阶段，不能修复全部环境问题；登录只处理身份，不会解决页面结构或访问规则。全部操作和剩余边界见浏览器采集按钮指南。

浏览器未就绪时不要继续改DNS

Playwright控制库与配套Chromium浏览器是两层安装。pip install Chromium不是安装浏览器；使用同一解释器的-m playwright install chromium。新版界面会检查真实可执行文件和空白页启动，显示分阶段原因与脱敏日志。完整命令和逐按钮排障见浏览器安装与启动修复。
